# 設計の確認事項と修正点を表示する

業務設計書の確認事項を関連するActivityやObjectに結び付けると、Viewerで図形の印と内容を確認できます。複数の項目に関わる指摘も一件として記録できます。

- **困りごと**：Activityに記載した既存のProblemとPain level。実業務で確認した負担を表します。
- **要確認**：原資料にない事実や、人が決める必要がある業務上の問い。
- **要修正**：原資料や規約に照らした矛盾・記述不備。指摘があることだけで、修正案への合意を意味しません。

AIの疑問から実業務のProblemやPainを作りません。種類は深刻さではなく、必要な対応の違いです。

## サンプルを開く

[架空の図書貸出のMarkdown](https://github.com/mk3008/alder/blob/1d629a9a5df26149e518473d05045e6a733235fb/examples/design-findings/library-lending.md)をViewerで開くと、図形の印と指摘一覧を試せます。返却期限の記述を意図的に異ならせた例です。複数対象の指摘、文書全体、関連先未設定、解消済みの表示も確認できます。実際の運用規則には使わないでください。

## Markdownに指摘を記載する

文書内に一つの`# Findings`を置き、その下に指摘を並べます。`Targets`は宣言済みActivity/Objectの名前と正確に一致させます。改名後は参照先も更新してください。

```markdown
# Findings

## Finding F01

### Kind
question

### Status
open

### Scope
items

### Targets
- 受付情報
- 依頼を受け付ける

### Summary
確認できる情報の範囲

### Content
担当者が確認する情報の範囲は、どこで定義されていますか。
```

項目は上の順序で記載します。

| 欄 | 値 |
| --- | --- |
| FindingのID | 英字で始まる1〜64文字の英数字・`_`・`-`。文書内で一意 |
| Kind | `question`（要確認）または`correction`（要修正） |
| Status | `open`（未解決）または`resolved`（解消済み） |
| Scope | `items`（項目）、`document`（文書全体）、`unassigned`（関連先未設定） |
| Targets | `items`なら一件以上の`- 名前`。その他は`(none)` |
| Summary | 空でない短い要点 |
| Content | 空でない根拠と質問、または修正内容。追加見出しは使わない |

Contentには通常の文章・箇条書き・コードフェンスを使えます。HTML、リンク、画像はViewerでは操作を実行しない文字として表示されます。コードフェンス外の見出しは指摘の構造として検査されるため、本文の小見出しには使いません。

同じ指摘を複数の対象へ付けるときは、Targetsに名前を追加します。本文を複製する必要はありません。関連先が分からなければ`unassigned`と`(none)`にし、推測で項目へ結び付けません。

## Viewerで確認する

未解決の要確認・要修正と困りごとは図形の印に表示されます。項目一覧から対象を選択すると、詳細で内容を読めます。左ドロワーの「指摘」で全件を確認できます。指摘を選ぶと左ドロワー内に詳細が開き、明示された関連項目への移動ボタンを使えます。

文書全体、関連先未設定、見つからない参照先は一覧で分けて表示します。対象名が間違っていても指摘を捨てず、参照先不一致として残します。共有指摘は一覧では一件、各図形ではその項目に関係する一件として数えます。

解消済みは既定の印と一覧から外れます。「解消済みも表示」で再確認できます。Markdownからは削除しません。解決した業務判断は正本の業務記述にも反映し、AIの指摘だけで解決済みにしません。

## Graph JSONへの出力

FindingsはMarkdownの付加情報であり、Graph v1のキーは変わりません。Pythonの`parse_document`は`graph`と`findings`を返します。従来の`parse_design`はGraphだけを返します。CLIは指摘がある文書をGraphへ出力すると、除外される件数を標準エラーへ警告し、標準出力には従来のJSONだけを書きます。

指摘を引き継ぐ場合は元のMarkdownを保持してください。Graph JSONだけから指摘を復元できません。Findingsがあっても、Input/Outputなど本文の構文検査は省略しません。未確認の授受を`(none)`へ書き換えて表示を通すものではありません。
