# 業務設計書の相関チェック

[文書構造へ戻る](business-design-structure.ja.md) · [品質チェック](business-design-quality-check.ja.md)

複数のActivityについて、前の仕事の結果が次の仕事の入力・開始条件につながり、業務を継続・終了できるかを確かめます。このページは実装前の業務設計書を対象にします。

## 用意するもの

関連するActivity・Objectを含む業務設計書の全文と版、適用範囲、合意済み判断、外部運用や共通ルールを渡します。文書上の並び順を、実行順序とみなしてはいけません。

## 確認する観点

| 観点 | 確かめること |
| --- | --- |
| 情報の受け渡し | 前段のOutputが共有Objectを通じて後段のInputに渡るか。対象・情報の意味が一致するか |
| 状態と開始条件 | 前段のResultで、後段のWhenや実行条件が成立するか。後段の追加判断が必要なら、それが分かるか |
| 処理単位と権限 | 何を一件として承認・完了するか、誰の判断をどの範囲で信頼するかがつながるか |
| 制約の原因と効力 | 制約が何によって生まれ、拒否や取消の後に何が残るか説明できるか |
| 例外と再開 | 発生側のExceptionと受け側のException Whenが対応し、必要な回復や合意を経て再開するか |
| 継続と終了 | 中断や判断変更があっても、事実を偽らず続行または終了できるか |

たとえば、会議室が空いているという検索結果と、予約の成立は同じ状態ではありません。空き確認から予約までの間に別の予約が入るなら、予約時点の再確認が必要になる場合があります。再確認があるだけで不具合とせず、前段が何を保証し、後段で何を確定するかを読みます。

## AIへ依頼するプロンプト

プロダクトのルートから使う例です。山括弧の箇所を置き換えてください。

```text
../alder/docs/business-design-correlation-check.ja.md と
../alder/docs/adoption.md の業務相関の記述・確認指針を使い、
業務設計書の相関を確認してください。
../alder/docs/phase2/review-knowledge-v0.3.md のQ1〜Q3・P1・Sも参照してください。

業務設計書: <対象パスと版>
合意済み判断・外部運用・共通ルール: <参照先、なければなし>
対象範囲: <対象業務と責任範囲>

最初に全文からActivity・Objectと実際の接続を把握してください。
各担当者として代表的な一件を入口から引継ぎまでたどり、
Output → Object → Input、ResultとWhen、例外と再開条件、
処理単位・権限・保証・残る制約を確認してください。
業務に自然な中断や判断変更の場面だけを追加してください。

各指摘に、関係する業務と文書箇所、具体的な場面、
どの受け渡しや判断が成立しないか、その根拠、最小限の確認事項を示してください。
明示された外部運用や再確認でつながる場合は、その根拠で閉じてください。
全Activityの全組合せや、無関係な例外の網羅は要求しません。
確認した接続と残る不確実性を報告し、根拠が十分なら指摘不要としてください。
実装は今回の対象外なので、実装を使うP2は適用しません。
読み取り専用とし、未決の業務ルールを代わりに決めないでください。
```

## 結果の扱い

説明上の不整合と、人間の業務判断が必要な問いを区別します。業務上の意味を変更する場合は、人間の判断を業務設計書へ反映して再合意します。追加機能を作らなくても、既存の外部運用や責任範囲で意味がつながることがあります。

JSONの参照が解決できることは、業務上の相関の正しさを意味しません。JSON化の形式は[Business Graph export](business-graph.md)、実装後の照合を含む手順は[導入ガイド](adoption.md)を参照してください。
