# 備品購入モデルの再レビュー（2026-10-20）

対象：[論理モデル案](logical-model-review.ja.md)、同じ改稿の[BD](README.md)と[操作ラフ](../../work/logical-model/issue-133/index.html)。根拠は[17:44中締め](https://github.com/mk3008/alder/pull/254#issuecomment-6287161069)。同一Agentが改稿後に別工程でレビューした記録。独立Freshレビュー、人間の業務合意、実DB・実機能の検証ではない。

## 結論

見積必須の提出、複数品目、差戻し・再申請、準備確定と再出力、分割入庫、一部購入・購入なしでの終結を表現できる候補になった。旧案の代替品許可・入庫を1回に制限する構造・承認記録単位の結果上限を改めた。

PK/FKだけで完成するモデルではない。以下の処理条件を含めて初めて合意した業務を守れる。財務・日付・合意証拠等の未決があるため、実装仕様の確定とは判定しない。GUI方向の人間レビューに返せる段階。

## 正当例・反例を使ったレビュー

| ケース | 改稿モデルでの扱い | 判定・保証の置き場 |
| --- | --- | --- |
| 品目・見積が未入力の下書き | 申請と下書きを保存、提出版なし | 表現可能。提出版のNOT NULLを下書きへ流用しない |
| 見積なしで提出 | 提出版を成立させない | 必須参照と提出処理。下書き保存は拒まない |
| 同じ見積で別の人が申請 | 見積IDの申請間UNIQUEを設けない | 正当な経路を誤って禁止しない。代理操作とは別 |
| 2品目、税抜単価100×3と200×2 | 判定額700、品目数2 | 品目1..Nと全小計の集計。上限判定・精度は更新処理で確認 |
| 見積文書が後日差し替わる | 提出版は不変な文書版を参照 | 可変なURL参照だけでは不十分。保存・版参照方式は設計で具体化 |
| v1承認→差戻し→v2再申請 | v1は不変、現在版v2、旧判断無効 | 表現可能。旧判断の削除/無効化と版切替を原子的に実施。FKの自動カスケードで旧判断をv2へ移さない |
| 承認と差戻しを同時に有効化 | 現在判断が申請PKで0..1件 | 構造で排他。状態と判断の一致は処理で維持 |
| 古い承認から新しい版を準備 | 拒否する設計 | FKだけでは不足。現在版・判断・準備未確定を排他下で再確認 |
| 差戻しと準備確定の競合 | 両方の成功を許さない | 共通の申請排他とトランザクション。競合DBテストは未実施 |
| 一申請を2つの準備へ所属 | 準備対象の申請PKで禁止 | 表現上の一意性。準備対象は確定版と対応 |
| 準備後CSV生成失敗・紛失 | 準備を保持、同内容で再出力 | 出力試行を分離。不変スナップショットが必要。二重発注まで保証しない |
| 10依頼→5入庫→残り5入庫 | 待ち5→待ち0、2回目も登録可能 | 合法な分割納品を拒まない。最終終結だけ最大1件 |
| 10依頼→8入庫＋2待ち | 作業中 | W=2。終結を拒否する集約・状態制御 |
| 10依頼→5入庫＋5購入なし | 一部入庫として終結 | R=5,C=5,W=0 |
| 10依頼→全数購入なし | 入庫0件で終結 | R=0,C=10,W=0。架空の購入日時・実購入額を要求しない |
| 10依頼→8入庫＋3購入なし | 不成立 | W=-1。行CHECKだけでなく集約を排他下で検証 |
| A10依頼→12入庫、B10依頼→8入庫 | 不成立・作業中 | 合計20を根拠に終結しない。品目ごとのW=-2,+2を検証 |
| 他申請・他版の品目を入庫実績へ混入 | 拒否する構造 | 実績ヘッダーと品目への複合FKで申請・版を一致させる |
| 代替品を元の品目の実績として入力 | 業務上禁止 | FKは参照先の整合のみ。現物一致は外部証憑・入力確認が必要 |
| 同一操作の再送と、同じ納品の別操作での二重入力 | 前者は再送識別で重複防止、後者は別問題 | 技術キーだけで実納品の同一性を自動保証しない |
| 終結後に入庫・購入しない数量を変更 | 今回は拒否する案 | 最終結果訂正なしに対応。PKだけでは防げず更新処理で凍結 |

数量6例と品目間相殺反例は計算で確認した。その他はキー・制約と更新手順の机上レビュー。実DBで拒否が強制されることを実証した結果ではない。

## 残る指摘・限界

1. **財務・日付の意味は未確定**：全数の見積額と各回入庫の実績額を混同しない。実購入金額の税区分・配賦、入庫日・購入日との対応は正式実装前に具体化が必要。今回の数量モデルから自動補完しない。
2. **合意の証拠範囲は未確定**：購入しない数量を持つだけで、申請者との合意が証明されるわけではない。理由・合意者等をどこまで保存するかは未決。
3. **現物の同一性と外部への二重配布**：再送識別子は同一操作の再試行用。同じ納品を異なる識別子で登録した場合や、再出力CSVの二重発注は内部キーだけで解決できない。入力確認・外部SR/運用契約の課題とする。発注日の受信機能は追加しない。
4. **実装での制約強制は未実施**：同時更新、集約上限、状態と判断の整合、確定版の不変性は、処理・トランザクション設計と関連テストが必要。今回のラフの数値計算を実装テストの代わりにしない。

これらは既知の未決・具体化課題であり、今回追加質問の回答待ちには戻さない。モデルの配置と業務上の効果をラフで確認した後、結果が変わる論点から扱う。
