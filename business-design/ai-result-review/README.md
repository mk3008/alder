# AI作業結果の返却と確認 — Business Design

AIが作業結果を返し、依頼者が目的との一致を確認して、必要な訂正や判断を伝える交換を記述する。結果レビューでは、何が変わり、何が残り、何を判断するかを把握できるようにする。結果の整理はAIが行い、目的・業務上の意味・採否の判断は依頼者に残す。

# Scope

Alder自身の作業における、AIの結果返却と依頼者の確認・訂正までを対象とする。上流の作業実行と訂正後の修正実行は隣接する仕事で、内部工程はここでは定義しない。既存のAlder利用業務のBusiness Designの範囲は変更しない。結果説明はChatやIssue / PRの既存の応答に含め、新しい中間成果物や承認工程を必須にしない。人間の確認を省略したり、AIの自己検査で業務判断を承認したりしない。

# Activity AI作業結果を返す

## Scope

true

## Why

依頼者が結果と目的の対応、残る仕事、必要な判断を把握できるようにする。

## When

依頼されたAI作業の結果を返すとき。

## Who

作業担当者

## Where

Chatと関連するIssue / PR。

## How

### Input

- 依頼内容 — 目的 / 確認条件
- 作業成果 — 作業結果 / 成果の参照先 / 検証結果と限界

### Procedure

1. AIは依頼内容と作業成果を照合し、結論と何を改善・変更したかを先に示す。
2. AIは目的・確認条件への対応、根拠の参照、残る未完了事項、依頼者の判断が必要な点を結果説明に含める。項目のない欄を埋めたり、詳細をすべて本文へ転載したりせず、依頼者の確認に必要な内容だけを短く示す。
3. 改善提案が含まれる場合、AIはカテゴリまたは改善効果の分かるタイトルを付け、どの場面のどの仕事を減らすか、人間に何を残すかを示す。候補・採用済み・未実施を区別する。
4. AIは結果説明を既存の応答へ含めて返す。要約は原典を置き換えない。検証成功、候補採用、実運用への反映、実効果の確認を区別し、必要な採否・判断だけを依頼者へ求める。

### Output

- 結果説明 — 目的との対応 / 根拠 / 未完了 / 必要な判断

## Result

依頼者が確認対象と残る仕事を把握し、結果の確認または必要な業務判断へ進める。

# Activity AI作業結果を確認し訂正を伝える

## Scope

true

## Why

依頼目的に沿った結果を得る。

## When

AIの作業結果と結果説明を受け取ったとき。

## Who

依頼者

## Where

Chatと関連するIssue / PR。

## How

### Input

- 依頼内容 — 目的 / 確認条件
- 作業成果 — 作業結果 / 成果の参照先 / 検証結果と限界
- 結果説明 — 目的との対応 / 根拠 / 未完了 / 必要な判断

### Procedure

1. 依頼者は結果説明を入口に、作業成果が依頼内容に沿うか確認する。必要な原典の確認範囲をAIの自己検査で代替しない。
2. 意図の逸れや不足がある場合、依頼者は訂正を伝える。業務上の意味や候補の採否に判断が必要な場合は、その判断を伝える。
3. 確認や訂正を確認結果としてAIへ返す。回答のない採否は未決のままとし、了承と扱わない。訂正後の修正手順や恒久的な引継ぎ方法はこの変更では追加しない。

### Output

- 確認結果 — 確認 / 訂正 / 業務判断・採否

## Result

依頼者の確認・訂正・必要な判断がAIへ伝わり、後続の作業へ進める。新しい業務上の意味や候補が自動承認された状態ではない。

## Problem

AI結果と目的の対応や不足を読み取ること、逸れた意図を説明し直すことに認知負荷がある。結果の整理を変えても負荷低減が確認されたわけではない。説明の誤りや冗長化が負荷を増やす可能性がある。

## Pain level

High
