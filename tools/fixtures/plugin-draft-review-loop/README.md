# 草案レビュー・再改稿の静的契約例

合成した受付業務を使い、指示が保持すべき六つの分岐を示す。scenarios.jsonはテスト専用の入力・期待例であり、製品の新しい出力形式、実行エンジン、保存契約ではない。

テストは、実レビューへの経路、参照先、根拠による修正・質問の区別、再レビュー・停止・未確認の報告に必要な指示が配布されることと、例の内部整合を確認する。実際にエージェントを起動してこの分岐を選ばせてはいない。レビュー結果は合成入力であり、モデルの検出率、実クライアントでの反復成功、工数改善の実測には使えない。

同一指摘は文字列一致に限らない。no_progressでは表現を変えた同じ意味の指摘を置き、指示上の停止対象を示している。rereview_failureは完了したreviewの空のfindingsと、未完了で結果がない状態を区別する。実行不能・コンテキスト上限も同じ未完了の境界で扱う。
