# 人間が示す探索次元の受け取りを確認した

## 結論

現行Alder Plugin 0.4.3は、自然言語で追加された探索次元を受け取り、既存業務の外側へ検討を広げられた。今回の2例では、どちらも追加された軸を明示し、Problemを減らす経路と、現行の業務意味を変える点を説明した。既存仕様・Skillの不足は確認されなかったため、変更しない。

ただし、確認できたのは**人間が示す軸を探索へ取り込む挙動**である。**実行可能で大きな効果を持つ改善案を得たこと**は確認していない。追加の軸に沿う視点は、どちらも事実や合意が足りず、実行可能な候補と分けたExtreme perspectiveとして返った。

## 比較したもの

[事前登録](protocol.md)と[入力manifest](inputs-manifest.json)を、出力前に公開commit `7eb9d311d3d08f6dd79ed28d2f8181680f48a477`で固定し、GitHubから取得できることを確認した。対象はmain `a58c970f3a78ac9a0ba91be3c6bfb05e4e2b1168`のPlugin 0.4.3。bundled authority原典revisionは`9d67d886de8317ad4d884ba8e06c356b44370c9a`、SHA-256は`76f9dd4fd58629e689fadc8edbbdbeda5b975197758b410c44e953795b0c657f`。

既存の公開BD「購入申請」「会議室予約」を改変せず再利用した。Problem/Painも#81/#85の既存比較用入力を再利用し、現行業務の実測事実とは扱わない。各例につきControlとTreatmentを1回ずつ、計4回の独立Freshレビューを行った。要求設定は現行AGENTSに従い`gpt-6-sol / medium / fork none`。有効runtimeの独立証明はできない。

Treatmentだけに次の一文を加えた。具体的な値、解決案、効果、外部サービスの存在、採用承認は与えていない。

- 購入：「必要備品を利用可能にする際の保有関係」を、変えてよいか検討する変数として探索に含めて構いません。
- 会議室：「会議開催場所の選択範囲」を、変えてよいか検討する変数として探索に含めて構いません。

両方に「値や採用案は未指定」「実行可能性の事実や変更の採用承認ではない」と続けた。ほかの入力は同一。これは事実の追加ではなく、検討してよい変数の追加である。Controlには探索を狭める指示を加えていない。

### 軸と値、採用の区別

保有関係は「誰が何を保有し、誰が使えるようにするか」を変え得る変数であり、共有保有物からの割当てはその値の一例である。開催場所の範囲は「何を開催場所の選択肢に含めるか」という変数であり、共有会議室以外の利用はその値の方向である。Treatmentは入力語を繰り返すだけでなく、それぞれの変更がProblemへどう作用するかと、現行BDとの境界を説明した。

会議室Treatmentの「許容範囲内の室選択委任」は、現行の室選択責任に根拠を持つ別の軸である。人間が追加した開催場所の範囲そのものではなく、候補数の増加を追加軸の効果とは数えない。候補の件数・Scopeのラベル差・文章量も品質向上の根拠にしない。

4出力とも候補を未承認とし、人間へ採用・修正・保留・却下の判断を返した。購入の承認・実購入後の記録、会議室の重複防止・利用可否・変更不成立時の元予約維持を黙って削除していない。追加軸が保証を変える場合は、その変更を候補の実施として扱わず、別枠で必要な人間判断を示した。

## 判定と扱い

- 自然言語contextで人間が指定した新しい探索軸を受け取る：今回の2例で確認。
- 追加contextを事実・実行可能性・採用承認へ置き換えない：今回の2例で確認。
- 現実的で大きな改善を得る：未確認。探索視点を候補へ進めるには、対象業務の事実と許容条件が必要。
- 専用パラメータがないため非対応：今回の仕様・挙動からは支持されない。
- Skill、guidance、bundle、BD、コードの変更：なし。新機能やreleaseを作らない。

利用者は、現行の依頼文に「どの変数を検討してよいか」を自然言語で加えられる。探索を許すことと、値を決めること、実行可能性を確かめること、変更を採用することは別である。今回の例を実業務へ採用する提案や、その採否を求めるものではない。

## 検証と限界

[verification.json](verification.json)で入力のdigest、既存BDとの一致、対照間の一段落だけの差、読取ログと禁止入力の分離を確認した。既存package関連チェックは25テスト成功。これは既存packageの整合確認であり、業務改善の効果を証明しない。入力・rawの公開前確認では、公開fixtureと比較用入力以外の個人情報、顧客情報、認証情報、privateな管理先へのリンクがないことを確認した。rawは生成後に改稿していない。

各条件1回の定性的な確認であり、生成の揺らぎと入力の因果効果を統計的に分離していない。人間の軸指定による一般的な発見率、提案の優越性、網羅性、現場での有効性は主張しない。実行中のPluginホストroutingやUIも試験していない。Skillとbundled authorityを直接読むFreshレビューである。

入力の追加軸は現行BDの外側にも及ぶ。そのため、この比較は「指定した軸を受け取れるか」を確認するが、「現行意味を保ったまま新軸から実行可能な候補を作る能力」全体を網羅しない。Controlが別の探索視点を自発生成した事実もあり、人間の指定がなければ新軸を一切見つけられないとは言えない。

先行#151/#153の複数条件を変えたprobeとは別研究であり、先行raw・解釈を上書きしていない。今回の観察から変更の必要性は確認できず、追加実験は行わない。
