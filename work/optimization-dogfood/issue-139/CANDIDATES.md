# 確認済み業務への未採用候補

2026-10-03。依頼者が確認した現状は[入力](inputs/result-review-current.ja.md)。以下は固定0.3.1 sourceに対するFresh出力の提案本文を転載したもの。候補1・2は未採用。責務差分と11項目を含み、効果は仮説。採否は依頼者へ届け、返答までBusiness Designや運用を変更しない。完全prompt・実行記録は[raw](runs/target-gate-known.raw.md)。

対象は、依頼者がAIの作業結果を受け取り、元の目的との一致を読み、訂正をAIへ返す仕事です。依頼者のHighの認知負荷と具体例は確認済みとして扱い、未採用の改善候補を2件返します。この現状記述は限定的なPoC入力であり、合意済みの恒久Business Designではありません。

現状では、依頼者が結果の読解に加え、逸れや不足を見つけ、必要な対応を文章化しています。供給された例では、対象業務の特定から人間の採否・再合意までの責務順序を説明し直しました。頻度や時間、効果量は未測定です。

## 候補1：AIが目的との対応と未完了事項を示して結果を返す

| 項目 | 内容 |
| --- | --- |
| Candidate | AIの結果返却時に、依頼目的・確認条件ごとの対応箇所、根拠への参照、未完了事項、依頼者の判断が必要な点を短く示す。 |
| Relation to the Problem | 依頼者が長い結果から目的との対応や不足を再構成する負荷を減らす。今回の例なら、対象業務を特定できたか、候補を人間の採否へ提示したか、次に残る対応を示す。 |
| Approach | Simplify / Delegate / Preserve。対応情報をまとめる仕事をAIに移し、目的との一致と業務上の意味の判断を依頼者に残す。 |
| Scope | Keep。既存の「結果を受け取り確認する」交換の見せ方を変える。新しい保管業務や承認工程は設けない。 |
| Expected benefit | 読む入口と不足の所在が明確になり、確認のための探索が減る可能性がある。短い要約だけで十分になるとは未確認。 |
| Difficulty | Low想定。依頼者とAIの返却内容を調整する。承認権限や他組織との責務は変えない。 |
| Affected parties / affected business | 依頼者、結果を返すAI、次の訂正作業。 |
| Existing Business meaning and constraints to preserve | 依頼者が目的・意味・採否を決める。AIの対応表や自己検査は判断の材料であり、自動承認ではない。原典への参照を残す。 |
| Assumptions / Unknowns | AIが対応箇所を正確に示せるか、表示が追加負荷にならないか、依頼者が原典をどこまで読む必要があるかは未確認。 |
| Questions people must decide or verify | この返却形式を使う場合、依頼者が必ず原典で確認する点は何か。実際の結果で、対応情報の誤りや省略が判断を妨げないか確認できるか。 |
| Confidence | 負荷との因果関係は中程度。実際の負荷低減と安全な読解範囲への確信は低い。 |

現在の入力には、AIがこの対応情報を日常的に作る手順は記載されていません。そのため、新たにAIへ移す仕事として提案しています。単なる現在業務の言い換えではありません。

## 候補2：依頼者の訂正から、AIが具体的な修正手順と引継ぎを組み立てる

| 項目 | 内容 |
| --- | --- |
| Candidate | 依頼者は逸れた意図・不足・守る条件を伝え、AIがそれを具体的な修正箇所、対応順序、次の作業で維持する指示へ展開する。 |
| Relation to the Problem | 依頼者が同じ指摘を説明し直し、詳細な対応手順まで書く負荷を減らす。今回の例なら「対象の特定が先」「運用改善案の採否は人間へ届ける」という訂正を、AIが必要な対応へ具体化する。 |
| Approach | Delegate / Simplify / Preserve。訂正の意味を作業手順へ翻訳し、次のAI作業へ引き継ぐ仕事をAIへ移す。 |
| Scope | Keep。訂正を受けた下流のAI作業までの既存の交換を変える。全開発工程や恒久的な記録管理を追加しない。 |
| Expected benefit | 依頼者による手順の再説明と同じ訂正の反復が減る可能性がある。AIが誤った解釈を引き継ぐなら負荷は増える。 |
| Difficulty | Medium想定。依頼者とAIの説明責任の分担、訂正が次の作業に届く方法を調整する必要がある。外部サービスや別担当者は仮定しない。 |
| Affected parties / affected business | 訂正する依頼者、訂正を受けるAI、次のAI作業。 |
| Existing Business meaning and constraints to preserve | 訂正の目的と業務上の意味は依頼者が決める。AIは新しい意味を補わない。合意済みの意味から一意に定まる修正には追加の業務承認を求めず、未決の意味が修正を左右する場合だけその決定を依頼者に返す。改善案の採否と採用後の再合意は維持する。 |
| Assumptions / Unknowns | 依頼者が詳細指示のどこまでをAIへ移せるか、訂正が次の作業で利用可能か、再解釈の誤りをどの程度許容できるかは未確認。 |
| Questions people must decide or verify | 訂正の具体化をAIへ移してよい範囲はどこか。供給された例で、依頼者の訂正から必要な対応順序をAIが正しく導けるか、次の結果で同じ逸れが再発しないか確認できるか。 |
| Confidence | 再説明負荷への関係は中程度。具体化の正確さと反復低減への確信は低い。 |

候補1は結果を読むときの情報探索を変え、候補2は訂正を具体的な作業へ展開する責務を変えます。それぞれ独立に採否を決められます。AIの作業実行は既に上流・下流にあるため、実行そのものを新しい委譲とは数えません。

「人間の結果確認をなくす」境界も検討しましたが、目的・業務上の意味・採否を依頼者が決めるという維持条件に抵触します。現時点で有用な別の業務モデルを示す根拠がなく、Extreme perspectivesは返しません。新しいサービス、頻度、全Taskへの広がりを仮定しないところで探索を止めました。網羅性や最適性は主張しません。

**依頼者として、候補1・2それぞれを「採用・修正・保留・却下」のどれにしますか。** 修正する場合は、移してよい仕事と、人間に残す確認範囲を示してください。両候補は未承認で、人間の採否待ちです。採用された場合も、変更する責務と意味を確認し、Business Designを更新・再合意してから下流の更新へ進みます。
