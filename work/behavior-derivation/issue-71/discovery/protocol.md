# コメント対応の探索的試行 — 出力前の固定条件

根拠: PR #72 comment 5746307498（2026-09-20更新）。前回の「現行形式で表現できる」は中心能力の検証になっていない。PoCの成立性確認と、品質化で未記載の条件を見つける作業を区別する。

## 入力・既知情報

- 基準はPR head `e84ea9b12da22368adf9da0dc49fc10e39b7701a`。会議室入力は既存の389行をそのまま使う。
- 実施者 `/root`。追加Agentなし。モデル/effortは継承、独立証明なし。
- 実施者はコメント、前回出力、過去評価、外部一次資料を既に読んだ。入力隔離・盲検・source選択の事前登録ではない。
- コメントで例示された同時更新・古い状態の操作、前回D05/Q01、M1/M2は既知。これらだけを再掲して新規発見の成功とはしない。
- すでに閲覧した資料はRFC 3339、PostgreSQL date/time、RFC 9110、AWSのidempotent API解説。検索結果に無関係なページが返ったため、それらを採用せず各公式URLを直接参照した。資料本文の再配布はせず、使用箇所と短い要約をsources.mdへ記録する。

## 今回の実行

`docs/behavior-derivation/functional-considerations.md` の手順候補を1回適用する。全文入力から機能の性質を捉え、一般知識との比較・具体場面・既決事項との反証照合を行う。出力はoutput.md、評価はassessment.mdへ分離し、生成後の原本を修正しない。

文書だけで結果を決められる項目と、外部知識を発見契機とする未記載論点を分ける。各論点の出自を「コメント/既知例」「今回の資料照合で具体化」「入力内の導出」で記録する。今回は後二者を混同しないこと、特にコメントの例以外に問いを具体化できることを確認する。

## 出力を見る前の評価基準

候補ごとに、(a)対象機能への関連性、(b)どこまで既決か、(c)既存保証を守る複数案の結果差、(d)未承認状態とSSOT、(e)新たな仮定・スコープ拡大、を個別評価する。単なる資料内容の言い換えは有用な候補としない。

同時予約の重複禁止、M1/M2、通知/代理/監査の対象外を蒸し返した場合は明示的に問題とする。タイムアウト等を全機能へ一律要求することも失敗扱い。既知例以外の候補がなければ、そのまま不十分と記録する。件数・hash検証・形式遵守だけで発見成功としない。

## 反証用の再照合

初回の候補から、答えを明示した架空の共通契約を別ファイルcontrol-assumptions.mdに置く。これは本当の人間承認やBusiness Design変更ではない。候補がその契約で閉じるか、契約が与えない保証まで増やさないかを、別のcontrol-output.mdで確認する。初回候補に適合させた同一評価者の反証例であり、未知入力での独立回帰・発見率検証ではない。

## 停止と判定

1回の探索と反証照合で停止し、課題固有の手順候補と結果をPRへ反映する。c3全文や業務設計は改変しない。前回原本・検証は保存する。良い例だけを残して評価しない。

採否は、試行候補として残す / 修正が必要 / 見送るのいずれか。入力内導出と外部知識による問いの違いを実例で示せても、独立試行の改善率や人間の価値評価を主張しない。必須工程・全製品への常設ルール化はしない。
