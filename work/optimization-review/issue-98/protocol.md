# Issue #98 Discovery — 生成前の条件・停止基準

- 対象: まず設備保全（5業務・設備状態と保守依頼状態の相関）。具体的で非自明な観測と確認可能な問いが少なくとも1件あれば、別領域の備品購入申請を1回だけ実行し一般化の限界を見る。なければそのまま停止。最大2対象、各1 Fresh Run。好ましい候補を得るための再実行はしない。
- 入力: 対象Business Designの原文と共通の探索指示のみ。Problem、Pain、改善テーマ、過去の研究結果や評価は生成者に与えない。生成者への閲覧許可は当該runディレクトリ内の `business-design.md` と `launch.md` のみ。実際のアクセス制御はなく、指示に基づく隔離。
- Fresh Agent要求: `gpt-6-sol` / `medium` / `fork_turns: none`。実効モデル・effortの独立証明なし。input revision/hash、指示全文/hash、raw/hash、担当IDを各Runに記録する。rawは生成後に改変しない。
- 評価順: (1)Observationが設計書の複数箇所に追跡可能か、(2)負荷・遅延・ミス・件数を事実化していないか、(3)単一Activityの言い換え／記述欠落だけでないか、(4)対象範囲と意味変更が明示されるか、(5)Unknown/Questionで人間が確認できるか、(6)既存Local/Extremeと意味上重複するか。既知案でもProblemなしで出た事実は別に記録するが、新規業務仮説として数えない。
- 安全閉鎖中の既存scheduled依頼など、設計書自身が未決定としている事項を勝手にProblemや採用可能な改善効果に数えない。既存業務の意味を守る必要がある場合は示し、意味変更は人間判断とする。候補ゼロを許容する。
- 判定: 有用な非自明Observationと検証可能なOpportunityが出ればこの対象では「探索材料になり得る」、既知論点だけなら「発見の新規性は未確認」、品質不備や架空Painだけなら「この条件では不成立」。複数対象で出ても再現率や全体最適の証明とはしない。恒久ルールへの昇格はこの研究でしない。
