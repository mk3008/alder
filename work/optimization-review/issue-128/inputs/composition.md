# 購入結果照合 — sealed synthetic supplement

この架空の完了済み現状設計は独立した検査の合成と数量の扱いを試すためのもの。実顧客の情報はない。

## Object
購入記録: 申請ID、承認数量、承認上限額、実数量、実金額、領収書、照合状態。例外判断の責任者は購買責任者。

## Activity A — 購入結果を照合する
What: 承認済み購入の実績を申請別に確定する。
Why: 承認の範囲内で購入された事実と、証憑の真正性を保持する。
Who: 購買担当者。例外解決は購買責任者。
When: 実数量、実金額、領収書が入力されたとき。
Where: 規定なし。
Input: 承認済み申請、実数量、実金額、領収書（すべて必須）。
How: 担当者が毎件、数量が承認数量以下か、金額が承認上限以下かを照合する。領収書がその購入の真正な証憑かは毎件人間が確認する。不一致は責任者へ戻し、修正または別途承認を受けるまで確定しない。
Output: 三つの確認が成立した記録だけが照合済みとなり、申請ID、実数量、実金額、証憑、判断者を保持する。

## 明示された制約と情報
- 数量と金額の比較は確定済み入力値から機械的に判定できる。入力の正しさは今回の改善対象外。
- 証憑の真正性確認は人間に残す。これを機械判定へ置換することは今回許されない。
- 数量照合の委譲と金額照合の委譲は別々に選べる。どちらも、片方だけも可能。
- 上限金額は数値で、申請ごとに異なる。上限自体を変更する権限は改善担当者にはない。
- 外部証憑認証サービスの利用可否、価格、連携契約は不明。実在・契約済みとは扱わない。
- 隣接の資産管理や採用人事は今回のProblemへ因果を持つ事実がない。

## Review input
Problem: 全件の数値照合を人間が繰り返す負担がある。「一部自動化する」案は、どの責任を残すか未整理である。
Pain: Medium
