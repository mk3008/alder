# Codexによる固定編集試験

実施者はこの作業中のCodexセッション（GPT-6系、実効variant/effortの独立確認なし）。同一文脈でMD→JSONの順に実施する。作者は形式の実装と採点条件を知っており、blind/Fresh比較ではない。追加API・別モデル・有料試験は使わない。推論時間とトークン費用は測定しない。

3課題×2方式、各1回を初回試行として固定する。入力の複製だけをスクリプトで行い、編集自体はCodexが個別のpatchを作成する。変換スクリプトで編集を代行した結果をAI編集と呼ばない。初回結果を保存してから構文/参照/意図外変更を採点し、不合格でも同じファイルを密かに修復しない。

入力はPhase 1の固定3原典。MDは明示境界で3文書を連結、JSONはPhase 2の同内容の型付きpackageからimmutable archiveだけを除いたもの。情報量・参照の表現とトークン長は同一ではない。MDの文書版と永続IDは元形式に存在しない。両候補ともこの局所編集試験ではrevisionを固定する。更新競合とrevision更新は別の機械テストで検査する。

## 固定指示（両方式共通）

対象は各課題の入力コピーだけ。業務上の採用ではなく形式を検査する編集である。指示した箇所以外の意味・順序・レビュー状態・ID・根拠・例は変更しない。自由記述や歴史説明に出る名称はそのまま残す。

1. **why**：新しい購買BDの「備品購入を申請する」のWhyを、元の文末に「（保存形式PoCの編集例）」を付けた内容にする。旧原典側のWhyは変更しない。
2. **rename**：新しい購買BDのActivity「購入を準備する」を「購買を準備する」、Object「購入用CSV」を「購買CSV」へ改名する。構造化された入出力・例外・Findings対象の参照を成立させる。IDが存在する形式ではIDを維持する。旧BDと旧版由来Checkは変更しない。
3. **review**：JA-EX-01の人間レビュー状態だけを「未レビュー」から「要確認」へ変更する。その他の状態・一般保証・例・共有参照は維持する。

## 採点

- 構文成功：その方式のparserで読み取れる。
- 参照成功：BD関係/Findings/Checkの参照が存在し、型と文書版が整合する。
- 目的成功：指定した値だけが変わる。MDは参照名の修復を許可し、IDを保存できない点を別記する。
- 意図外変更：上記許可範囲外の内容/状態が変わらない。
- 差分：実際のGit numstatとpatchを保存。読みやすさは作者の定性所見で、人間の読解時間・誤読率ではない。

各課題は独立した入力から始める。片方の結果をもう片方の編集スクリプトへ入力しない。
