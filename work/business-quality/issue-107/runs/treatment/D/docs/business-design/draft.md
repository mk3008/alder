# 取引先の振込先変更 — 業務設計書（草案・未合意）

対象は、取引先の変更申請を受けて確認・承認し、承認済みの変更を振込先台帳へ反映する業務。以下はヒアリングで確認できた範囲の整理であり、業務責任者の確認を待つ。申請方法、確認・承認の判断基準、支払業務との接続方法は未確認。

## Activity：変更申請の受付

- **Scope:** true
- **Why:** 取引先からの振込先変更を受け付ける。
- **When:** 取引先から振込先変更の申請を受けたとき。
- **Who:** 購買担当
- **Where:** 規定なし。
- **How — Input:** 取引先から変更申請（変更内容）。
- **How — Procedure:** 購買担当が取引先から変更申請を受け、契約担当へ変更内容を渡す。
- **How — Output:** 契約担当へ変更申請の内容。
- **Result:** 変更内容が契約担当の確認対象となる。

## Activity：取引先との変更内容確認

- **Scope:** true
- **Why:** 申請された変更内容を取引先と確認する。
- **When:** 購買担当から変更申請の内容を受けたとき。
- **Who:** 契約担当
- **Where:** 規定なし。
- **How — Input:** 購買担当から変更申請の内容、取引先から確認する変更内容。
- **How — Procedure:** 契約担当が変更申請の内容を取引先と確認し、確認した内容を経理責任者へ渡す。
- **How — Output:** 経理責任者へ取引先と確認した変更内容。
- **Result:** 取引先と確認した変更内容が承認の対象となる。

## Activity：変更申請の承認

- **Scope:** true
- **Why:** 振込先変更を承認する。
- **When:** 契約担当による取引先との変更内容の確認を経たとき。
- **Who:** 経理責任者
- **Where:** 規定なし。
- **How — Input:** 契約担当から取引先と確認した変更内容。
- **How — Procedure:** 経理責任者が変更申請を承認し、その承認結果と対象となった変更内容を経理担当へ渡す。
- **How — Output:** 経理担当へ承認結果と対象となった変更内容。
- **Result:** 承認された変更が台帳反映の対象となる。

## Activity：振込先台帳への反映

- **Scope:** true
- **Why:** 承認された振込先変更を台帳へ反映する。
- **When:** 経理責任者から承認結果と対象となった変更内容を受けたとき。
- **Who:** 経理担当
- **Where:** 規定なし。
- **How — Input:** 承認結果と対象となった変更内容、振込先台帳の変更前の内容。
- **How — Procedure:** 経理担当が承認された変更だけを振込先台帳へ反映する。
- **How — Output:** 振込先台帳の変更後の内容。
- **Result:** 承認された変更が振込先台帳に反映される。

## Object：変更申請と確認内容

- **Scope:** true
取引先からの振込先変更申請、および契約担当が取引先と確認した変更内容。申請と確認の具体的な記録・伝達方法は未確認。

## Object：承認結果

- **Scope:** true
経理責任者による変更申請の承認結果と、その対象となった変更内容。承認の具体的な記録・伝達方法は未確認。

## Object：振込先台帳と変更の確認情報

- **Scope:** true
振込先台帳は経理担当が承認済みの変更を反映する対象。変更後、変更した担当者、承認者、変更前後の内容と時刻を確認できることが必要。確認できる期間は変更後2年間。これらの情報の保持場所や方式は未指定。

## Quality（業務品質要求）

事業責任者の発言に基づき、振込先変更の業務が満たすべき条件を次のとおり置く。

1. 未承認の変更は支払先として使ってはいけない。対象は、変更申請から支払先としての利用までの業務上の許容状態。
2. 変更後2年間、変更した担当者、承認者、変更前後の内容と時刻を後から確認できる。対象は振込先台帳の変更履歴の確認可能性。

既存の事故や負担は報告されていないため、現状の Problem や Pain level は設定しない。技術担当による AES-256-GCM、3台のコンテナ、特定のクラウドDB は未承認のシステム設計案であり、ここで方式を確定しない。認証手段、暗号方式、DB、コンテナ数もシステム設計の検討事項。

## 未確認の業務判断

1. **承認から台帳反映・支払先利用への接続:** 未承認の変更を支払先として使えないようにする際、支払先を使う業務は何を正として承認状態を判断するか。承認後で台帳反映前の変更は利用できるのか。支払先として使えるようになる時点と、その判断を担う業務・役割を確認したい。
2. **変更申請の不承認・確認不成立:** 契約担当が取引先と内容を確認できない場合や経理責任者が承認しない場合、申請を誰へどう戻し、台帳反映の対象外であることをどう伝えるか。現時点の資料には例外時の流れがない。
3. **承認後に内容が変わる場合:** 承認対象と台帳へ反映する内容が異なるとき、再確認・再承認を要するか。変更した担当者・承認者・変更前後の内容と時刻を確認する対象範囲（差戻しや再申請を含むか）も確認したい。

これらは業務上の可否、責任、引継ぎを変えるため、草案のまま残す。記録方式や技術構成の選択で代替しない。
