依頼された Fresh 設定は `gpt-6-sol`、reasoning effort `medium`、`fork_turns: none`。評価時の HEAD は `ed21c60c1decb0ec5306dc32d0f1cf5a4391fd0a`。評価指示の全文は `comparison/evaluator-launch.txt`。実効モデル設定や履歴隔離はこの記録から独立に検証できない。`input-sha256.json` と `runs/sha256.json` に記録された protocol、4 prompt、Business Design、guidance、Problem 確認、4 raw と各 read log の SHA-256 は評価時のファイル値と一致した。ハッシュは比較したテキストの同一性を示すが、読取時点・他資料への非接触を証明しない。各 run の read log は指定された4入力だけを列挙する自己申告である。

## C：S の新規性を Local ごとに比較

- **対 L1**：S の「約束の成立時点、対象期間、種類・組数、番号の確定段階、使用可能状態」と競合時の承認・通知は、L1 候補1の「共通の期間別・番号別の利用約束」と `具体的な検討内容`・`人が決める／確かめる問い` にほぼ存在する。L1 候補1は両講座側でも照合し、学校の4組の持出しと整備待ちを扱う。S は「規則」と責任移譲の言語化がやや明瞭だが、別の主要作用点とは言えない。L1 候補2の番号後決めは S にない別案で、意味変更の承認を要する。
- **対 L2**：L2 候補1単独なら S は水曜・木曜の数量確約と後続申込を覆う明瞭な追加がある。しかし L2 候補2は S と同じ三業務の確約段階、番号への移行、競合時の優先・変更承認・通知を `Scope：Expand` で提案する。S の主要作用点は **L2 候補2単独で既出**。S は点検待ちや戻りの接点をより明瞭に述べるが、独立した構造案の差ではない。
- **対 L3**：L3 候補1は期間別の三用途の必要数を一緒に照合し、住民の新規約束にも効くため構造に到達している。ただし個別番号を後決めする意味変更を組み込む。L3 候補2は学校4組の先行番号確保に寄る。S は現行の住民番号割当を維持可能な中立的規則として約束の拘束力・変更権限を直接扱う点で、L3 の**各案単独**より整理されている。しかし L3 候補1にも競合時の権限者・通知があり、作用点が全面的に新しいわけではない。
- **Local の単純な和に対して**：L1 候補1と L2 候補2のいずれも S の中核を既に含む。両者に L3 の期間数量・学校番号確保を足せば、S の各時点・役割・通知の検討範囲は満たせる。単純な和に新たな共通構造を発明する必要はない。S の表現の整い方や候補を一件に絞った点を、新規な業務上の作用点として二重計上しない。逆に Local がたまたま Expand した事実を、Structural treatment が無益という一般論にも外挿しない。

## Negative control と横断範囲

`benchmark.md` の `工具の受取と貸出` は住民と窓口が番号・付属品・状態を相互確認し、受取署名で引渡しと後の返却責任を明確にする。`通常の修理講座の実施と工具回収` と `学校での出張修理講座と工具の戻り` では講師が使用直前の組、保護具、作業場所を授業の場で確かめる。`工具の点検と整備` では整備担当が使用後の番号・付属品・動作を機能点検し、使えない組に札を付け、復帰日時を記録する。人、時点、目的、証拠が違う。S と Local のどの候補もこれらを単純に統合・削除しない。L1 候補2と L3 候補1の番号後決めも受渡確認の廃止とは違うが、現行の割当 Result を変えるため承認を要する。署名・保護具・作業場所を全候補が同じ精度で明記したわけではなく、保持の記述の強弱は上表のとおり。

全候補は最大3件以内で、Extreme perspectives の独立した節・案は4 raw のいずれにもない。候補を Extreme と読み替えて水増ししない。L1/L2/L3 の Expand は guidance が認める自然な隣接業務への拡張であり、S の制約違反ではない。L2 候補1と L3 候補2は限定的な案として有用で、A の全面一致がないことを単なる失敗とは扱わない。全候補の便益は在庫余力、確約の意味、記録を参照できる時点、実際の重なりと運用負担の確認次第である。

## 総合判定と反証可能な境界

**Local-expands（限定付き）**。S は #99 oracle の根の構造を的確に捉え、共通の業務規則を一候補として節度ある形で提示した。しかし L1 候補1と L2 候補2はそれぞれ単独で同じ主要作用点に達する。したがってこの4件では **Structural-specific な新規作用点は認められない**。L3 に対する S の中立的な表現の利点は残るが、Local の和にも既出である。「No useful structural candidate」は S の有用性を誤って否定し、「Over-expansion」は約束と整備後の復帰に絞った内容に合わない。

この判定は prompt と Problem の非対称性を含む。S には最初から三者の相互扱い、優先・権限・通知が明示され、全設計と共通構造を先に見る treatment がある。Local の焦点はそれぞれ異なるが、各 Problem 自体が他用途との整合を含み、全 arm に隣接 Business を見て Expand できる同じ guidance と設計が渡る。4件は同一 Problem を treatment だけ変えた対照ではない。出力の差や同等性を Structural 指示だけの因果効果と断定できず、run の自己申告 read log から実効隔離も証明できない。

実際の期間別の需要・使用可能数・競合例と権限を関係者が確認して、数量の約束に拘束力がない、または三業務に共通の判断点が運用上成立しないと分かれば、この候補の便益・範囲は再判定が必要になる。逆に同一の Problem 文で treatment のみを変えた独立反復で S にだけ新しい作用点が安定して現れれば、この限定判定は覆り得る。今回は候補・問いの比較であり、方針の採用、実害の確認、全体最適の証明、恒久 Skill の採否ではない。
