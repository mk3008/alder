# Issue #103 — Local / Structural Optimization 比較結果

## 判定

**限定付き Local-expands。** 合成事例「みなと道具室」で、Structural Run は住民貸出・通常講座・学校講座の異なる時点／粒度の利用約束を、一つの業務上の照合・変更規則として扱う有用な候補を出した。しかし **L1 候補1と L2 候補2が、それぞれ単独で同じ主要作用点に到達**した。Local の案を単純に合わせた場合にも S 固有の横断 Candidate は残らない。独立評価の全文と候補別 A–F は [`comparison/evaluation-raw.md`](comparison/evaluation-raw.md)。

| Arm | 候補 | この比較での意味 |
| --- | --- | --- |
| L1 住民貸出 | 2件 | 候補1が期間・必要数・番号を三業務で照合する Expand。候補2は住民の番号確定時点を遅らせる別の意味変更案。 |
| L2 通常講座 | 2件 | 候補1は金曜の限定的な照合。候補2が水曜の数量確定、学校の前週木曜、住民の後続申込を共通の約束として扱う Expand。 |
| L3 学校講座 | 2件 | 候補1は期間別の三用途照合と番号後決め、候補2は学校の4組を早期に番号確保する案。いずれも条件・権限の判断を人へ返す。 |
| S 横断 | 1件 | 三業務に共通する確約時点、期間・組数・番号、整備後の利用可能性、競合時の変更・通知を一つの規則として検討。作用点は L1 候補1と L2 候補2に既出。 |

## 入力の確立

#99 の未合意 v4 を元に、合成顧客役が現在の貸出・通常講座と来月から決定した学校講座を区別して事実確認した。Authoring Skill 0.2.6 の別 Fresh Designer が比較用 [`phase0/benchmark.md`](phase0/benchmark.md) を最小改訂し、窓口側の「定例照合が**決まっていない**」と通常講座側の「定例照合が**ない**」を区別した。学校講座の前週木曜の先行貸出・通常講座予定との照合は、顧客回答に従い**未確認**として残した。合成事例の草案であって実在組織の合意文書ではない。

合成顧客役は [`phase1/problem-confirmation-raw.md`](phase1/problem-confirmation-raw.md) で横断的な未決事項を**改善検討の対象**と確認した。優先順位、変更承認、通知責任、記録・システム方式は決めていない。発生件数、損失、在庫総数、Pain の実測はない。比較の **Medium** は4件共通の実験用 signal で、現場の痛みの強さではない。

## 守った境界と限界

- 貸出時に住民と行う番号・付属品の受渡確認と署名、講師の使用前の組・保護具・作業場所確認、整備担当の機能点検と復帰は、actor・時点・目的が異なる。どの案もこれらを安易に統合・削除しなかった。番号後決め案は現行の申込時番号割当を変えるため、別途人間の承認が必要。
- 候補は未採用の仮説であり、競合の実発生、改善効果、最適解を実証していない。記録方式・優先順位・権限を AI が確定していない。候補ごとの前提や署名・保護具・作業場所の明示の強弱は独立評価を参照。
- Structural は横断 Problem と共通構造を先に見る追加指示を受けた。一方、Local の Problem も隣接する用途を含み、現行 guidance の Expand を許された。**同一 Problem の treatment だけを変えた因果比較ではない**。1ケース・各arm1回から一般的な Structural 優位や「全体最適」は言えない。
- 恒久的な Structural Optimization workflow / Skill の採否は**人間判断のまま**。この比較では S 固有の新しい主要作用点は観測されなかったが、S の一件に整理した説明の価値まで否定しない。

独立評価の冒頭に「未合意の第4草案」とある箇所は #99 の元資料 v4 を指す表現であり、今回の比較入力は上記の合成 **第5草案**。評価 raw は変更せず、本記録で区別する。
