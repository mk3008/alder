# 比較前固定条件

K の人間認識済み Problem：館内展示の企画を固める段階と館外貸出の回答を出す段階で、資料ごとの保存条件との整合をどう確認するかが定例手順として確かでない。後段の設営・梱包時に条件を確認して変更相談する現行業務があり、保存条件が変わった後の既存計画・回答への連絡責任も定まっていない。早い段階の約束と後段の条件確認のつながりを改善対象として検討したい。

この文章は解法・正解 Candidate を指定しない合成の人間役の認識である。件数・遅延・損失は未測定。比較のため Pain level を暫定 Medium と置く。U で人間が確認した Problem に進む場合も同じ暫定レベルを用い、実測の強さと混同しない。

U1 には Problem、Pain、Oracle、K 出力を渡さない。U2 は観察ごとに「改善対象」「理由があり Problem ではない」「事実不足で保留」のいずれかを返す。U3 には人間が確認した Problem と必要な原資料の事実のみを渡し、Discovery の Opportunity や Candidate 文面を渡さない。

Negative control：館内企画承認と対外貸出承認は承認という語が共通でも、対象と責任が違い代用できない。設営前の照明・展示方法の確認と梱包前の輸送条件確認も目的が違う。似た作業を単純に統合・削除する出力は false positive とする。

No-Problem control：`control/lecture.md` の広報承認と支払証憑確認には共通の講演会名しかない。この事実だけから Problem を確定させない。ゼロ Observation または理由確認に留めるものを有効とする。

評価の事前判定：K が既知 Problem に対応し U1 が未認識の構造を観察し、U2 の人間確認後 U3 が K と同じ主要作用点に到達し、negative control を守れば H1 の局所支持。K に重要な欠落があれば H2、U1 固有の価値が確認できなければ H3 の可能性、根拠薄い多数の Problem や意味破壊があれば H4、情報不足や Authoring の手掛かり露出等で入口の必要性を識別できなければ H5。専用 Structural Optimization の必要性は別途判定する。
