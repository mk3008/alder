# Authoring source fidelity・品質確認

入力：`customer-raw.md` と `customer-followup-raw.md`。設計者は Plugin 0.2.6 / provenance `af733229c7f20c5a9fc1c4f094a8fb8c548fe544` を読んで同一 `design.md` を改訂した。初稿と改訂の履歴は `design-v1.md` と `design.md` に残す。

- 受入、状態・条件記録、展示企画、別々の承認、設営、借用依頼と回答、梱包前確認、返却照合を Activity として区別した。番号・資料台帳・保存記録・展示計画・貸出回答を通した相関が読める。
- 顧客が述べた「設営前」「梱包前」の保存記録確認は現行手順とし、「企画確定時」「対外回答時」は未確認とした。状態変更後の伝達、承認時期、将来会期と貸出期間の照合も推測で確定しない。
- 展示責任者の館内企画承認と館長の対外貸出承認を別の責任として維持した。設営時と梱包時の確認目的も別に保った。
- `design.md` は任意 export profile の見出し形式ではない。今回は人間による Business meaning 評価を優先し、exporter の成功を品質証明に用いない。元資料にない実際の頻度・損失・不整合の発生は記載していない。

留保：草案には「貸出と展示の期間照合」の別の未確認事項が Authoring Skill の指示から表面化した。Hidden Oracle の論点と競合し得るため、Discovery がこちらを優先しても結果を消さずに評価する。また、保存条件に関する未確認事項は Business Design に明記されており、Unknown route は完全に手掛かりのない発見を試していない。これは結果解釈の制限とする。
