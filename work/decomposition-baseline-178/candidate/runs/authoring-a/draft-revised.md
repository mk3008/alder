# 倉庫の不足一覧作成 業務設計書（確認待ちの草案）

この文書は、決定済みの運用方針と提供された説明から作った草案です。業務内容の確認・承認はまだ受けていません。

未確認事項：対象倉庫が複数ある場合、不足の判定は倉庫ごとの在庫数と共通の基準在庫数を比較するのか、対象倉庫の在庫数を合算して比較するのか。倉庫ごとに判定する場合、一覧で倉庫をどう識別するかも未確認です。これにより不足一覧の対象と表示内容が変わります。

未決事項：不足一覧を何日間残すか。現時点で保存期間は定めません。

# Scope

倉庫の欠品の見落としを防ぐため、対象倉庫と共通の基準在庫数の登録、および保存済み条件に基づく毎朝の不足一覧の作成を扱う。在庫台帳の更新と商品の発注は対象外とする。

# Activity 不足一覧の条件を登録する

## Scope

true

## Why

不足一覧の作成に使う対象倉庫と基準在庫数を定めるため。

## When

運用の導入時、または条件の見直しが決まったとき。

## Who

倉庫担当者

## Where

設定画面。

## How

### Input

(none)

### Procedure

倉庫担当者が設定画面で対象倉庫と共通の基準在庫数を入力し、不足一覧の条件として保存する。保存直後には不足一覧を作成しない。

### Output

- 不足一覧の条件 — 保存した対象倉庫と共通の基準在庫数

## Result

不足一覧の条件が保存され、毎朝の不足一覧作成時に読み取れる状態になる。

# Activity 不足一覧を作成する

## Scope

true

## Why

対象倉庫の欠品を見落とさないため。

## When

毎朝7時。

## Who

集計システム

## Where

社内の一覧保管先。

## How

### Input

- 不足一覧の条件 — 保存済みの対象倉庫と共通の基準在庫数
- 在庫台帳 — 対象倉庫の商品のコード・商品名・在庫数

### Procedure

集計システムが毎朝7時に保存済みの不足一覧の条件と在庫台帳を読み、対象倉庫で共通の基準在庫数を下回る商品のコード・商品名・在庫数を商品コード順に並べ、社内の一覧保管先に保存する。複数倉庫の場合の判定単位と一覧での倉庫の識別方法は未確認とする。

### Output

- 不足一覧 — 商品コード順に並べた、基準在庫数を下回る商品のコード・商品名・在庫数

## Result

その朝の不足一覧が社内の一覧保管先に保存された状態になる。保存期間は未決である。
