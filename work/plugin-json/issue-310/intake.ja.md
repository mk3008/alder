# 来訪案内 — 検証用ヒアリング

これは架空の業務の草案材料であり、人間が業務設計書へ合意した証拠ではない。

対象は、来訪依頼を受けて案内を記録し、利用者へ知らせる仕事まで。来訪当日の応対は対象外。

利用者から希望日と連絡先を受け取ったとき、受付スタッフと案内システムが「来訪案内を登録する」を行う。目的は利用者が来訪予定を把握できるようにすること。場所は受付画面。

受付スタッフは受付担当と連絡担当を兼ねる。同じ人を別Objectに分けない。案内システムは自動処理の主体で、業務Roleは割り当てない。I/Oの相手である利用者を実行主体と推定しない。

正常手順は次のとおり。
1. 受付スタッフが希望日と連絡先を案内台帳に登録する。必須。
2. 希望詳細が届いている場合、受付スタッフが希望詳細も案内台帳に記録する。条件が成立した場合は必須。
3. 案内システムが来訪日と連絡先を利用者へ通知する。必須。

手順1は手順3より前でなければならない。配列は標準的な提示順で、これ以外の順序制約や入替可能性は決まっていない。

案内台帳は対象範囲内で管理する。利用者・受付スタッフ・案内システムは外部の相手または実行主体として示す。利用者が持つ業務情報は希望日・連絡先・希望詳細・来訪日。台帳が持つ情報も希望日・連絡先・希望詳細・来訪日であるが、所有者を混同しない。台帳への出力と同じ台帳から読み戻す入力では、同じ共通Dataを参照する。来訪日はこの業務では希望日と同じ日を案内する。

正常終了時の結果は、案内台帳に来訪日と連絡先が記録されていること、利用者に来訪日と連絡先が通知されていることの2点。通知失敗時の扱いは未決で、正常結果を確定したことにしない。未決は対象ActivityのFindingに残す。実装・Check作成・一般化した状態遷移は今回は依頼しない。
