# Minimal additive treatments (unadopted)

Control uses the pinned main guidance unchanged. Each arm adds only its paragraph below. No combination arm is initially run. Treatments are research candidates, not product instructions.

## A

When a requested change is not yet adopted, keep the current agreed business distinct from the proposed business. Mark any proposed design as Draft / unconfirmed and the requested means as a candidate, not current or agreed fact. Do not overwrite the current authority with the proposal. Use the existing draft and unconfirmed vocabulary; no new mandatory artifact or lifecycle state is required. Preserve explicit responsible-person decisions and settled external constraints.

## B

Before presenting a new or revised Activity, check Why: it must describe the purpose or expected business condition, not restate Procedure or the requested means. Remove the means mentally; the purpose must still make sense and retain a concrete connection to the affected work. If an existing-business change has no supported purpose or background, ask for the missing Problem or intended condition instead of inventing a Why or treating the means as settled. Do not require a new Problem to justify an explicit new-business decision, reopen agreed meaning, or demand alternatives to a settled external constraint.

## C

At intake, distinguish an unadopted solution-shaped change to existing work from a responsible person's explicit business decision, implementation of agreed meaning, and an externally fixed means. For the unadopted change, retain the requester's means as a serious candidate and locate the current affected work; before a candidate-shaped design is treated as the requested business requirement, ask only the missing background, actual Problem or intended condition that can change the choice. Do not invent a Problem or run Optimization without its required inputs. Once current work and a concrete Problem / Pain are established, route to the existing read-only Optimization Review if comparison is useful, keeping adoption with people; Authoring can then describe an adopted change. Follow the existing Authoring path for explicit new-business decisions and externally fixed changes, and the realization path for agreed implementation. Do not routinely rejustify settled decisions or force alternatives when the means is genuinely fixed. Concrete contradictions or undecided consequences still require a focused question. No new document or state is required.
