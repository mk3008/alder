## Finding

**Diagnostic false mismatch for a source-named Object section (bounded, moderate).** `docs/check-item-traceability.md` under “Activity and Object viewpoints” requires an Object section with the Business Design's Object name, but does not require a literal `Object ` prefix or a particular subtitle punctuation. The existing human-facing rules explicitly caution against imposing one format's syntax on every output. `tools/check_activity_names.py` now filters H2 headings only when they match `Object ` followed by an exact declared Object name and one of `：`, `・`, or ` — ` suffixes (lines 36–48 in the inspected file). Thus a document with `# Activity A`, `# Object O`, a four-column Activity index containing A, `## A`, and `## O` returns `status: mismatch`, `mismatches: ["headings", "index-heading-order"]` even though `## O` is an unambiguous source-named Object section and the Activity labels agree. `## Object O: handoff` likewise returns mismatch solely for punctuation. The bundled script has the same behavior. The Skill requires this diagnostic before return even in Consistency review-only mode, and says exit 1 is a literal mismatch, so a reviewer can be steered toward an unnecessary heading rewrite or report a false NG. Scope the diagnostic's exit-1 claim to its actual heading profile, or recognize Object sections without silently filtering a misspelled Activity. This is not evidence that the Activity names, links, or business meaning of any actual generated document are wrong.

Reproduction used `compare('# Activity A\n# Object O\n', '| Activity | Purpose | Connections | Check Items |\n|---|---|---|---|\n| [A](#a) | p | c | [C](#c) |\n## A\n## O\n')`, which returned mismatch; changing only `## O` to `## Object O` returned match. The test asserts the narrow `## Object O` case and an unknown Object name but does not cover source-named Object headings without the prefix.
