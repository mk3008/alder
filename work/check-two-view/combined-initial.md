## 備品購入を申請する

### PR-01 — 購入申請を成立させる

**人間レビュー状態：未レビュー**

#### 条件と期待する結果

- **必要条件：** 申請者が業務上必要な備品を購入したいと判断し、品名・数量・希望購入金額・購入理由をすべて入力する。各値の許容範囲や入力不備時の応答は業務設計に規定がない。
- **操作：** 新しい購入申請として登録する。
- **期待する結果：** 購入要求が `submitted` の購入申請として記録され、承認者が購入可否を判断できる状態になる。
- **必要条件の表現：** 登録に必要な入力 ⊇ {品名、数量、希望購入金額、購入理由}。入力の存在だけで登録成功を保証する式ではない。

#### サンプル

申請者が品名「事務用椅子」、数量「2」、希望購入金額「30000」、購入理由「執務用」を入力して新しい購入申請を登録する場合、対象の購入要求は `submitted` として記録され、承認者の判断対象になる。数値や文字列の妥当性規則をこの例から一般化しない。

- 根拠：[購入申請の扱い](stack-source/business-design/purchase-request/README.md#購入申請の扱い)、[備品購入を申請する](stack-source/business-design/purchase-request/README.md#activity-備品購入を申請する) Input / Procedure / Output / Result。導出：明示。AI確度：高。優先度：通常。
- 関連：[購入申請](#object-購入申請)、[購入申請を承認する](#購入申請を承認する)、[購入申請を却下する](#購入申請を却下する)。Test/assertion：未提示（証拠未収集）。

### PR-04 — 選択した申請を承認する

**人間レビュー状態：未レビュー**

#### 条件と期待する結果

- **条件（すべて満たす）：**
  - 対象購入申請が `submitted` であり、承認者がその内容を確認して購入してよいと判断する。
  - 承認者が承認する対象購入申請を選択する（必須）。
- **操作：** 選択した対象を承認する。
- **期待する結果：** その購入申請が `approved` となり、承認日時が記録される。

#### サンプル

対象Aが `submitted` で承認者が内容を確認し購入してよいと判断し、Aを選択して承認した場合、Aは `approved` となり承認日時が記録される。金額別の判断経路は [PR-10](#pr-10--金額による承認経路を決める) が未決であり、この例はそれを決めない。

#### 参照情報

- 根拠：[購入申請を承認する](stack-source/business-design/purchase-request/README.md#activity-購入申請を承認する) When / Input / Procedure / Result。導出：明示。AI確度：高。優先度：通常。関連：[備品購入を申請する](#備品購入を申請する)、[購入申請](#object-購入申請)。Test/assertion：未提示。

### PR-05 — 承認した申請を購入対象にする

**人間レビュー状態：未レビュー**

#### 条件と期待する結果

- **条件：** 承認者の判断と対象選択を経て、対象購入申請が `approved` になったとき。
- **期待する結果：** 購買担当者はその購入申請を購入対象として扱える。購買担当者による実際の購入や登録を自動的に意味しない。

#### サンプル

対象Aが承認され `approved` になった場合、購買担当者はAを購入対象として選択できる。実購入金額の入力と対象備品の購入は、後続の [承認済み備品を購入する](#承認済み備品を購入する) の条件に属する。

### PR-10 — 金額による承認経路を決める

**種別：業務設計に由来する未決事項（候補）**  
**人間レビュー状態：要確認**

#### 条件と期待する結果

- **条件：** 希望購入金額によって承認者または承認段階が変わる場合。
- **期待する結果：未承認。** 金額で承認者・段階を変えるか、その場合の境界と判断責任を業務設計は定めていない。通常の [PR-04](#pr-04--選択した申請を承認する) から金額別の承認経路を推定しない。

#### 未決事項

どの金額・条件で誰が何段階承認するのか、それとも金額による分岐を設けないのか。分岐を採るなら承認者の選択と `approved` に至る条件が変わるため、Business Designを改訂して人間が確認した後に本IDを再導出する。

#### サンプル

希望購入金額「30000」の申請と「300000」の申請について、承認者・段階が同じか異なるかは未決。いずれも承認経路をこの例で決めない。

#### 参照情報

- 根拠：[現在の業務設計で未決定の事項](stack-source/business-design/purchase-request/README.md#現在の業務設計で未決定の事項)。導出：明示された未決。AI確度：要精査。優先度：優先。Test/assertion：未提示。

### PR-06 — 選択した申請を却下する

**人間レビュー状態：未レビュー**

**人間レビュー状態：未レビュー**
