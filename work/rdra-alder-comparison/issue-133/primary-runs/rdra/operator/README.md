# RDRA primary orchestration

Operator entry point: `orchestrate.py`, executed from the benchmark workspace. The script never generates or edits AI business artifacts. It stages original official Prompt bytes, official AGENTS.md, .rdracore references, the byte-identical missing-path RDRA.md alias, and only the node's declared DAG inputs. Each AI invocation is a fresh ChatGPT Work collaboration agent requesting gpt-6-sol, medium, fork_turns:none. Effective independent model attestation is unavailable.

`init` creates the 20 clean workflows and hashes the primary inputs. `prepare C1 r1 s1 3` selects up to three input-satisfied, output-absent nodes, saves the envelope and evidence before dispatch, and returns the exact messages. Dispatch is performed through collaboration.spawn_agent rather than native CLI. `started` records the returned agent identity. `finish` accepts a file containing the exact raw final response, checks artifact and required read-log existence, copies unchanged agent artifacts to the project, and retains a node failure. No operator repairs and no undisclosed retries are performed. `post` runs the six original helper scripts in the official DAG order, preserving each script's stdout, stderr, exit status and artifact snapshots before and after execution. A failure leaves the workflow failed.

Per workflow: manifest.json; invocations.jsonl; project/0_RDRAZeroOne and project/1_RDRA; evidence/<node>/; evidence/postprocess/<script>/{before,after}; postprocess.jsonl. Node execution roots are at nodes/<node>/root/. Run input is project/初期要望.txt. Stage2 receives only its resolved s2 source; no Stage1 artifact is copied.

Official source reconstruction: RDRAAgent_v0.8.zip from https://drive.google.com/file/d/1ojI1f1tC4erawdZlkm7jtt3fnM0TTrs9/view, archive SHA256 528b17deb76ac70050620b82118a6140f070f9e7b6282fc8b26d2a43420e074b. Prompt and alias hashes are recorded per invocation. Original Prompt/Knowledge/source copies in nodes/*/root/ and project/RDRA_Knowledge must be excluded from publication; publish envelopes, hashes and acquisition URL instead.

Operational isolation uses a shared filesystem with explicit read allowlists and self-reported read logs. It is not a security sandbox. Original input, Prompt and Knowledge hashes and read allowlist membership must be checked to assess validity. Operator source-manifest metadata exposure and any initial actual/planned envelope differences are retained as deviations and do not become generator business inputs.
