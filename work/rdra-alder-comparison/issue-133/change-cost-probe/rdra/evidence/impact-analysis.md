# 影響度分析: 会議室の利用を停止する（既存予約の扱いの変更）

## 前提
- 根拠データ: `1_RDRA/if/関連データ.txt`。変更対象は、利用停止時の既存予約を維持して利用させる規則から、その時点で既存予約を取り消して利用不可とする規則への変更1点。
- 主対象のモデル: UC「会議室の利用を停止する」。連動対象は UC「既存予約を維持する」、条件「利用停止前予約維持条件」、情報「会議室」「予約」、状態モデル「会議室利用状態」「予約状態」。名前は既存関連データで確認した。

## 関連データ上の出現
- 主 UC は7行14ペア（アクティビティ→UC 4重複、UC→情報2、条件1、画面1、状態との矢印2、説明4）。維持 UC は5行12ペア（アクティビティ→UC 4、UC→情報2、条件1、画面1、説明4）。維持条件は5行8ペア（コンテキストの子1、説明1、バリエーション2、状態モデル2、UC2）。重複ペアは既存表の行展開に由来するため編集時も維持する。
- 会議室情報は7行21ペア、予約情報は7行23ペア。情報→情報は会議室↔予約、社員↔予約。

## 直接影響（辺の種類別）
- `#child`: 条件のコンテキスト所属は維持し、条件名・説明を取消規則へ変更する。業務→BUC→アクティビティの配下で「停止前の既存予約を維持する」を取消作業に変え、利用作業は取消後の意味に反するため当該行を取り除く。
- `#edge`: 停止 UC と取消 UC から予約・会議室、条件、会議室利用停止画面への接続を継承し、参照先の名称を一貫して改める。
- `#arrow`: 利用可能→停止 UC→利用停止中は維持。予約済み→既存予約の取消 UC→取消済みを同じ停止フローに明示する。社員による一般の予約取消遷移はそのまま残す。
- `#attribute` / `#comment`: 情報属性の ID や取消日時は維持。会議室、条件、UC、状態の説明と画面要求にある旧「維持・利用権」の記述を修正する。

## 情報を経由した波及
- 起点情報: 主 UC に直接つながる会議室、予約。
- 情報→情報の BFS: 会議室→予約→社員（深さ2）。これは到達候補であり、社員マスターそのものの意味変更ではない。
- 影響候補 UC: 会議室につながる14 UC と予約につながる15 UC の和集合。特に停止 UC、既存予約の取消 UC、空室検索、新規予約可否、時間変更可否、取消時間帯開放が対象。検索・予約可能性は会議室の利用停止が引き続き優先し、停止に伴う取消を理由に停止中会議室を再表示・再予約可能と解釈しない。画面は会議室利用停止画面、状態は会議室利用状態と予約状態、条件は停止時の既存予約規則と既存の取消時間帯再利用条件。

## 総合評価
- 影響度: 高。状態と条件の意味を反転し、複数の表と派生グラフにまたがる。既存の取消期限なし・当日取消可・取消後の直ちに再利用（利用可能な会議室に限る）・同時予約要求の保証と順序は未決という前提は保持する。
- 確認対象: 既存 `0_RDRAZeroOne` の phase1〜4 の該当行、`1_RDRA` の BUC・情報・状態・条件・バリエーション・アクター・概要、派生 `1_RDRA/if/関連データ.txt`。下流仕様・実装・Check Item は今回の対象外。
