社員が購入申請を出す。10万円以上は部長、10万円未満は課長が承認または却下する。承認後だけ購買担当が購入し、却下時は購入しない。購入結果を申請者へ伝え、金額と物品を記録する。TypeScriptとPostgreSQLを使用する。既存公開REST APIを維持する: POST /purchase-requests は amount_yen（0以上の整数）と item（空でない文字列）を受け取り、201で id と status=pending を返す。不正入力は400とする。POST /purchase-requests/{id}/decision は decision=approved または rejected と role=manager または director を受け取り、金額に対応した役割だけが決定できる。違う役割は403、存在しないidは404。既存schemaを維持する: purchase_requests(id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, amount_yen integer NOT NULL CHECK(amount_yen>=0), item text NOT NULL CHECK(length(item)>0), status text NOT NULL CHECK(status IN ('pending','approved','rejected'))) 。framework、layer構成、Repository/Service等の指定はない。対象は申請・承認分岐と購入への引渡しまで。
