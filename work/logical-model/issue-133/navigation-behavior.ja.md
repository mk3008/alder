# 灰色テーブルから作成工程へ移動する操作

root #133のラフと、将来の正式Viewer組込みで維持する操作契約。今回の正式Viewer実装・parser変更は行わない。

- Activityの局所ERで、灰色テーブルの名前を同じViewer内の作成工程へのリンクにする。色や表示名から推定せず、テーブルの識別子から作成Activity/セクションの識別子への明示的な対応を使う。更新・削除するActivityを作成元と混同しない。
- 今回の見本は、購入申請/申請版/品目→下書き保存、購入申請確定→申請提出、申請判断→承認。外部取得の見積書はこの3工程内に作成元がないのでリンクを作らない。作成元が不明/複数の場合も、先頭候補を無断で選ばない。
- リンクを押すと作成工程の局所ERへ移動し、対象テーブルを選択する。同じ画面で辿り、別タブを強制しない。リンク名は移動先を説明し、キーボードでも操作できる。
- 移動先に「戻る」を表示する。ブラウザ標準の戻るとも整合させる。複数工程を辿った場合は直前の工程へ順に戻る。
- 復帰時に元のセクション、ページ/図のスクロール、選択とフォーカスを復元する。正式Viewerにズーム・パン・タブ・ドロワーがある場合は、その閲覧状態も復帰対象とする。テーブルの手動配置は移動・復帰で変更しない。
- 灰色テーブルでも、名前以外の本体は選択・ドラッグに使える。名前クリックをドラッグ開始と解釈せず、ドラッグを工程移動と解釈しない。
- 全体ERからも明示的な作成元があれば移動でき、戻ると全体ERへ復帰する。直接URLで開いた画面では、存在しない復帰元を作らない。

ラフの対象は下書き・申請・承認の3工程。正式なモデル記法・作成元の宣言方法、Viewerへの読込仕様はGUI採用後に整理する。
