# 多重度を表す配置への修正（2026-10-20）

本人の訂正に基づき、画面幅内への投影・ResizeObserverによる縮幅を廃止。図は自然な大きさのまま縦横スクロールする。カードは280px幅、折返しと内容による高さを維持する。

配置の主たる所属はmodel-layout.jsのprimaryPairsへ明示する。同じ階層の1→0..1を横の一群にまとめ、その群の1→N依存を業務図と同じlayoutPlanへ渡す。N側は親カードから右下へ64pxずらして次の段へ置く。0..1側は同じyで右隣に置く。

複数の親を持つEntityを複製しない。他のFKは破線の参照として保持し、その相手と同じ段に置く保証はしない。例えば現在提出版は購入申請の0..1として横に置き、確定提出版からの参照も破線で残す。準備対象は確定提出版の0..1として横に置き、購入準備の1..Nは参照線として残す。この配置上の主従はDBの所有権・業務仕様を追加するものではない。

全17線で「1：0..1」「1：0..N」「1：1..N」を常時表示し、選択時の関連詳細も保持する。15 Entityと全フィールド、モデル意味・BDは不変。

検証：主たる12関連すべてでN側の右下配置、0..1側の同段横並び、15カードの非重複、全17線の多重度文字列を確認。文字幅を保守的に見積もる計算では自然キャンバス1654×1926px。実寸はブラウザの文字計測に依存する。HTML moduleの構文確認。固定プレビューの実表示・スクロールはPR #254の返却記録で確認し、本人スマートフォン採否を代替しない。
