Object ≠ 論理エンティティ ≠ 物理テーブル

PK：論理上の識別キー案。PK①＋PK②は複合キー。FK：関連先のキー参照案。型・採番・物理制約は未定義。
関連はすべてFK側から参照先1件が必須。0は参照元の記録がまだ存在しないことを表す。
購入結果IDと承認記録IDを分けており、FKだけでは最大1件を保証しない。最大1件を採用する場合は承認記録IDの一意性が必要。
品目番号を使う案は複数品目を識別できる。1品目に限定するか、履歴を何件保持するかは未決。

項目またはエンティティを選択情報項目の配置候補と、任意性・未決事項を確認できる。

未決事項

  • 購入申請に複数品目を含められるか。役職別上限額は申請総額と比較するか。
  • 購入結果を承認あたり最大1件とするか。分割購入・訂正の扱い。
  • 提出内容を固定して承認の根拠とする方式、再申請・再承認の履歴件数。
  • 下書きは提出前の編集情報として扱う案。未入力情報の保持方法は未決。業務上の任意項目とは区別する。
  • 現BDに業務上の任意項目は未定義。任意だからNULL可とする項目は、この案では追加していない。
購入申請を題材にした表示比較。業務仕様・論理モデルの確定には使わない。
