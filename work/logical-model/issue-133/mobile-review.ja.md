# 論理モデルラフのスマートフォン表示修正

2026-10-20。本人のスクリーンショットで、760px以上の固定幅と315px固定高のカード、数量例の常設表示がレビューを妨げていた。

- 業務図と同じ `layoutPlan` / `dependencyOrder`（Viewer `7af581e7319e9ca1fd34e8e0e22e0f314bdc2000`）を実行する。共通関数のアルゴリズムは変更しない。
- 独立HTMLで実行できるよう、共通ソースの型を除いた `shared-layout.js` と `shared-layout-order.js` を同梱した。前者はDAGの `layoutPlan` のみを抜き出し、Alder固有のmatrix分岐は含めない。論理EntityはBusiness/Object相関そのものではないため、汎用DAG経路を用いる。
- 共通処理が返す順序・座標を基に、横方向の段差を表示幅内へ投影し、カード内容の折返しに応じて縦方向を確保する。カードを縮小して文字を小さくする方式にはしない。上下の空白は内容の行数から計算する。
- モデルを先に表示し、数量例・Information一覧・未決事項は折りたたむ。15 Entity・全フィールド・17関連を維持し、関連の名前と多重度は選択時の詳細にも表示する。
- 新記法・正式Viewer・BD・モデル意味・Check/Skill/DDLは変更しない。

検証：元TypeScriptと生成JavaScriptの共通planner出力の完全一致、240〜700pxの9幅で15カードの横範囲と非重複の計算、HTML moduleの構文確認。文字の実幅は実ブラウザのcanvasで計測する。計算検査は実機Androidや画面操作の検証を代替しない。実表示の確認結果はPR #254の返却コメントに記録する。
