# 概念モデル候補の互換情報の棚卸し

対象は文書パッケージを起点とする候補。業務設計、チェック、状態遷移、概念モデル、原典情報までを対象に、候補の全項目と、保存契約・既存の設計判断を照合した。分類はこの候補のレビュー用注釈であり、Alder JSONの保存形式を変更するものではない。

## 互換・移行用として区別するもの

| 対象 | 根拠と扱い |
| --- | --- |
| 手順の旧手順の記述 `steps.legacyText` | 旧手順の原文を移行時に保持するもので、新しいActionの定義とは別。`tools/document_storage/schema.mjs` のStep定義のコメント。 |
| 手順の必須・任意 `steps.obligation` | 新しい概念候補では独立項目にしない。既存の `optional` が示す選択可能性と元の値は、変換時に条件・フローと照合して引き継ぐ。無条件の必須手順に読み替えない。 |
| 手順の旧適用条件 `steps.appliesWhen` | 旧条件文は原本を保持し、判定・例外・手順との対応を確認する。nullを無条件や未決に自動確定しない。 |
| 中断条件 `continuities.trigger` | 例外の発生条件と照合するための既存記録。文章から条件を自動確定せず、原文を保持する。 |
| 中断時の扱い `continuities.onInterrupt` | 例外時の手順と照合するための既存記録。未分解の内容を保持し、手順の確定済みデータとみなさない。 |
| 状態遷移の発生事象 `State.transitions[].event` | 旧宣言の保存用。状態遷移の表示名には使わない。`docs/json-state-transitions.ja.md` の明示された範囲。 |
| 外部業務設計書の目録、外部業務の目録項目と、それらを使う関連 | `externalDocuments` は別保存の旧業務設計書を参照するための最小目録。本文を含まず、現行の業務概念と区別する。`docs/document-storage.ja.md` の版と境界。 |

フィルターONでは、上記の互換・移行用情報を隠す。OFFでは「互換・移行用」の目印を付ける。候補と元データからは削除しない。

## 概念上の扱いを確認するもの

| 対象 | 判断を保留する理由 |
| --- | --- |
| 順序制約 `StepOrderRule` とその関連・属性 | 旧順序規則として引き継いだが、候補0.7の `before` と `interchangeable` に対応する。順不同管理を優先しない方針と手順の前提との重複を踏まえ、全部を一律に旧情報と断定せず確認する。 |
| チェック項目の概要 `Check.items[].detailSummary` | 旧形式の詳細見出しを保持する用途がある。現行のチェック項目にも独立した概要が必要か確認する。 |
| チェック項目および概念・関係・サブシステム・受渡しの `reviewState` | 旧データの確認状態は失わない。一方、「レビュー待ち」を現在の運用概念として置かないという本人の方針と整合させ、各状態が今後必要か確認する。原典との対応確認を示す `basedOn.verification` とは別。 |

これらは「要確認」と表示し、互換・移行用のフィルターでは隠さない。確認対象であることは、過去のチェック項目や人間の判断を変更する指示ではない。

バリデーションで検出する問題は該当手順の例外に記述し、検査を通過した後は通常の流れに記述する。対象がなければ何もしないだけの場合は、独立した条件を設けず手順に記述する。

## そのほかの項目

候補全体の属性・構造・関連を確認し、上記以外は互換専用と特定できなかった。未分類は、概念上の必要性や将来の採用を確定したという意味ではない。特に、参照元の版・照合状態、外部への一般的なリンク、データの記録元、CheckのIDは、それだけを理由に旧情報と決めない。旧 `conceptModel/0.1` を互換入力として扱うことと、0.2でも使用する共通の構造・サンプルをすべて旧情報とすることは別である。
