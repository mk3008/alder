# 概念モデルの値域

文書パッケージを起点とする66構造のうち、項目を持つ64構造の339項目を棚卸しした。[全項目の分類](value-domain-inventory.json)には、項目ごとの判断と根拠を記録している。値域の定義は概念モデルに記録し、Alder JSONの保存形式やSchemaには反映していない。

| 分類 | 項目数 | 扱い |
| --- | ---: | --- |
| 列挙 | 37 | 意味のある選択肢を、値と日本語の意味に分けて記録する。 |
| 固定値 | 6 | 文書の種類や形式が決まる項目の値を示す。 |
| 参照 | 90 | 対象の定義と対応する関係として扱う。 |
| 識別子 | 44 | 同一性を区別する。空白だけの値は使わず、採番や文字形式は決めない。 |
| 版・改訂 | 17 | 特定の版番号に固定せず、空白だけの値は使わない。 |
| 文章 | 103 | 名前や説明など、業務ごとに変わる値は列挙しない。必要な名前は空白だけにしない。 |
| 真偽・数値など | 8 | 真偽値・数値や、条件によって型が変わる値として扱う。 |
| そのほか | 34 | 旧記録、表示情報、URI、多重度、ハッシュ、参照先の種類、値域が未決の項目。 |

主体の種類は `role`（人が担う役割）、`system`（自動実行するシステム）、`scheduler`（スケジューラー）の3つ。主体が未決の業務は、架空の主体を作らず主体への参照を未決にする。`system` と `scheduler` を独立した種類にする必要性は、主体と開始契機の関係を見ながら再検討できる。

手順の受渡し・要求／応答・操作の効果、判定表・判定条件・結果、状態遷移の経路なども選択肢と意味を示す。比較演算子は具体値による条件で使用し、大小比較には数値を用いる。未決・該当なし・nullを一つにまとめない。

業務・対象の関係の既存定義には、対象と業務の入出力に加え、業務同士・対象同士の例外関係も含まれる。両端の違いが分かる選択肢を表示するが、一つの概念名でまとめることが適切かは構造の見直しに関わる。

古い確認状態は元の記録を保持するが、以前の「未レビュー」などの値を現在の業務概念の選択肢として新たに固定しない。版番号、表示色、アイコンも、現行の保存形式や画面上の候補を将来の業務上の値域とみなさない。根拠が不足する項目は無理に列挙せず、棚卸しで区別する。
