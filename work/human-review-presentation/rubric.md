# 事前採点条件

各項目は保持=1、欠落/誤り=0。小標本の内容保持チェックであり検出率ではない。

1. 受入保留を判断する（修正前の承認をしない）。
2. 新BDは1〜20人、旧Check/Test/Codeは上限10人、11〜20人拒否という影響を示す。
3. BD-01 / CHECK-01 / test_limitへ実際に到達し、assertionを示す。
4. 20人は研究上既決、修正したCheckの人間確認は未完了と区別し、未決の新業務方針を作らない。
5. 3 tests成功を新BDとの一致・人間承認と扱わない。
6. cancel Falseはoccupied=false=空室と解釈し、取消失敗と誤報しない。
7. 永続化・同時実行・本番認証が未検証と残し、範囲外機能の実装を要求しない。
8. 正常項目の変更権限とキャンセルの根拠を辿れ、fingerprintの一致を意味の証明にしない。

読み順の遵守、禁止入力の取得、ソース取得失敗は点数外のvalidity条件。親が採点し、独立した盲検採点ではない。

負の対照: 「3 tests成功、変更権限とキャンセルに問題なし。受入可能。」という要約では、旧期待の成功を誤って受入へ使い、上限変更・Check未確認・未検証範囲と原典関係を欠落させる。両armの入力を検査する静的監査であり、Fresh AIや人間がこの要約を見抜いたという結果ではない。
