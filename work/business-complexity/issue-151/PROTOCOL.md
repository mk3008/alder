# 複数業務の複雑性：事前固定プロトコル

## 目的
現実の改善前記述から既存Alderがどの調整上の問い・改善機構へ到達するか、追加の改善前contextで出力がどう変わるかを少数例で調べる。一般的な汎化性能を統計推定する実験ではない。

## 固定条件
- 既存Plugin 0.4.3、公開commit a58c970f3a78ac9a0ba91be3c6bfb05e4e2b1168を無変更で使用
- 2事例、各Discovery 1回、Optimization minimal / context各1回、計6つの履歴なしFresh agent
- 要求 gpt-6-sol / medium / fork_turns:none。実効設定とファイル隔離は独立証明なし
- DiscoveryはworkflowだけでProblem未指定。改善候補を出さない適切な問いや設計確認は失敗ではない
- Optimizationは同じworkflow・同じ資料由来Problem・同じ研究用暫定Medium。context側だけ改善前の規模・時間窓・目的等を追加。Mediumは資料の測定値や現場の合意ではない
- DiscoveryとOptimizationの差をcontext効果と呼ばない。比較対象は同一事例のOptimization対だけ
- 既知の改善後手段・結果、source同定、機構別評価鍵は生成者へ渡さない。匿名化は記憶汚染を排除した証明ではない
- 入力にない工程、役職、権限、保証は補わない。未記載への妥当な確認を尊重する
- 医療事例は公刊された組織内引継ぎの研究再構成。臨床判断や治療手順の提言は範囲外

## 評価
1. 観測関係と原因の仮説が資料に根拠づくか
2. 必要な目的・保証・担当能力・順序・情報・責任を保つか
3. 歴史的改善との機構レベルの一致（なし / 部分 / 中核と因果説明）を、採用・実行可能性・実効果と区別する
4. 他の妥当な改善、意思決定を変える確認質問、確認不足での停止を別に扱う。歴史的案だけを唯一解にしない
5. contextによって機構、未知、質問、責任・保証、scopeがどう変わったかを記述する。単回差から因果効果は主張しない
6. 無根拠のPain、見えない工程や権限の創作、未承認の採用、既知の改善後固有数値の混入を検査する

事例別のsource mappingと期待機構は、HELDOUT-SHA256のhashで生成前に固定し、全6run終了までローカルの生成者許可範囲外に保存する。全生成後に同じ内容を公開し、rawと照合できるようにする。評価者は資料と正解例を知る非盲検である。

## 停止
各条件1回だけ。望ましい出力を得る再生成、途中のguidance変更、seed探索はしない。重大な入力不備は実行結果を保全して比較不能とし、説明なく修正runへ置換しない。入力不足それ自体をAlderの能力不足にしない。
