# 4件の業務設計

各Caseは独立した業務である。以下に各業務の合意前提と業務設計を示す。

# Case 1

## 合意前提

施設の閉館時刻は既に決まっている。運営担当者は開館中の管理作業で、閉館後に入館できる利用区分を変更する。保存した設定は次の閉館時刻から有効になる。入口装置による個々の入館判定は別の業務である。

# Object 施設運用方針

## Scope
false

## Information
- 閉館時刻
- 閉館後に入館できる利用区分

# Object 入館制限設定

## Scope
true

## Information
- 閉館後に入館できる利用区分
- 適用開始時刻

# Activity 閉館後の入館を制限する

## Scope
true

## Why
決められた利用区分だけが閉館後に入館できるようにする。

## When
閉館後の利用区分を見直し、次回の閉館までに設定を変更するとき。

## Who
施設の運営担当者

## Where
施設管理の管理画面

## How
### Input
- 入館制限設定 — 閉館後に入館できる利用区分 / 適用開始時刻
- 施設運用方針 — 閉館時刻 / 閉館後に入館できる利用区分
### Procedure
1. 担当者は現在の設定を確認し、閉館後に入館できる利用区分を選び直す。
2. 次の閉館時刻から適用されることを確認して保存する。
### Output
- 入館制限設定 — 閉館後に入館できる利用区分 / 適用開始時刻

## Result
次の閉館時刻から入口装置が参照する設定が保存されている。

# Case 2

## 合意前提

受付窓口には営業日と休業日がある。窓口担当者は翌月の受付準備中に、休業日の電話を受ける代行窓口を変更する。営業日の着信先は維持し、今後の休業日に着信した電話へ登録内容を適用する。個々の電話を接続する仕事は電話設備が行う。

# Object 受付計画

## Scope
false

## Information
- 休業日一覧
- 代行窓口の連絡先

# Object 着信先設定

## Scope
true

## Information
- 休業日一覧
- 休業日に使用する着信先
- 営業日に使用する着信先

# Activity 休業日の着信先を切り替える

## Scope
true

## Why
今後の休業日にかかってきた電話を、合意した代行窓口で受けられるようにする。

## When
翌月の休業日と代行窓口が確定し、受付準備を行うとき。

## Who
受付窓口の担当者

## Where
電話設備の管理画面

## How
### Input
- 着信先設定 — 休業日一覧 / 休業日に使用する着信先 / 営業日に使用する着信先
- 受付計画 — 休業日一覧 / 代行窓口の連絡先
### Procedure
1. 担当者は休業日一覧を確認し、休業日用の着信先を変更する。
2. 営業日用の着信先が変わっていないことを確認し、設定を保存する。
### Output
- 着信先設定 — 休業日一覧 / 休業日に使用する着信先 / 営業日に使用する着信先

## Result
今後の休業日に使用する着信先が登録されている。

# Case 3

## 合意前提

今月・来月・再来月に開始する講座が講座台帳にある。今回の募集更新は今月中に行い、来月に開始する講座だけを掲載対象にする。他の開始月の講座は今回の更新に含めない。

# Object 講座台帳

## Scope
false

## Information
- 講座
- 開始日
- 募集内容
- 申込先

# Object 募集一覧

## Scope
true

## Information
- 掲載する講座
- 開始日
- 募集内容
- 申込先

# Activity 来月開始の講座を募集一覧に載せる

## Scope
true

## Why
来月開始の講座を希望する人が、募集内容を確認して申し込めるようにする。

## When
今月の募集一覧を更新するとき。

## Who
講座の募集担当者

## Where
講座案内サイトの編集画面

## How
### Input
- 講座台帳 — 講座 / 開始日 / 募集内容 / 申込先
- 募集一覧 — 掲載する講座 / 開始日 / 募集内容 / 申込先
### Procedure
1. 担当者は開始日が来月に属する講座を講座台帳から選ぶ。
2. 募集内容と申込先を募集一覧へ加え、掲載内容を確認して公開する。
### Output
- 募集一覧 — 掲載する講座 / 開始日 / 募集内容 / 申込先

## Result
対象講座の募集内容と申込先が、今回の更新で公開されている。

# Case 4

## 合意前提

見積書には編集中で未保存の内容と、一覧に保存されている内容がある。別条件の見積書を作る際は、保存済みの見積書を複製元に使う。元の見積書は変更しない。複製後の条件変更と送付は別の業務である。

# Object 見積書

## Scope
true

## Information
- 見積書番号
- 品目
- 数量
- 単価
- 複製元の見積書番号
- 保存状態

# Activity 保存済みの見積書を複製する

## Scope
true

## Why
既存の見積内容を元に、別条件を検討するための見積書を用意する。

## When
保存済みの見積内容を利用して、別の見積書を作ると決めたとき。

## Who
見積担当者

## Where
見積管理の一覧画面

## How
### Input
- 見積書 — 見積書番号 / 品目 / 数量 / 単価 / 保存状態
### Procedure
1. 担当者は保存済みの見積書を一覧から選び、内容を確認する。
2. 複製操作を行い、元の番号と異なる新しい見積書が作成されたことを確認する。
### Output
- 見積書 — 見積書番号 / 品目 / 数量 / 単価 / 複製元の見積書番号 / 保存状態

## Result
元の内容を引き継いだ新しい見積書が保存され、元の見積書は維持されている。
