# Explore It! 補助観点：既存3ケースのFresh比較

2026-10-02。Execution: [Alder #125](https://github.com/mk3008/alder/issues/125)。結果前に固定した[計画](protocol.md)、[介入](heuristic.md)、[完全prompt](prompts/)、[実行記録](manifest.json)を参照。

## 結論

**正式採用を保留し、現行方式を維持する。** 補助観点を与えたBには、同じケースのAにない有用な未決論点が3件あった。ただしAだけが保持した論点もあり、各群1回の非盲検評価で、補助文による発見能力向上は示せない。今回の範囲では固定チェックリスト化も、Skillや正式ガイドへの追加も行わない。発想材料としての価値を否定する結果ではない。

「何を探索したか／今回は探索していない範囲」の短い申告は、結果の対象を読む補助にはなる。Bの3出力はいずれも保証ではないことを明記した。一方、未探索欄は主に既存の対象外・未決事項や実装詳細を再掲し、次の業務判断を新たに示したわけではない。標準出力としての導入も保留する。

### 準備時の逸脱

Git tree APIはTransport closed、mirror cloneは認証不足だった。Contents APIで必要な公開ファイルを取得した。別入力や別baselineへの代替は行っていない。

ローカル保存時、baselineと3入力の末尾に改行が1つ増えた。公開blobとローカルblobは同一ではない。全4ファイルについて「公開content + LF」以外の差がないことを照合した。A/Bには同じローカル入力を渡した。意味上の影響はないと判断して実行を保持し、再試行しなかった。manifestには公開blob SHAと実読取ファイルのSHA-256／Git blob SHAを区別して記録する。追試時は公開contentへLFを1つ追加する。prompt・heuristicのローカルsnapshotにも同じ保存処理が入っているため、manifestの実ファイルhashを参照する。

rawに記載された読取範囲は許可入力と整合する。読取申告はagent自身の記録であり、全tool履歴を第三者向けに独立監査できる形式で公開しているわけではない。

「有用」は人間が保証の意味を判断し得る候補という評価であり、実際の利用環境への適用や業務要件の承認ではない。候補ID数と、複合候補を分けた原子論点数を区別した。

PR-B-03は新しい承認段階の必須化ではなく、既存の承認と購入金額の意味を問うものなので、現行の対象内の有用候補とした。Aが結び付けた「金額別承認段階を未決とする」ことだけでは、希望額が参考か上限かは閉じない。ただし保留・再判断の業務を新設するなら人間の承認が必要になる。

AだけにはFM-A-01の後半（日程設定・完了の成功後に結果が失われた再実行）があった。Bの設備保全は新規報告の件数に絞った。探索観点の付加は、Aの各論点の上位集合を保証しなかった。

## 判断の限界と次

各ケース・群1回、同一要求モデル、架空入力、非盲検の担当者評価である。発見の揺らぎ、順序効果、実効モデル設定、人間の採否、実運用の事故減少は評価していない。Bの候補生成と報告書式を同時に加えたため、成分ごとの因果効果は分離できない。類似テーマがAの別ケースにも現れ、B独自の発想能力を示す証拠にはならない。

採用を保留する理由は、具体的な追加候補があっても、それが追加文言によるものか、既存方式の選択的探索の別出力かを区別できず、常設の観点列挙や報告欄を増やす必要性が確立していないためである。低件数を理由に反復せず、このpilotを停止する。

正式Skill・ガイドは維持し、PRでは証跡とResearch Decision Indexのみを追加する。後続の行動変更は決めていない。再検討条件は、実利用で現行方式が同じ重要論点を繰り返し逃す証拠、または探索範囲申告が具体的なレビュー判断を改善した証拠が得られた場合とする。追加研究を自動発生させない。
