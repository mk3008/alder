# 最小 provenance / lifecycle guidance（実験用、恒久 Skill には未適用）

1. 発言の比較対象は、同じ業務上の判断・状態に影響するものに限る。実行可否、Who、When、Where、Input / Output、条件、例外、権限、Object の意味を優先する。言い換えや感想の差だけでは conflict を作らない。
2. 発言者と発言時刻を根拠として保持する。発言時刻と業務ルールの適用時点を混同しない。後に言われたという事実だけで旧発言を破棄しない。
3. 前の説明が誤りだったと明言されたら correction として旧発言と訂正根拠を結ぶ。条件が示され両立するなら refinement として条件ごとのルールを記す。適用時点を伴うルール変更は policy-change として旧・新の適用範囲を分ける。
4. 上記の明示的根拠がなく、同じ論点で両立しないときは conflict / unresolved として草案に残し、どちらが現行か人間へ短く質問する。別人の発言でも同様。根拠が曖昧なら分類を確定せず質問する。
5. provenance の全発言を業務設計書へ転記する必要はない。重要な置換・時間境界・未解決事項だけを読みやすく記す。通常の Alder Authoring Skill の草案・少数の質問・人間レビュー境界は維持する。
