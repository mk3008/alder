# Issue #106 — 発言変化の最小モデル検証結果

**結論：現時点で五項目の guidance 全体は恒久採用しない。** 現行 Alder Authoring Skill 0.2.6 の baseline でも、6 ケースすべてで後発発言を時刻だけで採用せず、同一人物・別人物の未解決矛盾を質問として返した。追加 guidance には明示訂正の出典保持という狭い利点があったが、条件追加ケースでは「両立する」という説明が元の無条件の禁止と後の例外との関係を曖昧にした。現行 Skill への一般的な信頼性も、各1回の合成入力からは推定できない。

| Case | baseline | treatment | 差分と判断 |
| --- | --- | --- | --- |
| A 明示訂正 | Partial | Pass | 両者とも訂正後の本人当日取消を記載。treatment は旧発言の話者・時刻・内容と訂正の関係を明示し、根拠を追いやすい。baseline は訂正を述べるが旧発言の内容を十分残さない。 |
| B 条件精緻化 | Pass | Partial | 両者とも本人のみ可、他者不可という結果を記載し、conflict にしない。baseline は既に明示された他者不可を再確認。treatment は旧来の無条件禁止と例外の関係を「両立」と表現し、論理的に粗い。 |
| C 時点付き変更 | Partial | Partial | 両者とも10月1日からの変更と旧予約の扱いを残し、発言時刻を施行時刻にしない。年と「それ以前の予約」の判定基準は未確認のまま質問。baseline は既出の旧予約規則も再確認する。 |
| D 同一人物の矛盾 | Pass | Pass | 双方、10:00/15:00 を残してどちらが現在の方針か質問。後勝ちしない。 |
| E 別人物の矛盾 | Pass | Pass | 双方、A/B の出典を残し人間に確認。後勝ちしない。 |
| F 非 material な差 | Pass | Pass | 双方、同義の業務表現を統一し、感想を要件化・conflict 化しない。質問は予約業務の通常の欠落について。 |

各 case の判定根拠は [独立評価原文](evaluation/evaluator-raw.md) にファイル・行番号付きで記録した。実際の回答文中の質問は両 arm とも**計14論点**、D/E の必要な矛盾確認が各2論点。A では treatment が通常の未確認事項を一つ追加したが、F の言い換え・感想からの偽 conflict は双方0。件数だけで質問品質を判定しない。

## 仮説と採否

- **H1（最小 lifecycle）: 差分効果は判定保留。** 現行 Skill も四種類の業務上の帰結をほぼ安全に扱い、treatment が新しい処理能力を示したとはいえない。A の訂正 provenance だけ改善。
- **H2（materiality filter）: 差分効果は判定保留。** F のノイズ抑制は両 arm で成立し、treatment による追加の削減は観測できない。
- **H3（粗い同一論点識別）: 一般化は判定保留。** この6例では両 arm が可否・行為者・適用時点を区別した。近接する別論点や大量発言での誤結合・見落としは未検証。

恒久採用を検討するなら、最小候補は「**明示的訂正を適用するときは、以前の説明の話者・発言時刻・内容と訂正根拠を簡潔に結び、旧説明を現在の方針として残さない**」という Authoring 指針の一文だけ。今回は Skill を改訂しない。別の業務と異なる表現で、この一文の出典保持と文量への影響を追加検証してから採否を決める。汎用 Ontology、Graph DB、Business Design の恒久 metadata 追加は必要性が示されていない。

## 限界

合成の会議室予約一題、各 arm・case 一回。C の予約時点の意味は資料だけでは一意ではなく、質問して止めたことは安全側の対応である。raw は独立 Fresh context への依頼と read log で追えるが、共有 filesystem の物理的隔離と実効モデル設定は証明できない。合意済み業務設計や発見率の主張はしない。
