# 購買テスト仕様の条件と対応の見直し

対象は単一 JSON の V7 と、その修正案 V8。Business Design の版は変えず、Check の ID と人間レビュー状態は維持した。V8 は人間の合意前の参考草案であり、Check の存在は実装テストの完了を意味しない。

## 変更した箇所

- P-18 の再出力は、操作の理由だった「CSV の失敗・紛失」を判定条件にせず、指定した購入準備番号と、その対象が確定済みかを表にした。番号なし・対象が確定済みでない場合の結果は未決として残す。もとの、同じ番号・対象申請・版で再出力する保証は維持する。失敗や紛失は再試行の具体的なシナリオに使えるが、システムが外部での紛失を検知できるとは扱わない。
- P-26 は「競合する」という判定値を、承認済み・準備未確定の同じ申請に差戻しと準備確定を並行実行する、再現可能なシナリオに改めた。両操作が同時に成功しない保証を維持し、どちらが成功するかは決めない。
- Activity の Result・各例外から、それを説明する機能別仕様を明示的に参照した。対応は自由形式の presentation を使った Viewer の試作表現であり、正式な JSON 標準ではない。購入準備競合には既存の P-17 と P-26 があり、仕様がないと扱わない。ただし、実際のテストの実装・実行は別問題である。
- P-01〜P-31 の根拠に記された古い Business Design 版を、同じ Activity の現行参考草案の版に更新した。従来の記録は V7 に残す。

## 可否表の照合

表は上から最初に該当する行を読み、`‐` は値不問。以下の「対象外・未決」は、その結果を推測して補っていないことを示す。

| 仕様・表 | 確認結果・残る確認点 |
| --- | --- |
| 下書き保存 | 入力・申請状態を問わず保存可能という P-01 の範囲と一致。元の版・状態を変えない保証は P-02・P-30 で確認する。 |
| 提出 | 見積と上限は先着行で判定する。品目情報・購入理由が揃う場合に限定した表であり、不足時は対象外。入力不備の具体的な扱いは別途確認が必要。 |
| 再提出 | 下書き・差戻しの範囲で、見積不足と上限不適合を扱う。品目・理由不足、対象外の状態は未網羅で、結果を勝手に補わない。 |
| 準備済みからの再提出 | 購入準備済みなら再提出しない P-14 を表す。これ以外の状態を一括して許可する意味ではない。 |
| 破棄 | 下書き・差戻しの破棄可を表す。他の状態の扱いは未記載。 |
| 下書きの再開 | 保存済み下書きの選択・再開を表す参考案。対象が存在しない場合や選択できる範囲は未定義。元の確定内容の保持は P-33。 |
| 承認 | 申請済みの対象版を承認する場合を表す。承認以外は差戻しの表にあるが、未指定・その他の状態は未記載。 |
| 再提出後の判断 | 再提出された申請済み版について、認める・認めないを記載する。判断未指定は未記載。 |
| 差戻し | 申請済み・承認済み・準備確定済みの既存保証を表示する。それ以外の状態や判断値は未記載。 |
| 購入対象の確定 | 有効な承認・未組込みで確定可、組込み済みは重複不可。無効・不明な承認で未組込みの場合は未記載。 |
| 購入準備の競合 | 事前状態と並行する二つの操作を明記し、両方の同時成功を禁止する。実行順や勝者は固定しない。 |
| 再出力 | 番号指定と確定状態を条件とし、その他は要確認。失敗・紛失の検知を前提にしない。 |
| 入庫登録 | 過剰数量と別申請・旧版の不成立を記載する。正の登録条件、0・負数・未入力や複数条件が同時に該当する場合は未記載。結果の P-19 等だけで可否表の網羅性は証明できない。 |
| 未購入で終結 | 購入しない数量の確定後、全品目の待ちが 0 の終結を記載する。待ちが残る場合の確定操作自体の可否やその他の入力範囲は未記載。 |
| 入庫なしで終結 | 入庫なし・全品目全数を購入しない場合の終結を記載する。他の場合の結果は決めていない。 |

## Check と具体例の未解決点

- P-29 は同じ入庫結果の再送を重複させない保証を持つが、同一の再送と判定する入力識別子や、登録成功後に応答だけ失われたケースの再現方法は確定していない。例の入庫回 RC-001 の存在だけから、API の引数や重複判定方式を確定しない。
- P-18 の既存の結果例は、同じ準備を再出力する内容の確認に使える。番号未指定・不明・未確定の仕様は別途確認が必要で、エラー形式は未定義。
- P-26 の同時操作は独立したセットアップ・二つの操作・両方が成功していないという観測で検証する。表の一行がロック方式や実行順を決めるものではない。
- P-01〜P-33 はすべて従来の「未レビュー」を保持する。テスト可能な記述や表示リンクの追加によって、業務・テストが承認されたとは扱わない。

上記の不足の多くは、必要情報の未定義や既存の Check が扱う範囲の限定による。既存の肯定結果から反対側を自動的に禁止としない。
