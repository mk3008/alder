# 保存済みの下書きを再開する案

対象は購買の `purchase-v4-check-review.json`、業務設計 `bd-v3-review-1` の「備品購入を申請する」「購入申請を再申請・破棄する」です。これは業務内容のレビュー用草案です。

## 現在の記載と不足

- 下書き保存はテスト仕様の機能として定義されています。一方、業務設計と状態遷移では例外としても表現されています。
- 新規申請の下書きを保存した後は「購入申請を再申請・破棄する」で再開すると書かれています。その業務には内容確認と再申請・破棄の手順がありますが、保存済みのどの下書きを選んで編集を再開するかが明示されていません。状態遷移 T06 は再申請の成立を表し、再開操作自体は表しません。
- 既存の承認済み・購入準備済み申請に対して別の下書きを保存する案もあります。元の申請状態は変えないため、申請状態が「下書き」「差戻し」の場合だけを対象とする再申請の説明からは、その別下書きの再開経路を読み取れません。P-14 は購入準備済み申請の再提出を認めない案であり、保存した下書きを開けるかどうかとは別の条件です。

## 機能案：下書きの再開

申請者が、保存済みの下書きから対象を選び、その内容を開いて入力を続けます。再開しただけでは提出も破棄も行いません。再保存と提出・破棄はそれぞれの機能として扱います。既存申請に対する下書きは確定済みの提出内容と区別し、開くだけでは元の申請状態・承認・購入準備を変更しません。

対象を選んで開く手段や認可の詳細は、この案から推測しません。再開は状態を変更しない操作として扱い、再提出できるかどうかは再提出の条件で判断します。既存申請に付いた別下書きの再開と、その後の提出可否を混同しません。

## Check と具体例の候補

- 保存済みの下書きを選んで再開すると、保存した入力内容を使って編集を続けられる。
- 再開だけでは提出・破棄せず、既存申請の確定版・状態・承認・購入準備を変更しない。
- 具体例は既存の R-101 の下書きを使い、保存内容を再開して見える内容と元の申請の状態を比較する。新規下書きと、既存申請に別保存した下書きは区別して扱う。

この候補を、既存内容を保持した単一 JSON の参考案 `purchase-v5-resume-reference-draft.json` に追加しました。P-32・P-33 と T20～T22 は未レビューです。元の v4 は変更せず、レビュー画面や状態図があることを業務上の承認とはしません。
