# 発言録の要求保持を観測する単一初回検証

Execution: https://github.com/mk3008/alder/issues/174

## 問いと事前の範囲

公開済みAlder 0.4.4のBusiness Design authoring Skillは、自然な発言録に混在する業務要求とユーザー要求レベルの性能・可用性・セキュリティ・保持・利用条件をどう残すか。一つの合成相談・一つの初回出力を観測する。AWSやDB製品選定の設計はしない。既存の機材レンタル題材を変更して独立した入力として凍結し、前回の得点比較はしない。変更由来はpreparation/change-provenance.mdに残す。

期待Business Design、発言単位の要求台帳、BD外の保持期待はAuthorへ渡さない。BD作成だけがSkillの責務であることを維持し、新規System Requirements文書を出すことは合格条件にしない。発言された業務品質要求は既存の欄に置けることを確認する。外部要求の保持場所に唯一の正解を置かず、前提、未決事項、結果の説明等の保持も内容と採否を失わなければ認める。

## Source precedenceと評価規約

1. 凍結した発言録の明示事実・訂正・採否が当該業務の根拠。後の訂正は訂正前の発言を上書きする。提案は採用と区別する。
2. 公開0.4.4同梱のauthoring guidanceとstructureがAuthorに与える基準。Skillの正規責務を変える要求を暗に付け足さない。
3. 評価時の現行Alder文書は境界解釈を確認するために参照可能だが、未releaseの新機能やルールにAuthorが従ったことは要求しない。
4. Oracleは評価側の解釈であり唯一の分解・表現の正解ではない。矛盾や誤りは原本を残し評価補正として記録する。発言にない隠れた真実を正しく推測しても成功としない。任意の未発言事項を質問する義務もない。

台帳は各要求の発言番号・引用→raw出力位置→判定を対応する。BDに保持／BD外の候補・前提等に保持／確認事項として保持／部分保持／ロスト／不適切な意味変更／提案の要件昇格を区別する。分類が曖昧な要件は理由と妥当な別配置を明記し、完全なカテゴリ一致を合否にしない。未採用技術案や拒否された元案の文言の省略は、合意済み要求のロストと別に扱う。これらで主に検査するのは要件への誤昇格であり、全提案の再引用を要求しない。全台帳と主要BDの境界・受渡し・状態のsanity確認を行う。今回は118項目のBD網羅評価を再演しない。

要求保持には関連する定量値、主体、対象、期間、適用条件、採否が追えることが必要。「性能は後で検討」のように原要求の条件が消える場合は、一般語が残っていても完全保持ではない。全文の発言録を単にリンクするだけでは、草案・返答側へ要求が引き継がれたことの代わりにしない。一方、後続へ渡す具体的な未決要求として明記されれば新規SRファイルなしで保持と認める。

## 対象と文脈分離

release plugin-v0.4.4 / eb177dab8d30383f0a5e084ad22a8eca59455d27。Authoring revision 02093f4d4e957ae851f7812e958aab3827190f31。Structure revision 9cf192c5bced1eeb872795eec8ced21b7bcbf492。標準資料は前回の固定packageから複製し、release git objectと全ファイルの一致を再検証した。最新版releaseはGitHubで再確認した。証跡ブランチの起点main 9cd3d9a3de9a19973af32412e281841fab9f246cとは別の版である。

Authorは親会話をforkしない中立名の新規native agentとする。入力は中立ディレクトリの発言録・標準package・普通の依頼。Issue、計画、oracle、期待分類、前回raw、過去比較を渡さない。親が正確な凍結dispatchだけを送る。全readはopen.pyを通してパス・範囲・sha256を記録し、アクセス申告も別に残す。

OSによる強制隔離はしない。共有filesystem、共通ランタイム指示、利用可能なツール・Skillカタログは残る。許可パス指示とログは読み込んだ資料の証跡であり、あらゆる他経路を排除した独立証明ではない。前回判明したCLI/bwrapのsandbox起動障害を再調査しない。共通カタログのAlder説明は存在し得るが、今回固有のoracleや研究仮説は渡さない。

Fresh author/評価者はrepository AGENTS.mdの既定に従い指定model gpt-6-sol、reasoning medium、fork_turns none。入力合成者はnative既定model・reasoning xhigh。指定値とtool受理は記録するが、実効値を独立確認できなければunknownとする。

## 実行順序・停止条件

入力・oracle・package・完全dispatch・hashを出力前に固定して公開commitへ保存。初回draft・質問・返答・read logは改変せず評価前に凍結する。質問への回答・再草案化はしない。その後に別評価者がread-onlyで照合し、評価原本を保持する。coordinatorによる修正・異論は別記録として残す。

対象ファイルだけをGitHub Git data APIで作業ブランチへ保存する。git proxyの既知のInvalid Git namespaceでfetch不可のため、ローカルcheckoutの履歴は公開mainの証明に使わない。公開commitのbase tree・親はconnectorで確認したmainを使い、余分なローカル変更を公開しない。

rawは合成事例であることとsecret/個人情報/私的参照のないことを確認してから公開する。証跡hash、出力参照、全台帳、差分範囲、公開commit読戻しを検証して結果を返す。コード変更がないためgraph/exportや通常製品テストは本検証の合格条件にしない。Skill変更、記事、release、merge、自動追加実験は行わない。振り返りとControlへの返却・Reviewer確認で今回を止める。

単一の合成事例は実顧客での成功率、一般的な脱落率、モデル間優劣、Skill改修の必要性や効果を確定しない。業務草案は人間未承認のまま。
