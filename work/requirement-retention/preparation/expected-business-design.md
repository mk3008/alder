# 貸出し業務草案の期待意味

これは著者へ渡さない事前の意味基準であり、唯一の正解本文ではない。Activityの名前・数・並び・分割、Objectのまとめ方は固定しない。5W1H、Input → Procedure → Output、Resultと次の開始条件、担当の切替えが読み取れればよい。入力は新しい82ターンだけとし、旧ケースの料金や例外を補わない。

出典の優先順位：requirement-oracle.jsonの66項目にある発言根拠を、この期待文書の自然な補助説明より優先する。以下のInput/Outputや説明には相関を読みやすくする構造上の整理を含む。たとえば変更結果の顧客通知や新条件確認時の在庫表参照について、入力で具体的な手順が指定されていない部分まで独立した必須手順として採点しない。情報が見られることから、担当者がいつもその表を読むProcedureを導かない。期待文書側の補完を著者出力への新しい要求へ昇格させない。

## 文書全体の境界と状態

- 店頭での予約から、機材の準備・受渡し・返却受領・検収・料金確認・経理への請求依頼までを扱う。一店舗、会社・団体向け、配送なし。月〜土9〜18時、日曜休み。
- 現行の仕事と、これから実現したい運用・道具の条件を区別する。新しい毎朝の紙控え、表示や性能等が既に達成されているとは書かない。全面電子化・紙廃止は未決。
- 草案であり業務合意済みではない。受付・倉庫・計算担当が実例と照らして訂正する。
- 修理作業、請求書発行、入金追跡は隣接する範囲外の仕事。直接の引渡しだけ説明する。顧客セルフ予約サイトは今回不要。
- 返却受領、機材単位の検収、貸出可能、料金確認、請求依頼を別の状態として保つ。予約全体の一括完了を作らない。

## 役割とObjectの期待

Whoは受付、倉庫担当、計算担当を一貫して使う。顧客、修理担当、経理は実際の情報の送り先・送り元にもなる。人をWhoに書いただけでI/Oを代用しない。

| Objectの意味 | 範囲の考え方 | 必要な情報 |
| --- | --- | --- |
| 顧客 | 外部の相手 | 予約・変更・取消・延長希望、連絡先・請求先、受領サイン、料金確認・異議、代替への判断 |
| 予約表 | 対象業務で管理 | 予約番号、型、台数、受取・返却予定、確定・取消等の状態、連絡先・請求先。変更時も同じ予約を特定できる |
| 在庫表 | 対象業務で管理 | 管理番号、型に応じた使用可能台数の判断材料、貸出可・貸出中・点検待ち・修理中の状態 |
| 貸出票 | 対象業務で管理 | 対象予約、実機番号、付属品、受領サイン、実受取・返却時刻、機材ごとの点検結果・保留理由、担当者、確認日時、修理症状 |
| 料金表 | 外部から後日提供する根拠。保守業務は今回未記述 | 基本料金・遅延追加料金の計算根拠。具体額は未提供。取消料は本ケースではなし |
| 料金内訳・確認記録 | 対象業務で成立する情報群。独立帳票である必要はない | 機材ごとの計算済み内容、未計算分、顧客へ示した内訳、確認・異議・待ち状態、金額変更の証跡 |
| 請求依頼 | 対象業務で成立し経理へ渡す情報 | 予約番号、請求先、顧客確認済みの内訳と金額。部分的な依頼とその予約の最後の依頼を区別できる |
| 紙の控え | 対象業務で作成・照合・保管 | 当日確定予約、用意済み貸出票、停止中の時刻・担当者・貸出番号・返却内容、点検結果、未確約の問い合わせ連絡先 |
| 変更・点検の履歴 | 各記録のInformationに統合してよい | 予約・金額の変更者、日時、項目、変更前後。点検者、日時、対象機材、確認内容。電話・メールの生値を別コピーとして保持する必要はない |
| 修理担当 | 範囲外の相手 | 故障機材と症状を受け取る。内部の修理・費用負担決定を作らない |
| 経理 | 範囲外の相手 | 請求に必要な予約番号・請求先・確定内訳・金額を受け取る。請求書の保管年限は別の責任範囲 |

構造上のまとめ直しは許容するが、実在する三つの記録を全く区別せず、実機番号と予約番号を同じものとするのは不可。通常I/OはObjectを経由させる。役割間で口頭・紙等によって渡す情報も意味として落とさない。

## Activity 予約を受け付ける

- Who：受付。Where：店の電話・メール、受付の利用環境。When：顧客から予約希望を受けたとき。Why：希望する型・台数・期間で貸出しの約束を成立させるため。
- Input：顧客の型・台数・受取返却予定・連絡先・請求先、在庫表の稼働台数と状態、予約表の期間が重なる確定予約。
- Procedure：点検待ち・修理中を除いた稼働台数と、重なる確定予約の台数を確認する。貸せることを確認して予約表へ確定を記録し、顧客へ返答する。この段階では個体番号を選ばない。予約操作が確定したか不明な間は確保済みと伝えない。
- Exception：不足なら型・日を顧客と相談し、了解前に確定しない。操作結果不明なら対象記録を確認する。押し直しで同じ予約・確保台数を二重化しない。停止中、空きを確認できない新規は連絡先を預かり確約を保留し、復旧照合後に返答する。
- Output：予約表への確定予約、顧客への予約結果または未確定の相談、倉庫が参照する準備対象。
- Result：型・台数・期間の予約が一つ成立し、後日の実機準備に進める。顧客了解のない代替や結果不明の保存は、この正常結果ではない。

## Activity 予約を取り消す

- Who：受付。Where：電話・メール。When：顧客の取消依頼。Why：不要になった予約を解消するため。
- Input：顧客の取消依頼、予約表の対象予約、準備済みかを判断する記録。
- Procedure：予約表を取消にし、その時点で台数を他へ回せる扱いにする。用意済みなら倉庫へ伝え、番号の割当てを外してもらう。取消料はなし。
- Output：予約表の取消、倉庫への割当解除の連絡と貸出票等の割当解除。
- Result：予約の台数約束が解消される。用意済みの実機の割当ても解除に進む。料金条件を理由に台数を留保しない。

## Activity 予約内容を変更する

- Who：受付。Where：店の受付・顧客との連絡。When：日程・型の変更希望。Why：既存予約を顧客の新しい希望に合わせるため。
- Input：顧客の新条件、予約表の元予約・競合予約、在庫表の利用可否。
- Procedure：新条件で空きを確認し、顧客の了承後に同じ予約を修正する。変更を倉庫へ知らせる。
- Exception：空きなしなら元予約を残す。停止中に空きを確認できなければ確約を保留し、復旧照合後に返答する。
- Output：同じ予約の変更内容、顧客への結果、倉庫への変更連絡。
- Result：顧客了解を得た新条件に同じ予約が変わる。確認失敗時に元予約が失われない。

## Activity 利用中の延長に対応する

- Who：受付。Where：電話等の顧客連絡。When：利用中の延長希望。Why：後の予約を損なわず延長可否を決めるため。
- Input：顧客の延長希望、予約表の後の予定、貸出票の現返却予定。
- Procedure：予約表の後の予定を見て延長可能と確認した場合だけ、新しい返却予定を顧客へ伝え、予約表と貸出票を更新し倉庫へ知らせる。
- Exception：不可なら元の期限までに返してもらう。無連絡の遅延を延長承認へ書き換えない。
- Output：新返却予定または元期限の案内、両記録の変更、倉庫への連絡。
- Result：確認できた延長だけが新しい約束になる。

## Activity 機材を準備する

- Who：倉庫担当。Where：倉庫・棚前。When：予約表の準備対象の前営業日。月曜分は土曜。Why：当日の受渡しに必要な実機と付属品をそろえるため。
- Input：予約表の型・台数・予定、在庫表の状態、貸出票の既存割当て、対象の実機。
- Procedure：今貸せる状態と別予約への番号割当てを確認して実機番号を選び、付属品・動作を確認して箱へまとめ、番号・付属品を貸出票へ書く。完了分が前営業日17時までに受付へ分かるようにする。倉庫自身が準備結果を記入できる。
- Exception：用意できない分も同じ17時までに受付へ戻し、顧客と型・日を相談してもらう。受付の相談と顧客了解前に別型を決めない。
- Exception When：受渡しで型・台数の不一致が見つかったとき、受付から差戻しを受け内容を直し、受付・顧客による再確認へ戻す。
- Output：用意した箱、番号・付属品等を記した貸出票、受付への完了または未完了の状況。
- Result：確認済みの実機が対象予約へ割り当てられ、受渡しに使える。17時の条件は未完了報告も含み、「全件必ず17時までに準備完了」とはしない。

## Activity 機材を渡す

- Who：受付。Where：店頭。When：顧客が予約機材を受け取りに来たとき。Why：約束した機材を確認して引き渡すため。
- Input：予約表の対象内容、準備済みの箱と貸出票、顧客の確認・サイン。
- Procedure：予約内容と箱を照合し、番号・付属品を顧客と確認して受領サインを得る。実受取時刻を貸出票へ書き、在庫表を貸出中にする。支払いは後払い。
- Exception：型・台数不一致は倉庫へ戻し、訂正された物の再確認まで渡さない。停止中は紙控えと現物で確認できる既存予約について継続し、時刻・担当者・貸出番号を紙へ書く。代理受取りの確認方法は店長確認待ちで、架空の許可方法を入れない。
- Output：顧客へ機材、受渡し実績とサインを持つ貸出票、在庫表の貸出中状態。
- Result：確認した実機が顧客へ貸し出され、その実績が分かる。

## Activity 返却を受け取る

- Who：受付。Where：店頭と黄色い札の棚。When：顧客が返却物を持参したとき。Why：戻ったことを記録して検収へ引き渡すため。
- Input：返却物、対象貸出票、顧客の返却内容。
- Procedure：返却受領時刻を貸出票へ記し、在庫表を点検待ちにする。貸出票を箱へ添え黄色い札の棚へ置く。受付は検収済みを付けない。
- Exception：停止中も受領を続け、時刻・担当者・戻った内容を紙へ記す。復旧後照合へつなぐ。
- Output：返却受領実績、点検待ちの在庫状態、貸出票を添えた返却物。
- Result：店が受領したことが成立し、倉庫の検収を待つ。貸出可、検収済み、予約全体完了はまだ成立しない。

## Activity 返却物を検収する

- Who：倉庫担当。Where：倉庫・棚前。When：点検待ちの物について手の空いたときに順に確認する。Why：返却内容を確かめ、再貸出や料金計算に進めるか判断するため。
- Input：返却物、貸出票の番号・付属品、追返却された不足品。
- Procedure：番号・付属品がそろい、動くことを確認できた機材ごとに結果・担当者・日時を残して検収済みにし、在庫表を貸出可へ戻す。検収済み分の貸出票を計算担当へ回す。一台保留でも他の問題ない機材を進める。当日中の点検は希望であって保証せず、翌朝となる場合がある。
- Exception：不足なら貸出票へ不足を残し当該機材は点検待ち継続、受付へ連絡する。故障なら症状を記し修理中にして、修理担当へ機材・症状を渡す。いずれも受付の次予約影響確認につなぐ。
- Exception When：不足品が届いたとき、倉庫が残りを再確認する。停止中の紙の点検結果は倉庫担当が確認してから反映し、受付が検収した扱いにしない。
- Output：機材別の検収結果・保留理由、在庫状態、受付への不備、修理担当への故障機材と症状、計算担当への検収済み分。
- Result：確認を終えた機材だけが検収済み・貸出可となり、その分の料金計算が始められる。

## Activity 不備や準備不足を顧客と調整する

- Who：受付。Where：店から顧客への連絡。When：通常の必須順序とはしない。Exception When：準備で用意できない旨、または検収で不足・故障の連絡を倉庫から受けたとき。Why：不足を解消し、影響する予約の顧客と代替を相談するため。
- Input：倉庫からの不備内容、貸出票の不足・故障、予約表の後続予定・連絡先、顧客の判断。
- Procedure：不足は顧客へ追返却を依頼する。不足・故障による次予約への影響を確認し、影響顧客へ型・日を相談する。準備不能も顧客相談へ戻す。了解があれば予約変更の仕事へ渡す。倉庫に顧客連絡を転嫁しない。
- Output：顧客への不足品依頼・代替相談、顧客の了解や未決、倉庫への必要な変更内容。
- Result：顧客と対応を調整し、追返却・再検収または了承した予約変更へ進める。連絡しただけで問題解消とはしない。

この例外対応を各元Activity内のExceptionへまとめてもよい。独立Activityとするなら正常Whenへ例外を混在させず、起点・受け先の例外関係を読めるようにする。

## Activity 返却遅延に対応する

- Who：受付。Where：予約表を確認できる受付・顧客連絡。When：返却予定を過ぎた未返却を確認したとき。Why：返却予定と後続予約への影響を調整するため。
- Input：予約表の期限超過の対象と後続予定、顧客連絡先。
- Procedure：対象顧客へ連絡し、次の貸出しに影響する場合は次の顧客とも調整する。勝手に延長へ書き換えない。確認間隔は未決。
- Output：現在の顧客への返却連絡、影響する次顧客への調整内容。
- Result：遅延について必要な顧客調整が進められる。返却日確定や延長承認を自動成立させない。

## Activity 料金を計算し顧客確認を得て経理へ渡す

- Who：計算担当。Where：計算業務の環境、顧客へのメール。When：倉庫から検収済み分の貸出票を受け取ったとき。Why：根拠のある料金を顧客と確認し、請求依頼へつなぐため。
- Input：検収済み機材の貸出票、予約期間、実返却時刻、料金表、顧客の請求先、顧客の確認または異議。
- Procedure：予約期間の基本料金と実返却時刻から遅延追加料金を計算する。保留機材だけ未計算として残し、問題ない分を進める。基本・追加料金の内訳を顧客へメールし、問題ないとの返答を受けた分だけ、予約番号・請求先・確定内訳・金額を経理へ請求依頼として渡す。予約・金額変更の前後値、操作者、日時を追えるようにする。
- Exception：異議があれば貸出票・料金表を確認し再説明する。無返答は確定にしない。催促間隔は未決。修理費負担の決定責任は店長確認待ちで、未確定額を入れない。料金表の具体額は後日提供。
- Output：顧客への内訳と説明、顧客の確認状態、経理への請求依頼、部分請求と最後の請求依頼をたどれる記録。
- Result：顧客確認済みの分だけ請求依頼が成立し、経理の請求書発行へ渡せる。単に内訳を送った状態と混同しない。

計算、顧客確認待ち、請求依頼を別Activityに分けてもよい。その場合もInput/Outputの情報とResult→次Whenのつながりを保つ。

## Activity 当日の控えを用意する

- Who：受付。Where：店の受付。When：毎朝。Why：停止中も確認できる既存予約の受渡し・返却を続けるため。
- Input：当日分の確定予約、用意済み貸出票。
- Procedure：当日分を紙で控える。これは今後行う運用として示す。
- Output：当日の紙控え。
- Result：障害時に顧客の予定と実物を確認できる準備がある。ただし空き照会不能の新規・変更まで確約可能にはしない。

## Activity 復旧後の記録を照合する

- Who：受付。紙の点検結果の確認責任は倉庫担当に残す。Where：店。When：記録が使える状態へ復旧し、停止中の紙記録があるとき。Why：重複や未反映をなくし、確約可能な記録状態へ戻すため。
- Input：紙の控え・停止中の実績、復旧した記録、倉庫が確認した紙の点検結果。
- Procedure：受付が紙と記録を照合し、未反映だけ登録する。貸出・返却を二重反映しない。点検結果は倉庫確認後に反映する。全照合終了まで新規・変更の確約を再開しない。反映・照合済みの紙を受付の施錠できる引出しへ戻し、見えるカウンターへ放置しない。
- Output：照合・反映済みの記録、確認済み点検結果、保管した紙、再開後に返答する問い合わせ。
- Result：停止中の実績を重複なく反映し終え、新規・変更の確約と保留問い合わせへの返答を再開できる。

## 業務の成立条件として落としてはいけない横断事項

個別ActivityのProcedure/Exception/Result、対応ObjectのInformationへ意味を接続する。一般的なQuality欄を新設して重複させる必要はない。

- 予約確定・変更は受付、準備・点検結果は倉庫、料金計算は計算担当。倉庫が予約台数・料金を独断で変更しない。
- 倉庫へ渡すのは予約番号、機材、予定、点検情報。電話番号・メール・請求先を倉庫へ見せない。これらを扱うのは受付・計算担当。経理には請求必要情報だけ渡す。
- 予約変更者・点検者・金額修正者を識別でき、誰か分からない共有名運用にしない。認証方式は未決。
- 予約・金額変更の操作者、日時、対象項目、変更前後を追跡する。点検は担当者、日時、機材、確認内容を残す。
- 予約の最後の請求依頼から2年間、予約内容、受渡し・点検結果、確認済み料金内訳、変更履歴をたどれる。部分請求の最初の日ではない。
- 電話・メールは、その予約の最後の請求依頼から2年が過ぎ、未解決問い合わせがなければ貸出し管理側から削除する。問い合わせ中は解決まで保持。生の電話・メールを変更履歴に別コピーする必要はない。住所削除時期は経理確認待ち。
- 紙の保管日数・処分時期は店長と未決。電子的な追跡期間の2年を紙へそのまま適用しない。

保持・削除の具体的な実行担当や処理周期は入力にない。独立した保持管理Activityを置く場合、それらを確定事項として創作しない。既存Activityの記録義務とObjectの保持条件として表してもよい。

## BDの外側にも保持すべき具体的条件

以下を「範囲外なので無視」としない。一方、現在の業務手順として無理に押し込む必要もない。草案の前書き、具体的な引継ぎ事項、依頼者への提示応答でもよい。新しいシステム要件書ファイルを自動作成することは、この一回の著者タスクの成功条件ではない。

- 空き候補表示：型・期間入力から普段3秒以内。対象は繁忙期の同時8人まで。通常混雑時の6人を最終上限にしない。データ件数・年数、「普段」の割合、試験方法は未決。業務全体を3秒で終える条件ではない。
- 保存表示：保存中・終了・失敗が分かる。再試行重複禁止という業務条件に結び付けるが、UI表示要求自体も保持する。
- 利用環境：今の受付PCのブラウザー、既存倉庫タブレットで使える。個人スマホ必須にしない。機種・ブラウザー版は未確認。棚前にキーボードを置けず、通常の番号・付属品確認をタブレットを片手で持って進めたい。
- 表示の利用性：状態を色だけでなく「点検待ち」「貸出可」など文字でも区別。現物の黄色札を廃止する決定ではない。
- 店頭端末：無操作5分で顧客情報を非表示にし、そのまま操作できない。再開時には本人確認。確認方式は未決。
- 利用可能性：月の営業時間内で、予約照会と記録が99.5％使えることが目標。営業時間中の計画停止を除外しない。夜間まで常時利用を求めない。計測境界・停止開始の測定方法は未決。紙継続率へ置き換えない。
- 電子記録の回復：誤削除時に「直前30日分は戻せる」こと。通常の業務履歴保持年限とは別。誰が依頼し、どの時点へ復元するかは未決。30日分のデータか復元履歴窓かは発言に幅があり、RPO・RTO、日次バックアップ等を創作しない。
- 習得性：貸出し仕事を知る臨時スタッフなら約30分の説明後、普通の返却受領と付属品確認を一人で進められることが目標。故障判断・代理受取まで拡張しない。店の人に実際に試してもらう。
- 二つのクラウド案は未採用候補。費用と営業時間条件を満たす方法の比較後に採否判断する。バーコード採否も未決。返却読取りだけで貸出可にする案は不採用。

分類に幅がある利用性・可用性・保護条件は、具体的な意味を保ち、業務上の条件との関係が分かれば異なる置き方を許容する。別ファイルの有無、特定見出し、カテゴリ名一致は必須でない。

## 未決の扱いと最終整合確認

- 明示済みの未決：代理受取確認、修理費負担判断、料金表の額、催促間隔、遅延表確認間隔、紙処分、住所削除、端末版、認証方式、測定方法、復元の責任と時点等。既知の草案は進められる。
- それらの同じ質問を直ちに繰り返すことを採点上の義務にしない。隠れた正解、外部の法定期間、実装案を補う義務もない。
- 代表経路：予約確定 → 前営業日準備 → 店頭受渡し → 返却受領・点検待ち → 機材単位の検収・貸出可 → 検収済み分の料金計算 → 顧客確認 → 経理へ請求依頼。顧客確認待ちを飛ばさない。
- 例外経路：準備不足・受渡不一致は受付と倉庫の間で戻る。不足追返却は再検収へ戻る。故障は修理へ渡し、次予約の調整は受付へ渡る。障害は紙へ継続し、全照合完了後に新規・変更の確約を再開する。
- 取消後台数解放、同一予約の変更、延長前の後続予約確認は入力で明示済み。旧ケースの取消料期限や規約の未決を持ち込まない。
