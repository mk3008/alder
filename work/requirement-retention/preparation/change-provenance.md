# 材料の再利用と変更の来歴

## 出発点

旧ケースの入力：alder-transcript-study/work/transcript-study/inputs/transcript.txt（72ターン）。旧ケースの同梱公開パッケージ：inputs/package、Alder 0.4.4。

読んだ公開境界：authoring Skill、同梱adoptionの第1節全文、business-design-structure.ja.md。authoringの基準ソースは02093f4d4e957ae851f7812e958aab3827190f31、文書構造の基準ソースは9cf192c5bced1eeb872795eec8ced21b7bcbf492。旧ケースのraw/evaluationは読んでいない。

業務品質は既存のBD欄へ、採用技術・システム条件は技術側へ、Whereは業務上の利用環境根拠とする公開境界を基準にした。現在mainの実装レビュー側の変更を、著者Skillの新しい義務として持ち込まない。

## 再利用した業務の骨格

- 一店舗の会社・団体向け機材レンタル、店頭受取・店頭返却。
- 予約表・在庫表・貸出票という三情報群。
- 型と台数での予約確定、準備段階の実機番号割当て。
- 受付の受領と倉庫の検収、付属品不足、故障、次予約への調整。
- 前営業日の準備、予約変更・取消・延長、無断遅延と正式延長の区別。
- 検収済み機材からの料金計算、顧客の内訳確認、経理への請求依頼。
- 代理受取と修理費の負担判断は未決、修理・請求書発行・入金追跡は対象外。

これは同一店舗の事実を再調査した記録ではない。旧ケースから着想した独立の合成ケースであり、最終の事実源は新しい入力だけである。

## 組み替え・追加・省略

| 領域 | 新しい入力での変更 | 理由 |
| --- | --- | --- |
| 会話順序 | 予約から料金までの間に機器、応答、情報範囲、障害、復旧、保持を挿入 | 最後にNFR一覧を付けるだけの入力にしない |
| 営業条件 | 月〜土9〜18時を明示 | 店頭継続と月次利用可能性に現場の範囲を与える |
| 準備期限 | 前営業日17時までに完了・未完了いずれも受付へ伝える条件を追加 | 業務上の期限とシステム応答目標を区別できる材料にする |
| 取消料 | 今回は取消料なし | 旧ケースの無料期限・休日受信時刻・料金連絡の枝を簡素化。旧ルールを新ケースへ継承しない |
| 予約・表示 | 3秒、8人、保存結果表示、再試行の二重確保防止 | システム応答・操作性と業務不変条件を同じ会話に置く |
| 停止・復旧 | 毎朝の紙控え、確認可能な既存予約の継続、新規確約保留、全照合後再開 | 営業継続の意味とシステム利用可能率目標を分ける |
| 利用可能率 | 営業時間内月99.5％、計画停止も含む、計測未決 | 利用者目線のシステム選定条件を追加し、構成選定にしない |
| 情報保護 | 倉庫には連絡・請求先を見せない、操作者識別、5分離席保護、紙の引出し保管 | 人の責任・情報の範囲と画面の保護条件を混ぜる |
| 保持 | 最終請求依頼から2年の追跡、問い合わせ条件付き電話・メール削除、住所・紙未決 | 対象情報・起点・例外を持つ実務要件にする |
| 回復 | 電子記録の誤削除から直前30日分を戻せる希望、依頼者・復元時点未決 | 通常業務の保管年限以外のシステム条件を含める |
| 利用環境 | 既存PCブラウザー・タブレット、個人スマホ不要、棚前、文字表示 | Whereの根拠と具体的な互換・表示条件を持たせる |
| 習得性 | 既経験臨時スタッフが約30分説明後に通常作業、店の人で確認 | 一般的な「使いやすい」より具体的だが、熟練判断まで過大要求にしない |
| 技術案 | 読取り即貸出可の拒否に加え、二クラウド案を未採用として会話に置く | 技術案を合意要求へ昇格させないか区別する |
| 省略 | 用途入力の任意性、取消料の規約基準時刻等の枝は再導入しない | 主経路を保ちながら独立ケースの焦点を絞る |

旧ケースとターン対応を取りながら出力差を測る統制実験ではない。追加条件の数だけを効果量として旧研究と比較しない。

## コーディネーターの事前レビューによる改訂

最初の82ターン版を作成した後、著者実行前にコーディネーターが末尾T079–T082の誘導を指摘した。保持・置き場所・文書数・再質問への発言を取り除き、受付・倉庫・計算担当が草案を実例と照らして直す通常の締め方へ変更した。

変更前の入力はpreparation/transcript-before-coordinator-review.txtへ保存した。業務中の具体的な条件T001–T078はこの改訂で変えていない。oracleでは旧末尾由来の保持ポリシー要求を除き、最終入力の草案レビュー要求へ置き換えた。

さらに、候補を引用しないことと合意要件の脱落を分ける注記をoracleに追加した。二クラウド候補は、採用済みへ昇格させることを主要な失敗とし、引用省略だけを合意要求保持失敗に数えない。これは採点境界の事前明確化であり、新しい業務事実の追加ではない。

最後に、期待BDの構造上の補助説明を独立した必須手順へ昇格させない出典優先注記を追加した。66項目の発言根拠を優先し、情報の可視性から常時参照手順を導かない。これも著者実行前の基準明確化である。

## 固定手順

入力とoracleのハッシュをコーディネーターのレビュー後に固定する。準備ファイルの内容は著者実行前に作成し、実行後に結果に合わせて変更しない。現在の具体的ハッシュはrequirement-oracle.jsonのinput.sha256と準備検証結果で確認できる。
