# Issue #102 実施結果

## 変更

- Alder Authoring Skill に、少数の重要な問いを依頼者への回答文で返し、回答を同じ草案へ反映して人間の確認で止める手順を追加した。未決・保留事項を合意済みにしない。
- 情報の閲覧可能性と定例利用を区別し、取消後の可用性を可否から問う。有限資源を共用する活動では、双方の**最初の台数・期間・番号の約束時点**に、相手の既存の約束を認識するかを確認する。後日の番号選定だけでは早い段階の約束を説明できない。
- Plugin を `0.2.5` に更新し、導入文書と版数検証を合わせた。著述元の同梱資料と pinned revision は変更していない。

## 固定した検証と限界

| 実行 | 対象版 | 結果 |
| --- | --- | --- |
| 事前登録4 Fresh ケース | 0.2.2 | 閲覧可能性、共用資源の双方向質問と改稿、保留可能な媒体は適合。取消は初稿の再予約可否の含意と回答後の質問再掲が一部適合。`evaluation-raw.md`。 |
| 修正後2 Fresh ケース | 0.2.3 | 取消の可否と停止は適合。共用資源の講座側確認が依頼者向け回答から抜け、未達。`correction-evaluation.md`。 |
| 双方向指示の新規1 Fresh ケース | 0.2.4 | 双方へ質問したが、講習側は金曜の具体番号選定時のみ。木曜の必要台数を約束する時点を問わず、一部適合。回答反映と停止は適合。`final-evaluation.md`。 |

各実行は一度だけで、失敗・部分適合も raw と評価を保持した。最後の不足を受け、**0.2.5 で最初の約束時点を明示**した。この最終文言については追加 Fresh 実行を行っていないため、行動改善は未実証である。一般的な成功率や実効隔離も測っていない。Plugin パッケージの単体テスト4件と `git diff --check` は通過したが、業務意味の正しさを代替しない。

## 人間による確認

具体的な優先順位、調整・通知の責任者、取消条件は依頼者側の未決事項として残る。草案を合意済みの業務設計へ昇格させるには、依頼者の確認と判断が必要。
