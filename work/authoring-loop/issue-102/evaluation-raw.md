# Issue #102 独立評価（固定4ケース）

## 評価範囲と証拠

- 実行時の **requested model / effort** は4件とも `gpt-6-sol` / `medium`、`fork_turns: none`（`protocol.md`、`runs/run-method.md`）。評価者自身のモデル・effortを特定する記録は本ファイル群にないため、実行時の指定と混同しない。
- 読んだファイル：`protocol.md`、`inputs/case1.md`～`case4.md`、`runs/run-method.md`、`runs/sha256.json`、各ケースの `AGENTS.md`、`notes.md`、`read-log.md`、依頼者向け `response*.md`、最終 `docs/business-design/caseN.md`、ケース2・4の `draft-v1-reconstructed.md` と各差分、`plugins/alder/skills/alder-draft-business-design/SKILL.md`。引用箇所は、明示しない限り当該ケースの `runs/caseN/` 以下。
- ケース2・4の初稿本文は一次 raw ではなく、更新後の草案と差分からの**復元物**。初回の依頼者向け回答文は `response-v1.md` の一次記録として評価する。`read-log.md` は各 Agent の自己申告である。

## 事前基準別判定

| 基準 | 判定 | 観測と理由 |
| --- | --- | --- |
| 1：閲覧可能性を現在の照合手順と区別 | **pass** | `response.md` は「窓口担当は貸せる組を判断するとき、期間別の台帳をどう使いますか」と実際に質問（全2問）。草案の台帳情報は「窓口担当は閲覧できる」、Procedure は「判断に台帳を使うか…未確認」とし、定例照合を事実化していない。棚確認や案内後の予定確保も未確認にした。 |
| 2：共用資源の双方向の将来約束を捉え、講座側の確認時点を依頼者に質問 | **pass** | 初回 `response-v1.md` の第2問は窓口が講座必要組数を確認するかと、「水曜正午後に講座担当が必要組数を記すときは、既存の貸出予定を確認・調整しますか」を両方向で問う。第1問は競合優先順位と通知、第3問は番号照合と整備中の変更。質問は草案だけでなく依頼者向け回答に実在（全3問）。復元初稿の「両方の予定の照合」にも対応する。 |
| 2：固定回答後に既存草案を更新し、未決の優先順位を確定しない | **pass** | `draft-diff-v1-v2.patch` と最終草案は、講座担当が水曜に将来予定を「定例確認していない」、窓口の申込時確認は「未決定」と反映。優先順位と割当変更の承認者・通知担当は「まだ決めていない」と保持した。ただし固定回答の伝達・同じ Skill の再適用は `run-method.md` と自己申告 `read-log.md` に依拠し、実際のツール履歴は未計測。 |
| 3：媒体未定でも草案を出し、媒体だけの追加質問をせず停止 | **pass** | 草案は貸出確認、引渡し、返却照合・記録、故障時の連絡を作成。「紙と表計算のどちら…未決定」と保持。`response.md` の3問は貸出確定時の共有、返却日・空きなしの応答、故障判定・再開という業務意味に関し、媒体だけを決める質問はない。回答なしで追加往復した記録もない。 |
| 4：当日取消・取消後の結果・権限を推測で確定せず、少数の初回質問 | **partial** | `response-v1.md` は3問で当日取消、再予約可能時点、管理者例外の可否と判断条件を問う。復元初稿は当日を未確認とし、管理者例外も手順には入れない。一方、復元初稿の Result「取り消した時間帯が**いつ**再び予約可能になるかは未確認」と第2未決事項「**いつ**空き状況へ反映し」は、再び予約可能になること自体を前提に読める。元メモは再予約を認めるかも決めておらず、初回の質問はその可否を直接問わなかった。 |
| 4：固定回答後、未決のまま草案を維持し、質問を繰り返さず停止 | **partial** | `diff-v1-v2.md` と最終草案は「再び空きとして扱うか」を明示し、当日取消と最終判断者も未決に修正。`response-v2.md` 冒頭は「現時点で追加の回答は不要です」と停止を表明。しかし直後に「判断できる段階で、次の点を確認してください」と4項目を再掲している。即時回答の催促とは断定しないが、顧客が未決定と答えた直後の回答文で質問を繰り返さない、という厳格な基準は満たし切らない。実際の三度目の質問・往復は記録されていない。 |

## 横断的な source fidelity と質問運用

- **概ね適合、一部留保**。ケース1の「閲覧できる」と「使う」を分けた記述、ケース2の水曜の未照合、ケース3の媒体保留、ケース4最終版の取消後の空き可否は、入力と固定回答に沿う。ケース4初稿の再予約可否の前提は上記の通り不正確な含意がある。
- ケース2の復元初稿・最終草案の貸出 Activity Result「貸出予定として扱える」は、メモにある番号割当・受取予定連絡から予定の成立・他の申込への効力を強め得る。割当番号の記録先と講座必要組数との効力を未決としているため確定した優先規則ではないが、文言は要注意。また貸出 Output は「受取予定」のみで、メモの「具体的な番号を割り当て、受取予定を住民へ伝える」に対し、番号の住民への伝達を明示しない。ケース3では「返却日に返却照合・記録を行える」と既知の流れを記載し、媒体を選んでいない。
- 初回依頼者向けの質問数は順に **2、3、3、3**。ケース2回答後は3問を再提示（窓口の確認、金曜の講座側照合、優先・承認・通知を含む）。ケース4回答後は「現時点で追加の回答は不要」としたうえで将来の4判断を列挙。草案中の未確認事項の件数（ケース1=3、ケース2=3、ケース3=4、ケース4初稿=5／最終=6）は、依頼者向けに実際に質問した件数とは区別する。
- 未決の優先順位、調整責任、取消可否、空き扱いなどは合意済みと呼ばれていない。ケース1の受取不一致、ケース3の媒体、ケース4の重複時案内・取消通知も保留。ケース2・4で回答後も判断待ちの事項を具体的に記録した点は評価できるが、同じ問いを再度並べる量は停止基準上の減点とした。

## 実証限界

固定された各ケースは1回ずつの記録であり、一般化可能な成功率、旧 #99/#101 からの改善量、実効的な隔離、Skill の因果効果は測っていない。ケース2・4の初稿本文は復元物であり、一次 raw 初稿としては扱えない。requested model/effort、`fork_turns`、参照資料読込、固定回答の送信、同一 Skill での更新は実行記録または自己申告から確認した範囲であり、独立した実行トレースによる検証ではない。書式やハッシュ記録は業務上の正しさの証明には用いていない。
