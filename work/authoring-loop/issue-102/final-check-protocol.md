# Issue #102 双方向確認の追加 Fresh 検証

0.2.3 の追加実行で case2 の依頼者向け質問が講座側の既存貸出予定を抜かしたため、その raw と判定を固定した。最終修正前に下記の新規1ケースと判定条件を固定する。このケースは一度だけ実行し、結果が未達でも繰り返さない。

入力 `inputs/final-shared-resource.md`。別作業場所に Skill の最終候補、入力、保存先 AGENTS.md を置き、Fresh Agent (`gpt-6-sol`、`medium`、`fork_turns: none`) に自然な草案依頼をする。以前の入力、出力、評価は見せない。初稿と回答文を別ファイルに保存する。

**成功条件**：カメラの貸出と講習が同じ限られた現物に将来の利用を約束する。窓口が講習の必要数をいつ確認するか、講習担当が先に受けた貸出予定をいつ確認するかの**双方を依頼者への回答文で実際に質問**する。閲覧可能な事実から現在の定例照合を推測で Procedure にしない。競合時の優先順位を決めない。

関連質問が出た場合のみ、固定顧客回答「講習担当は必要数を決める時点では貸出台帳を定例確認していません。窓口が貸出申込時に講習予定を確認するかは決まっていません。両方を満たせない場合の優先順位と調整担当も未決定です。」を送る。同じ Skill で草案を更新し、回答後は未決の項目を質問として即時再掲せず停止する。関連質問が出なければ回答は送らない。質問数・差分・未決事項・限界を残す。
