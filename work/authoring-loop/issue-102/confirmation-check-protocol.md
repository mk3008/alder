# Issue #102 先行予定の確認方法：追加の事前条件

0.2.5 の `resume-evaluation.md` は、木曜に必要台数を記す時点を問えたが、「先行貸出を考慮するか」は台帳・予定を実際に確認するかとは同義でないとして部分適合にした。これを固定した上で、Skill の質問指示を一度修正し、同じ `inputs/final-shared-resource.md` を別の Fresh Agent に渡す対応比較とする。失敗も含めて結果を記録し、成功例が出るまで繰り返さない。

- Agent は requested model `gpt-6-sol`、effort `medium`、`fork_turns: none`。別作業場所の入力・保存先 AGENTS.md・修正版 Skill だけを読み、旧出力・評価・本 protocol は見せない。
- 初稿と実際に依頼者へ返した質問文を別に保存する。**成功条件**：木曜の必要台数記入時に、講習担当が貸出台帳の先行貸出予定を確認・照合するかを、依頼者向け回答文で明確に尋ねる。「考慮するか」だけでは未達。窓口が貸出番号決定時に講習予定を実際に確認するかも問う。閲覧可能性から定例利用を推測せず、優先順位は未決のままにする。
- 関連質問が出た場合だけ `final-check-protocol.md` の固定顧客回答を一度送る。同じ Skill で既存草案を更新し、未決定の問いを即時再掲せず停止する。関連質問がなければ回答を送らない。
- 草案内の問いと依頼者向け回答文を分けて判定し、回答数、改稿差分、未決事項、実証限界を残す。同一入力での対応比較であり、一般性能を示さない。
