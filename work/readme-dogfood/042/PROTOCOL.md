## 模擬レビュー入力（モデル実行前に固定）
以下は実際のユーザーの業務承認ではなく、試験用の明示的な模擬入力。
- 対象は工具の返却受付だけ。貸出処理、点検作業、修理、課金は今回実装しない。
- 貸出中の工具番号と、その貸出で渡した付属品一覧が貸出記録にある。
- 番号と付属品が一致した場合だけ返却受領を確定し、返却日時を記録する。記録先は貸出・返却記録。
- 受領済みの組は点検待ちとなり、まだ貸出可能にはしない。
- 番号不一致または付属品不足の場合は受領を確定せず、返却日時と点検待ちへの変更も行わない。窓口へ要確認として返す。
- 受領済みの同じ貸出を再処理しても最初の返却日時を上書きしない。
- 整備担当への物理的な引渡し方法は未決とし、今回の実装範囲に入れない。
- 上記の業務条件に根拠があるCheckは模擬確認済みへ。未決の引渡し条件は未確認のまま。AIが新たに足した期待結果は自動的に確認済みにしない。

## 試験用システム要件
Python標準ライブラリだけの小さいローカルモジュールとunittest。外部通信、実データ、UI、アカウント、依存追加は不要。fixture内のメモリ上の貸出記録を更新する。日時は呼び出し元からtimezone付きdatetimeを渡しUTCへ正規化。永続DB・認証・同時実行・本番運用はこの一回の検証対象外。これらはプロダクト側の試験条件であり、業務設計に新しい業務要件として混入させない。
