# 必要十分性の点検

以下は草案の意味の自己点検であり、人間による採用・実装検証ではない。例の数量は説明のための整数。精度・上限・金額や日付の規則を追加しない。

## 許容する状態と操作

| ID | 具体例 | 表現・期待 | 根拠 |
| --- | --- | --- | --- |
| L01 | 初回保存、1版・1品目、品名も単価も数量も未入力、見積なし | 保存可。未確定版。入力値の不足と品目の不存在を分ける | B2・C1 |
| L02 | 提出する2品目が単価100×3、200×2、上限700、見積・理由あり | 合計700で提出可。版を確定し現在対象にする | B1・B2 |
| L03 | 承認後・準備前に理由付き差戻し | 現在判断は差戻し。過去承認の履歴を必須保存しなくてもよい | B4 |
| L04 | v1差戻し後にv2を編集、再申請で確定 | v1内容不変、v2へ現在対象切替、判断待ち。v1承認の流用なし | B3・B4 |
| L05 | 承認済みAとBを準備番号Pでまとめる | 準備1件・対象2件。両申請に各自の確定版がある | B5 |
| L06 | PのCSV生成失敗、後で再出力 | Pと対象版は維持。書き出し成功日時と準備の存在は別 | B6 |
| L07 | Q10の品目が1回目5、2回目3入庫、C0 | 入庫回2件、R8、W2で作業中 | B7・B8 |
| L08 | 同じ回にA品目3、B品目2が入庫 | 入庫回1件・内訳2件。回と品目のどちらからも追える | B7・H1 |
| L09 | Q10で5入庫後、残り5を購入しないと合意 | R5・C5・W0、一部入庫と残り購入なしで終結 | B8 |
| L10 | Q10で入庫0回、C10 | 全数購入なしで終結。架空の入庫回・購入日時は要求しない | B9 |
| L11 | A全数入庫、B全数購入なし | 品目別W0。申請全体は一部入庫と残り購入なし | B8 |
| L12 | 同じ見積根拠を別申請・別版で参照 | 再利用可。各確定版の根拠内容は不変 | B1・H1 |

## 情報が落ちていないか

| 必要な意味 | 新モデルで読む場所 | 点検結果・限界 |
| --- | --- | --- |
| 下書きと提出を区別 | 版の確定状態、入力値の存在条件 | 下書き専用の入力・品目は不要。C1はBDとの記述差として残す |
| 確定した内容と現在対象を区別 | 不変な版群と申請の現在対象版 | 旧版を保存。現在対象の保存方式は決めない |
| 承認・差戻し・再申請 | 申請の現在判断、対象版、状態遷移 | 旧判断履歴の保存は必須でない。再提出の同時更新条件を落とさない |
| 準備番号とCSV再試行 | 準備と固定対象版、条件付き書き出し日時 | CSV試行全件の履歴は省略。BD上の必須情報の喪失ではない |
| 分割入庫と各回の内訳 | 入庫回・入庫内訳 | 累計に縮約せず、複数回・複数品目を保持 |
| 購入しない数量 | 準備対象品目のC | 合意者・理由や変更履歴の保存は未決のまま |
| 申請全体の一度の終結 | 申請の終結結果と全品目W | 独立した終結エンティティなしで0..1を表現 |
| 見積の根拠 | 版の不変な見積根拠 | 文書の独立管理を省くが根拠内容は落とさない |
| 実績金額・業務上の日付 | 未決情報として別記 | 不要と判断したのではない。必要性と粒度が決まるまで最終実装仕様にはならない |

## この点検で保証できないこと

数値線と属性の個数だけでは不正状態を防げない。全体の成立条件を消してエンティティだけ減らすと、旧版承認の流用や過剰入庫を許してしまう。今回は[工程表](activities.ja.md)と[整合条件](model.ja.md#導出と整合条件)をモデルの一部として残す。

機械検証は、数量の合法状態の列挙・反例と関係図の整合に限定する。現在版切替、競合、再送については上記の机上検証であり、動く業務処理やDBで強制できた証拠ではない。別の再送識別で入力された同じ現物納品の検出、外部CSVの二重発注、実際の認証・権限判定は別の実装・SR・運用上の検証が必要。
