# 全体図と個別図の描画契約

業務フローと概念モデルは、それぞれ次の順に処理する。

1. A：表示対象のノードと関係を抽出する。全体図は全対象、個別図は既定の隣接範囲を渡す。
2. B：抽出済みグラフを配置・配線・描画する。全体／個別の種別や選択の起点を使って処理を変えない。

Bの初期配置、コネクタ割当て、配線、ラベル、選択効果、CSS、操作規則は、同じ図種の全体図と個別図で同一性を維持する。同じ対象グラフ・表示状態（カレント詳細対象と選択を含む）を渡せば、どちらの入口からでも同じ結果を得る。対象数や接続数が異なれば、同じ規則による配置結果は変わり得る。全体図で計算した座標を個別図へ固定する契約ではない。

業務の個別図だけをInput・対象Activity・Output・例外Activityの列へ置き換える分岐や、概念全体を配線してから対象外を消す処理は置かない。対象外の要素をBへ渡して配置や配線へ影響させない。

業務と概念の意味・図形・アローヘッド・件数など、図種固有の表現は維持する。この契約は両図種のレンダラーを丸ごと一つにする要求ではない。各図種において、全体／個別を理由にBを分岐させない。

初期表示の線・ラベル・カードの非重複は、全体図と全個別図で検証する。手動配置・拡大率・選択・スクロールの保存状態はビューごとに持てるが、状態の適用規則は同じにする。

## 現在対象と詳細ナビゲーション

現在開いている個別図の対象と、選択中のカードは別の情報として扱う。全体図ではカレント詳細対象は存在しない。個別図では別のカードを選択してもカレント詳細対象は変わらない。

詳細へのリンクは、リンク先とカレント詳細対象が同じなら表示しない。自己リンクは既に開いている詳細を開くだけで、移動先として意味がないためである。別対象へのリンク、および全体図からの詳細リンクは、対象カードを選択していても表示する。この共通規則へ現在対象の文脈を渡し、全体／個別で別の配置・配線処理を作らない。

条件・保証・理由・検証との対応は[画面操作の検証正本](verification/check-items.json)の `VIEW-NAV-001`〜`VIEW-NAV-003` で管理する。これはViewerのUI要件に対する正本であり、業務用Alder CheckItemの管理範囲を変更しない。

実装修正と照合は別工程とし、`npm run verify:contract` がこの正本を読み、実際の業務・概念DOMを検証する。実装に合わせて正本の期待を変えない。不合格は正本を保持して修正へ戻す。原典の意味変更が必要なら、根拠と影響を示して別の要求判断とする。テスト成功だけで条件・理由の意味照合を省略しない。
