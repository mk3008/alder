# Alder Web Viewer

1つのBusiness DesignのMarkdownをブラウザーで開き、全体図とActivity別の詳細図を切り替えて、ActivityとObjectのつながりを確認できます。ノードを選ぶと右側に対応するMarkdownが表示され、図の配置、タブ、倍率、ライト／ダークの表示を調整できます。

操作方法は[Viewerの使い方（日本語）](usage.ja.md)を参照してください。以下は開発・検証用の手順です。

## 静的検査

`npm run lint` でソース・テスト・Vite設定をoxlintで検査します。CIでも同じ検査を実行します。`npm run lint:fix` は自動修正可能な指摘を修正します。型検査は引き続き `npm run build` で行います。

導入時点の既存警告100件を上限とし、超過すると失敗します。警告を減らした際は `package.json` の `--max-warnings` も下げてください。この上限は件数の増加を検出するもので、同数の別の警告への置き換わりは検出しません。既存コードの一括修正は行っていません。

## 起動する

Node.js 24を用意し、このディレクトリで次を実行します。

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

ターミナルに表示されるlocalhostのURLを開きます。業務設計の表示を試すには、空の画面で「サンプルを開く」を選びます。[Alderを使った設計業務](../business-design/alder/README.md)が表示されるので、自分でファイルを用意する必要はありません。Activity右端の「詳細タブを開く」アイコンをクリックまたはタップすると、そのActivityの詳細タブが開きます。ActivityやObjectを選んで本文を確認してください。配置は初めはロックされています。右下の鍵ボタンでロックを解除すると、ActivityとObjectは本体をドラッグして移動できます。ページを開き直すと、再びロックされます。Activity本体のクリック・タップは、Objectと同様に選択と本文の確認を行います。詳細タブのアイコンはTabで選び、EnterまたはSpaceでも操作できます。図形の選択・移動はポインター操作に対応します。タブやツールバー、Markdown欄の幅調整はキーボードでも操作できます。

配置を元に戻すには、歯車の「レイアウトを初期値に戻す」を押します。表示中の文書のノードを初期配置に戻し、倍率とスクロール位置も初期表示に戻します。本文・未反映の編集・表示設定・配置ロック・他のタブは変わりません。保存できない場合は通知が表示され、変更後の配置は画面に残ります。

図の上で2本の指を広げると拡大し、狭めると縮小します。2本の指の中点を基準に25〜250%で調整でき、右下に倍率を表示します。ロック中は、ノードの上からでも1本の指で図をスクロールできます。ノードを短く押すと選択できます。ロックを解除すると1本の指でノードを移動でき、背景をなぞると図をスクロールできます。ピンチ後は一度すべての指を離すと、次の操作を始められます。

「全体図」は常設です。Activity詳細タブを閉じても、原本と関連Checkは残ります。同じActivityを開くと既存タブに戻り、倍率・配置・選択は各タブで独立します。閉じる保存に失敗した場合は、タブを残して通知します。

全体図には原本のActivity・Object・相関をすべて表示します。Activity詳細は対象Activityと、直接Input/OutputでつながるObject、例外遷移で直接つながるActivityとその線を表示します。例外遷移は入出両方向を含み、隣接Activityの先へは展開しません。対象Activity自身の詳細を開くアイコンは表示せず、隣接Activityのアイコンからはその詳細タブへ移動できます。共有Objectの定義とI/Oは原本に共通です。

サンプルは公開の業務設計書をアプリのビルド時に同梱します。開く操作や表示の復元では外部へ通信しません。配布版に含まれる内容を表示し、原典の変更は次のアプリ配布時に反映されます。

初期配置はRead／Writeの向きに沿って左から右へ伸ばし、画面幅に合わせて折り返しません。循環するつながりではActivityの文書での登場順とObjectの書込み元を配置の手掛かりにし、戻りの関係は元の向きの曲線で残します。この見せ方は業務の実行順序を定義するものではありません。保存済みの配置は更新時も保持し、新しい項目だけを追加します。線は互いに向かい合う面へ接続し、その接続を保ちながら途中のノードを滑らかな曲線で避けます。向かい合う面からの候補がすべて遮られる場合だけ別の面を試します。ノードを移動すると引き直します。複雑な図では線やラベルの重なりが残るため、必要に応じて配置を調整してください。

## 図の情報量を減らす

右下の歯車ボタンで、4つの表示設定を開閉できます。設定は上側に開き、Escapeで閉じられます。倍率の調整と配置ロックは常に表示されます。

歯車ボタンを押して「Writeを優先表示する」をオンにすると、同じActivityとObjectの間にReadとWriteの両方がある場合にRead線を隠します。Readだけの接続、Write線、例外線は残ります。元の業務設計やデータは変更しません。初期状態はオフで、設定はテーマと同様にこのブラウザーへ保存されます。

左上の一覧ボタンで、Activity・Object・ロール別の一覧を開けます。名前で検索でき、ロール別ではWhoと同じ色の人物アイコンを見出しに表示します。見出しでActivityの一覧を折りたためます。種類の切替は左右矢印、一覧を閉じる操作はEscapeにも対応します。

各行の目アイコンで、その項目だけを表示・非表示にできます。表示中の目は文字色、非表示の目は控えめなグレーです。「スコープ外」の目は範囲外の全項目をまとめて切り替えます。一部だけ表示しているときは表示件数を示し、押すとすべて表示します。その後、各行で個別に切り替えられます。非表示の項目も一覧には残ります。孤立したObjectは自動では隠しません。

表示中の名前を押すと、倍率やノード座標を変えずに、見えている図の中央へ移動して選択します。中央へ移動するための余白だけを図の外側に確保します。非表示の名前を押しても表示や移動はしません。図で選択すると一覧の種類とロールを開き、該当行を示します。検索条件に合わない選択では検索を解除します。狭い画面では左一覧を図に重ね、名前から移動すると一覧を閉じて、右のMarkdownに隠れていない領域の中央へ移動します。

非表示では、その項目につながる線・ラベルも隠します。全項目の座標と経路計算・図の範囲は保持するため、表示を戻すと同じ位置に戻ります。選択中の項目を隠すと選択を解除し、Markdown全文を表示します。Write優先と併用でき、表示設定は全体図・Activity詳細タブごとにブラウザーへ保存します。旧版の半透明設定と旧チェックボックス設定は「表示」へ引き継ぎ、旧選択式の「非表示」は各文書の範囲外項目に引き継ぎます。

## 自分の文書を読む

- 「ファイルを開く」でBusiness DesignのMarkdownを選びます。元ファイルは書き換えません。
- 「テキストを入力」ではMarkdownを貼り付けて開きます。
- 「URLを開く」は、匿名取得とCORSを許可したHTTPSのMarkdown本文URLに対応します。認証が必要なページやHTML表示ページ、リダイレクト先は取得できません。URL本文は2MiBまでです。

別の業務設計書を開くと、原本とActivity詳細タブを置き換えます。現在の本文・関連Check・タブ・配置などの閲覧状態をブラウザーに保存します。以前の本文を新しい世代として蓄積しません。読込・保存に失敗しても現在の図を保持します。

「原文を見る」から全文を読み取り専用で確認できます。業務設計書とCheckの編集は外部で行います。テキストを貼り付けて開く操作も使えます。

URLで開いた文書は、起動時に取得元の本文を取得して現在の本文と比較します。差分を確認できた場合だけ、インフォバーで古いバージョンを開いていることを知らせ、「更新する」「このまま読む」を表示します。自動的に本文を置き換えません。通信失敗・未変更では更新通知を出しません。「このまま読む」を選んで未更新なら、次回起動時に再確認します。通常の「更新」ボタンからも読み直せます。更新時は既存の配置と有効なActivityタブを維持し、関連Checkとの対応を再評価します。

「開く」のURL閲覧履歴から過去のURLを再訪できます。同一URLは重複せず、履歴にはURLと名前だけを保存します。履歴から別の文書を開くと、取得元の現在の本文を読み込みます。ファイル・サンプル・貼付けテキストはURL履歴に入りません。

URLの共有ボタンは取得元だけを含むリンクをコピーします。本文、配置、関連Checkを相手へ送る機能ではありません。URLに認証情報・クエリ・フラグメントがある場合や、旧版の編集が残っている場合は理由を示します。同じURLを表示中なら表示状態を保ち、取得元の更新有無を確認します。別のURLなら新たに取得します。


文書と設定はブラウザーのIndexedDBへ保存します。URLの読込・更新・起動時確認では指定元へ匿名通信します。Cookieやブラウザーの認証情報は送りません。URLのクエリは指定元へ送信され、URL全体もブラウザーに保存されるため、秘密情報を含むURLは入力しないでください。共有端末では保存内容に注意してください。サイトデータを削除すると、閲覧状態・履歴・旧データも失われます。ファイルの再読込では再選択が必要な場合があります。

閲覧状態を次回に引き継げない場合も、現在の本文と図はそのまま閲覧できます。OS権限変更・プロセス強制終了・Android等の実機でのタッチ操作は未検証です。

## 関連するCheck Itemsを読む

業務設計書を新しく開くと、「チェックリストも開きますか？」の任意案内を表示します。「あとで」で閉じられ、復元時には再表示しません。案内または文書ツールバーの「チェックリストを開く」アイコンを選び、「ファイルを開く」から別のCheck Markdownを選びます。「URLを開く」では、業務設計書と同じ匿名HTTPS取得の条件で本文を読み込みます。新しいGraphタブは作りません。アプリの「サンプルを開く」で表示した未編集の業務設計書では、メニューの「サンプルを開く」から対応する2項目の表示見本を試せます。通常のファイル・URL・テキスト入力や編集後のサンプルには、このリンクを出しません。

業務・Object名はタブの上に表示されます。Activityを選び、「業務内容」と「チェック項目」を切り替えて確認します。共有Checkは業務別インデックスから同じIDの本文を表示し、未決事項と人間レビュー状態を原文のまま残します。根拠・関連業務・テスト証拠を含む全文は、元のCheck Markdownで確認してください。読込や関連付けは、Checkや業務意味の承認にはなりません。

原典参照が別文書なら関連付けを拒否します。GitHubのblob/raw表現を照合し、commitの違いは版の一致未確認として扱います。ローカルファイルや識別情報が足りない文書は自動確定せず、原典・業務別インデックス・本文を確認して「対応を確認して表示する」を押します。対応先のないActivity／Checkは不明として表示し、名前を補って結び付けません。BDの本文を変更した場合は関連付けを再確認します。

関連付けとCheck本文は業務設計書ごとに保存し、全体図と各Activity詳細で共有します。復元時の自動取得はありません。読込後の再指定・解除は、文書ツールバーの「チェックリストを開く」アイコンから操作します。不要なら「チェックリストを閉じる」を選びます。読込・保存に失敗しても現在の関連付け、図、入力中の本文を保持します。

[購買Check実例](../docs/examples/purchase-check-review.ja.md)の現行表示形式（業務一覧の4列表、`### CheckID — 見出し`、条件・期待結果・人間レビュー状態）に対応します。別のMarkdown形式を推測して変換しません。通常表示は条件・期待結果・人間レビュー状態を中心にし、補足の詳細領域は表示しません。数式の組版は行いません。読込データと原本は保持し、表示のために原本を書き換えることはありません。

## 検証とビルド

修正中の対象指定と、全体検証へ進む条件は[変更の検証手順](validation.ja.md)を参照してください。

```sh
npm test
npm run build
npm run preview -- --host 127.0.0.1
```

`dist/` に静的ファイルを出力します。アセットは相対パスです。テスト用文書や契約fixtureはビルドに含めません。テストにはDOM・IndexedDB・ファイル権限のモデルが含まれ、実ブラウザーやOS権限の確認とは区別します。

## 確認版と本番を分ける

`preview/pr-194/<版ID>/` の確認用URLでは、画面上部に「確認用」と版IDを表示します。文書と設定は本番とは別のIndexedDBへ保存します。確認版どうしも版IDごとに分かれ、同じ確認用URLを開き直すとその版の状態を復元します。URLのクエリやハッシュは保存先を変えません。これは同一サイト内の保存先の分離であり、別オリジンのセキュリティ境界ではありません。

公開サイトへ配備した確認用URLは一般公開です。公開許可がない確認では、localhostで操作できる静的パッケージを使用します。配布するのはWebアプリの静的ファイルだけで、入力した文書を公開する仕組みではありません。

配備時は、既存の配備ブランチを基準に新しい版IDのディレクトリへビルド成果物を追加し、本番と既存の確認版のファイルを保持します。版IDは再利用せず、ソースcommitと配布ファイルのhashを配備記録へ残します。本番の全ファイルが変更されていないことを、配備前後のGit blobと公開URLのbytesで確認します。

確認版の承認後は、確認済みの配布ファイルを再ビルドせず本番へコピーします。同じJavaScriptがURLから確認用表示と保存先を切り替えるため、昇格時の書き換えは不要です。復旧に備えて直前の本番ファイルとhashを記録し、復旧時も本番部分だけを戻して確認版を保持します。開いているタブが参照する旧assetsは残し、IndexedDBを削除・変換しません。

## 設計の確認事項を読む

[Findingsの記法](../docs/design-findings.ja.md)で関連するActivity/Objectを明示すると、未解決の要確認・要修正を図形と詳細で確認できます。既存Problem/Painは困りごととして区別します。左ドロワーの「指摘」では、文書全体・関連先未設定・参照先不一致も確認でき、解消済みを再表示できます。

[図書貸出のサンプルMarkdown](../examples/design-findings/library-lending.md)を「テキストを入力」または「ファイルを開く」で読み込むと、困りごと・要確認・要修正の印を試せます。左ドロワーの「指摘」には文書全体と関連先未設定も並びます。「解消済みも表示」で解消済みの指摘を確認できます。架空の例には返却期限の意図的な不一致があり、実際の運用規則には使えません。

左ドロワーの「項目」はActivity・Object・ロール一覧、「指摘」は要確認・要修正と困りごとの一覧です。指摘を選ぶと左ドロワー内に詳細が開きます。複数の関連項目は詳細の移動ボタンで選べます。移動先の業務設計本文は右側に表示されます。非表示の項目や参照先が見つからない項目へは移動できません。
