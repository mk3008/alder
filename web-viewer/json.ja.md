# JSON文書を読む

Pluginが作成・更新した型付きJSONを、業務の図と本文、指摘、Checkで確認できます。

<a id="確認版を用意する"></a>

## Viewerを開く

[公開Viewer](https://mk3008.github.io/alder/)を開きます。

## JSONを開く

「開く」→「サンプルを開く」で、業務設計書とチェック項目を含むJSONの表示を試せます。

1. 「開く」→「ファイルを開く」からJSONを選びます。ローカルファイルはサーバーへ送信しません。
2. 全体図や一覧でActivityまたはObjectを選ぶと、右側の業務内容を読めます。Activityの詳細タブも使えます。
3. 右側を「チェック項目」へ切り替えると、そのActivityのCheckと、文書全体・未割当のCheckを表示します。一般保証や例の参照は展開して読めます。
4. 左の「状態遷移」で対象を開き、操作・例外・未決を確認します。記載のない操作を推論しません。
5. 指摘から未決事項と関連項目を確認します。修正はPluginへ依頼し、更新したJSONをViewerで読み直します。

Checkは同じJSON内に入っています。Markdown用の別ファイルの関連付けは不要です。元JSONは「原文を見る」から読み取り専用で確認できます。

## 版と確認状態を読む

JSONの構造版、文書集の版、BDとCheckの版を区別します。ActivityやObjectを改名しても、IDを維持した更新なら選択や配置を引き継げます。

「原典の意味対応は未確認」は、ID・版の機械的一致から業務合意を判断していないことを表します。Checkの「未レビュー」「要確認」「確認済み」「要修正」は保存された人間レビュー状態です。Viewerで開くことや、参照の検査が通ることによって状態は変わりません。

## 読込の条件

| 読込方法 | 条件 |
| --- | --- |
| ローカルJSON | 8MiB以内。サーバーへアップロードしません。 |
| HTTPS URL | 2MiB以内。匿名取得・CORS許可が必要で、30秒で中止します。取得中は既存のキャンセル操作を使えます。 |
| テキスト入力 | 2MiB以内。入力後は読み取り専用です。 |

現在の新規保存契約は候補0.4で、旧候補0.1〜0.3も互換入力として読み込みます。対応する構成は、1つのJSON内にBusiness Designが1件ある構成です。複数のCheck文書は読めます。別のBDを原典とするCheckは現在の図に関連付けず、その理由を表示します。

未知の版・文書種別、不明参照、Checkの原典版ずれを黙って補正しません。読込や保存に失敗した場合は通知し、現在の表示を保持します。複雑すぎる図・構造・参照展開には表示上の制限があります。JSONの保存契約自体を変更する制限ではありません。

端末ファイルとして開いたViewerからHTTPSを読む場合、取得先には`Origin: null`を許可するCORS設定が必要です。ブラウザーやOSの制限を解除して回避する必要はありません。

旧Markdownも同じ「開く」から読めます。JSONの直接編集とJSON→Markdown同期は提供しません。状態遷移と概念モデルはJSONに明示された内容だけを表示します。JSONの正式v1採用は未完了です。

旧候補で保存した配置と手動で動かした座標は、自動で再配置しません。初期配置へ戻す場合は、既存の表示設定から「レイアウトを初期値に戻す」を選んでください。

JSONの作成・更新は[Alderの導入・作成手順](../README.ja.md)へ戻ってPluginに依頼します。保存形式を実装する開発者向け資料は[JSON構造契約](../docs/json-native-contract.ja.md)を参照してください。
