# Object右ドロワーの状態遷移図

Objectの右ドロワーは要素・状態遷移・チェック項目の3タブです。状態遷移の明示宣言がないObjectでは状態遷移タブを無効にします。状態遷移タブにSVG図を表示します。状態は箱、遷移はActivity名の矢印で、通常は実線、例外は破線で示します。作成前・保存不可・未決は保存状態ではありません。未記載の操作は未決です。

図の状態名は日本語に揃え、矢印は既存Activity名と明示された条件を表示します。event列の別名は表示しません。操作IDは折りたたんだ「操作の詳細」で照合します。同じ元・先・Activity・効果・通常/例外区分の操作は一本の線へ条件を併記します。Activity名から業務説明へ移動でき、原文は「原文を見る」から確認できます。

購入申請例の外観・操作は人間レビュー済みです。対応範囲は下記の実験宣言に限定します。完成済みライフサイクルを扱う汎用記法、正式BDへの宣言表の統合、Plugin生成・配布への同期は今回採用しません。自然文の業務意味と宣言表の対応は人間が確認する必要があります。

読み込む宣言はInformation後の `## State Transitions` 内に置くPoC案A相当のメタ情報と表です。[購入申請の隔離fixture](../tools/fixtures/state-transitions/purchase-request.md)を使います。自然文から遷移を補完しません。正式BD、Findings、Check、Skill、本番配信は変更していません。

配置と配線の比較ラフでは、既存の `matrixPlan` と `routeEdge` を直接使います。状態を配置用の順序付き箱、明示された遷移を依存線として渡す表示専用アダプターです。BDのActivity/Object区分や保存データは変更しません。状態一覧の順序は表示ヒントだけに使います。戻り線・到着直線も既存ルーターに従います。図の幅は維持し、右ドロワー内で横スクロールできます。

最新比較ラフは矢印を既存Activity名と明示条件に揃え、event別名を表示に使いません。実線は通常・破線は例外（path宣言）です。短い状態名に合わせて箱を縮め、matrixPlanの階段セルを表示サイズと複数行条件の余白へ投影し、routeEdgeで配線します。保存不可は確定した非保存結果、未決は各経路の設計課題の集約注記で、どちらも保存ステータスではありません。通常のCSV出力先も現宣言では未決であり、不変を推定しません。状態・注記の色と選択時の強調は業務相関図の共通色を使います。非関連の状態・線・説明はグレーアウトせず通常表示です。

Activity名は出発状態ごとに一度だけ見出しとして表示します。複数経路がある場合は「通常」と例外名の箇条書きを添えます。例外名はBDのException内の名前を宣言表のexception列から完全一致で参照します。条件全文・IDは操作詳細に残します。名前を持たない旧宣言は「例外名未定義」と表示し、説明文や旧event列から補完しません。

状態シェイプはクリック・Enter・Spaceで選択し、Escapeで選択を解除できます。隣接状態・線・キャプションを強調します。graph-focus.tsの隣接判定/強調クラス、graph-visuals.tsの矢印とLucideアイコン解決、共有CSS色変数を業務相関図と共用します。操作によって業務相関図の選択・配線は変更しません。Objectのチェック項目は既存Check表示を使い、Object対応Checkの解釈や生成は追加しません。

Activityの右ドロワーはグラフと同じWhoの丸付き人アイコン、Scope、基本・手順と結果・課題の3タブです。初期表示は手順と結果。基本はWhy/When（Exception When含む）/Who/Where、手順と結果はHow/Resultを明示見出しで区切って表示します。課題は既存Findings/ProblemとCheck表示を使用します。状態遷移図の共有Activity見出しは関連経路があれば強調し、箇条書きの各行は対応する遷移だけで強調を判定します。別の状態へ向かう兄弟経路の名前へ強調を広げません。

## 対応する実験宣言

`state-meta` は object / states / start / terminal / completeness / source の6項目です。開始は `@new`、終端は `@unknown`、網羅性は `partial` を明示します。確定した終端や `complete` を渡すとエラーを表示し、対応済みのように描きません。

表の基本9列は id / from / activity / condition / to / effect / path / evidence / note です。名前付き例外は activity の次へ exception 列を追加します（通常は `-`、例外はBDの名前）。旧event列を持つ10列形式も読み込めますが、event別名を表示名に使いません。9列・旧event列形式で例外名がなければ「例外名未定義」と表示します。名前付き例外形式の例外は、該当ActivityのException定義へ完全一致で参照できる必要があります。通常を含むすべてのActivity参照は、実在するActivityに限ります。

| effect | 明示する境界 |
| --- | --- |
| change | 登録済み状態へ移り、変更前と変更後が異なる |
| unchanged | 変更前と変更後が同じ。自然文の沈黙から補わない |
| no-create | `@new` → `@none`。保存状態を作らない処理結果 |
| constraint | 遷移先は `@unknown`。保存状態は未決 |

購入申請のT07/T08/T10/T11（破棄・再申請不成立）とT12（CSV出力）はconstraintのままです。CSV出力を承認済みへの自己ループや購入済みへの遷移へ置き換えません。未記載の操作も禁止や状態不変へ補完しません。

現在の図・操作は `test-state-transitions.mjs` / `test-state-transitions-dom.mjs` / ブラウザーのstateTransitions群で確認します。一般化していない記法や自然文の自動意味検証を、これらのテストで保証するものではありません。
