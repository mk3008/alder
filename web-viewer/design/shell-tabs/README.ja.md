# Viewerのシェルとナビゲーション

2026-10-24の本人による構成変更を反映し、左を全体共通のエクスプローラー、中央を一段のタブとする。以前の[シェル画像](shell-reference.png)の二層タブ・領域別左ドロワーは旧案。新たな画像は作らず、操作可能な試作で配置を確認する。

## 左のナビゲーション

[Torrone MENU-001](https://github.com/mk3008/torrone/blob/main/catalog/menus/one-level/README.md)の親開閉矢印、子の字下げ、選択行の背景・先頭アクセントを採用する。確認したカタログ文書のblobは `eec672a678ae4bcaf396aa9630fbfc5083508edc`。親ラベルは通常の太さで左に置き、右端にLucideのChevronRight／ChevronDown（線幅1.5px）を置く。開閉で右向き／下向きを切り替え、左側の文字記号は使わない。アイコン形状は自作せず、カタログの配置・向き・線幅に合わせる。参照したparent-closed.svg blob `6f73c660614eb72d3e405a8b203e1a804375db38`、parent-open.svg blob `9b0596493fae796b9c68a219e7a0ec521dad703d`と両PNGを確認。配色はViewerを維持する。カタログの静止画像は検索やルーティングの仕様ではない。

「業務設計」は全体図とActivity、「状態遷移」は宣言済みの対象、「業務データ構造」は全体図と明示済みの概念を並べる。まず分類と子の二段とし、架空の業務領域階層を増やさない。複数分類を同時展開できる。横断検索は一致する子と親を残し、一時展開する。解除時は元の展開状態に戻り、図と開いているタブは変えない。左の開閉・検索・展開はタブ間で共通。

個別項目の目隠し操作とActivity/Object/ロールの一覧切り替えは主ナビゲーションから廃止。既存の指摘はグラフのバッジから開ける。指摘の閲覧経路を新メニューへ統合し直す作業と、旧個別非表示の保存状態の扱い、旧UIに依存する回帰テストの移管は、構成レビュー後の本実装で仕上げる。図のツールバーの一括フィルタは維持する。

## 中央と右

上位の「業務グラフ／業務データ構造」タブを廃止し、開いた業務、状態遷移、概念を中央の一段のタブへ並べる。同じ対象は既存タブへ移動。業務の全体図を含め、すべての図のタブを閉じられる。図を閉じても読み込み済みの文書とナビゲーションは保持し、左の一覧から再度開ける。最後のタブを閉じたら中央は空にする。タブは共通の描画関数で、Lucideの種別アイコンと対象名を表示する。種別は業務=青・状態=緑・概念=紫の背景色と上端帯、選択は共通の青い下線で示す。種別名と対象の全文はtitle/aria-labelに保持する。長い対象名は一行で省略し、titleとアクセシブル名には種別と全文を残す。閉じるボタンは共通のLucide Xを使用し、32×44pxの領域の縦横中央へ14pxのSVGを置く。概念のシェイプ本体を選ぶと、選択を強調して右ドロワーに概念名・説明・持つ情報・作成業務を表示する。選択だけでは新しいタブへ移動しない。シェイプ右端のLucide SquareArrowOutUpRightは、対象概念と直接隣接する概念だけの図を別タブで開く。参照線も含む明示された関係の一段だけを使い、隣接先からさらに展開しない。全体図・各隣接図はそれぞれのカメラと配置を保持する。右ドロワーの情報は各図で最後に選択したシェイプに対応する。状態遷移は既存の宣言用レンダラーを中央で使い、未定義の状態や遷移を補作しない。

[採用済みタブ画像](tab-baseline.jpg)の選択背景、下線、境界を維持する。[旧一覧](drawer-before.jpg)は余白の問題例であり、実装目標ではない。行は40px、粗いポインターでは44px以上、検索周囲8pxとする。

業務データ構造は正式JSONの新種別ではない。現在の文書に定義がない場合は未定義と表示し、本人が「購買の表示例を開く」を選ぶか、確認URLに `conceptFixture=purchase` がある場合だけ既存の購買fixtureを描く。別文書を開くと例を解除する。文章からの構造推論は行わない。

概念図はPR #293の固定版 `f885d391bde2255a10c1d29d2c949ba74eeb1fdf` をiframe内の隔離した表示例として流用する。階段配置・独立した口と両端件数・灰色・下→右配線・ドラッグ／パン／ズームを維持。選択した概念IDだけを同一originの親シェルへ渡す。public/concept-previewはこの表示例であり、製品の共通conceptModel契約や共通canvas化を実装したものではない。

[4分類の草案](../../../work/concept-review/issue-133/README.ja.md)に沿って、入口は「購買業務の全体像」とする。4分類の単一レビュー責任ロール候補・主Activity・受け渡しを確認し、分類を開くとその範囲の業務データ構造を表示する。6概念を一度に表示する図は「全データ（参考関連図）」として補助入口に残す。分類内では使う情報も対象版に基づいて展開し、その後のレイアウト・配線・カメラ・選択は既存描画を共用する。分類内の右ドロワーも同じ情報範囲を用い、情報の出所・対象時点と生成/確定するActivityを表示する。選択時にドロワーを自動で開かない。説明は自由文の草案であり、正式JSONの説明規約は未確定。作成業務リンクも既存の明示対応だけを使い、対応する5 Activity名を持つ業務設計書が開かれている場合だけそのIDへ移動する。この一致判定は試作の対応確認であり、正式なBD・概念対応契約ではない。


## キャンバスの操作バー

2026-10-24の追加指定で、業務データ構造も業務グラフと同じ右下のフローティングバーへ統一する。[業務側の基準](business-toolbar-target.jpg)、[概念側の修正前](concept-toolbar-before.jpg)、[変更見本](toolbar-reference-v2.png)。変更見本は選択画像をimagegenで編集した外観参考であり、図のラベルやデータ構造の正本ではない。

設定、配置ロック、縮小、倍率、拡大の順。アイコンは同じLucide定義、外観は共通CSSを使う。概念の設定には、その図のレイアウト初期化だけを置き、Activity用の線フィルターは出さない。倍率は25〜250%、ボタン操作は1.2倍／逆数。上端の文字ボタン列は廃止し、図に上端44pxの予約領域を残さない。

## 場面別データ例

各分類の「構造図／データ例」で切り替える。データ例はメイン領域に表示し、場面を選ぶと図のカードに対応した具体値を表で確認できる。架空データ・独立した場面であることを明示し、業務規則や保存方式を追加確定しない。例の状態は `dataExample` URLパラメータで復元する。構造図のiframeとカメラを保持し、例から戻ったときは既存ドロワーの開閉記憶を復元する。

## 概要の表示

分類名と全体像へ戻る入口の下に「概要／構造図／データ例」を置く。目的・構造要件の説明・レビュー責任ロールと範囲は概要本文で読み、構造図/データ例の上には重複しない。概要は `dataView=overview` で復元し、最後のデータ例や構造図のカメラ・drawer記憶を保持する。
