# 既存Viewerで構造を比較する

業務の手順・担当・結果・入出力を項目に分けたD2案を、従来のViewerで確認できます。通常Viewerと同じヘッダー、エクスプローラー、タブ、カード・配線、ズーム、右詳細を使います。未採用の構造を読む確認版で、正式な保存形式は変更しません。

`d2.html`を開いて図のActivityを選び、右詳細の「0.4表現」「D2構造案」を切り替えます。同じ欄で、Procedureは番号付き手順、ResultとI/Oは独立項目、担当・適用条件・順序は補足として読めます。別ActivityのStep参照は、従来の詳細タブを開いて該当Stepへ移動します。右詳細の「例」で五つの限定例を切り替えます。例の選択と0.4/D2切替は検証専用で、正式採用時には表示しません。

投球後は記録と立直しのStepだけが入替可能です。二Activity全体・別の実投・次の投球を交換する意味ではありません。Resultは成立条件付きの定義を表示し、自然文条件を自動判定しません。担当未確認と外部業務をそのまま保持します。複数Roleを持つ場合は担当欄へ全件を示し、既存の単色Roleバッジで主担当を新たに推定しません。

比較JSONは`public/d2-examples.json`です。0.4側は同じ焦点情報を現行形式で表した比較草案で、研究原典全体の移行ではありません。架空例は名前に明示しています。D2モードのGraphは候補JSONから直接投影し、0.4側のGraphを流用しません。

`?source=<匿名取得できるHTTPSの比較JSON>&case=molkkyCross&mode=d2`で固定入力を指定できます。この入口だけで研究形式を検査し、既存の共通表示モデルへ投影します。投影値は保存packageではなく、元の候補構造から詳細を導出します。文書・表示状態をIndexedDBへ読み書きせず、通常Viewerの文書を変更しません。エクスプローラーの開閉等の一時設定は、このページのsessionStorageを使います。

Step IDと順序検証の規則は内部に保持し、通常表示には出しません。入力・出力は情報名、受取元／渡す相手と独立項目で表示します。投球のInputは凍結原典の関係IDを保持して復元しています。

## 検証と範囲

`npm run test:d2`は既存D2-01〜06と、`verification/d2-viewer-ui.check-items.json`のD2-UI-01〜04を、実際のmainを起動するDOM結合検証で照合します。構造・参照の異常系、候補だけの変更がGraphへ出ること、既存操作、通常入口の0.4読込、IndexedDB非接触を確認します。Chrome検証は同じCIで通常Viewerとの比較画像、切替・Step移動・担当・条件・配色・393pxを記録します。自動検証は人間の意味レビューや可読性の採否を代替しません。
