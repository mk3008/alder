# 構造比較の確認版

業務の手順・担当・結果・入出力を項目に分ける案を、同じ情報の0.4表現と切り替えて確認できます。読み取り専用で、構造案は未採用です。通常ViewerやPluginの保存形式は変更しません。

`d2.html`を開き、「投球後」「受付」「写真」「集計」「試合開始」を選びます。「0.4表現」と「D2構造案」で表示を切り替え、図や一覧で同じActivityを選んでください。横断手順の所属先を押すと、元のActivityのStepへ移動します。

確認する違いは、次の5点です。

- 投球後：記録と立直しのStepだけが入替可能で、二つのActivity全体や次の投球を交換する意味になっていないか。
- 受付：入力・確認・案内を、人とシステムのどちらが行うか追えるか。
- 写真：写真がある場合にも保存は任意であり、写真を撮る義務を足していないか。
- 集計：Objectが持つ同じ受付件数を二つの後続業務が利用できるか。
- 試合開始：正常結果の成立条件、開始しない処理、担当や案内方法の未確認を区別できるか。

Resultは成立条件付きの定義を表示します。Viewerは自然文条件を判定せず、表示された全項目が今成立しているとは扱いません。未決の担当と外部業務もそのまま表示します。

比較JSONは`public/d2-examples.json`です。モルックは二つのActivityに絞った焦点例で、研究原典の全件移行ではありません。その他の例は明示した架空の前提による構造比較です。0.4側は同じ候補情報を現行形式で表した比較用草案で、過去の研究版そのものではありません。

`?source=<匿名取得できるHTTPSの比較JSON>&case=molkkyCross&mode=d2`で固定入力を指定できます。研究用の`alder-structure-preview`とD2候補だけをこのページの境界で検査し、本番の`alder-document-package`へ変換・保存しません。正式なJSON入口は従来の契約のままです。画面の状態を既存ViewerのIndexedDBやlocalStorageへ保存しません。

型付きの入力・ID/所有者・局所/横断順序の検査と、人間の理解・業務上の妥当性は別です。画面を操作して、具体的にどこを訂正できるか確認した後に採否を判断します。

## 開発時の検証

`npm run test:d2`で`verification/d2-preview.check-items.json`の6項目をDOM/参照検査へ対応付けます。候補例の変更に合わせて期待を弱めず、旧版とD2の要素・接続、Step移動、担当、条件、情報参照を照合します。`npm run build`と既存の最終CIも維持します。

既存のChrome全体検証と同じCIで`web/test-d2-preview-browser.mjs`がこの確認版を操作し、Before/After・担当・条件・配色・393pxの画像を既存の`json-document-HEAD`artifactへ保存します。自動検証は人間の可読性・訂正容易性の採否を代替しません。

この差分はPR #301の固定head `650632167c1a61bb0b8614431d08f8d1ecbfb690` からの独立Previewです。#301の既存branchや、本番トップページ/配布Plugin/正式Schemaは変更せず、公開確認版は既存のものと別の固定パスに置きます。mainへ単独で先行統合しません。
