# Experiment 2: external delivery provider boundary

Authorized by [PR #46 comment](https://github.com/mk3008/alder/pull/46#issuecomment-5643502093). This separate addition supersedes the first experiment's historical stop instruction, not its evidence or conclusions. First-experiment directories remain byte-for-byte frozen at `fb2bded27f58711187c552b29a0e9baf26b3e643`.

One small delivery-booking fixture, four fresh arms, S0 plus one boundary-crossing change S1. A receives current requirements only; B also receives one concrete provider-expansion concern; C receives VSA; D receives Clean Architecture. No prescribed tree, interface, or forced absence of architecture. Same requested `gpt-6-astra` / `low`, `fork_turns=none`; only S0 is delivered initially. Continue each same agent only after all S0 sources pass and are frozen. Isolation is instructional on a shared filesystem, not OS-enforced.

S0 books and cancels shipments over actual loopback HTTP to one evaluator-controlled provider. The fixture is new because modifying the first memory-only fixture would leak future information and add unrelated workflow code. Reuse its Node built-in test/check, snapshot, diff and line-measurement infrastructure. No live vendor, package, credential or paid service is required.

S1 adds a second provider with different request/response shapes, authentication, cancellation verb and business rejection semantics. New bookings select a provider; cancellations must route using the original booking even after later bookings use a different provider. Both book and cancel cross the I/O boundary. Failed bookings/cancellations preserve local state, and valid existing behavior must continue. No retries, distributed atomicity, persistence, authentication of end users, concurrent commands or uncertain-outcome recovery is claimed.

Freeze exact prompts and cumulative gates before dispatch. B receives only: “The business owner expects additional delivery providers with different API contracts to be added. The provider and timing are not decided.” It does not receive S1 details. A/C/D do not receive this concern. B versus C/D therefore compares instruction packages, not style independent of information.

Before comparing costs, all common functional and failure gates, syntax checks, and optional agent tests must pass. Review C/D structure against feature locality/dependency direction, not file count. At most two correction rounds per arm/stage; preserve all check logs and disclose failures. Never repair an arm as evaluator or weaken tests to force a pass.

Prespecified measurements: physical production added+deleted lines (initial creation included), blank/standalone-comment-excluded sensitivity, production changed/new/deleted files, separate optional-test churn and failed check counts. Use the first experiment's exact difflib algorithm. Export every hunk and classify R (requirement), M (boundary maintenance), D (restructuring existing behavior), X (inseparable/uncertain), with rationale; S0 is X because incremental structure cost is not identifiable. Record concrete extraction/routing/adapter changes; do not label all infrastructure as overhead. Show X sensitivity. These are source-change proxies, not labor, comprehension, monetary cost, or causal estimates. A positive S0 proxy deficit is recovered only if cumulative cost crosses A after S1; lower S1 cost alone is insufficient.

Retain all prompts, requested runner settings and returned IDs, reports, source hashes, raw checks, evaluator replays, diffs, aggregation tools and a frozen first-experiment manifest. Effective backend settings, seeds, tokens, cost and evaluator runtime identity remain unknown absent tool attestation. One fixture and one realization per arm; no statistics, extra language/model/seed, or further stage chosen after seeing results. H4 (missed foresight) is not tested here. Report this result separately, then a new synthesis for Issue #45 without editing the first result.
