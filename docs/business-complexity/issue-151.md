# 業務間の複雑さを実例から定義する

[Execution Issue #151](https://github.com/mk3008/alder/issues/151) · [固定した比較条件](../../work/business-complexity/issue-151/PROTOCOL.md)

## 定義案

**業務の複雑さとは、目的に必要な判断・状態・例外を扱いながら、複数の仕事の情報・順序・準備状態・責任を整合させて、一つの結果を成立させる難しさである。**

複数業務では、個々の作業が簡単でも、前の仕事が終わらないと次へ進めない、必要情報が担当変更で失われる、変更を複数箇所へ反映する、責任移管の成立が分からない、といった接続の難しさが全体を複雑にする。ここを単一作業の手数へ還元しない。

この定義は以下の事例を踏まえた研究上の提案であり、検証済みの尺度や採用済みAlder規則ではない。

| 区別 | 問うもの | 混同しないもの |
| --- | --- | --- |
| 仕事そのものの難しさ | 専門判断、不確実性、守るべき状態・例外が目的上どれだけ必要か | 難しい仕事を「無駄」と呼ぶこと |
| 規則を表す方法の複雑さ | 区分ごとの式・手順に共通関係があるか、差はパラメータか本質的意味か | 式が長いだけで同一視すること |
| 業務間調整の複雑さ | 依存する仕事を、役割・時刻・情報・資源の境界を越えてどう成立させるか | 担当者や工程の数そのもの |
| 過度な複雑さ | 必要な目的・保証に対して、避けられる整合・判断・待ち・復旧負担を負っていないか | 遅い・忙しいという結果だけから原因を決めること |

「過度」は絶対的な工程数で決められない。同じ目的・保証・許容リスクを満たす実行可能な構成と比べて負担を減らせる、または保証への寄与を確かめたうえで避けられる負担だと示せる、という根拠が要る。説明が見つからないだけでは不要と断定できない。損失の観測だけでは、人員不足・需要変動・装置制約との区別はつかない。代替の成立性が不明なら「過度と疑う理由」と「確かめる事実」を返す。

必要な職務分離、安全確認、専門性、説明責任は、費用を伴っても残す意味がある。保証を落とした短縮を、同じ条件の単純化とは数えない。目的や保証そのものをやめる方がよい場合もあるが、その価値判断は同じ保証を保つ比較と区別して人間へ返す。

## 実例の対照

### Iowa州の大気許可

23工程・18受渡しだった処理を7工程・4受渡しへ整理し、配置変更と滞留処理チームも導入。標準許可の平均発行期間は62日から6日へ、約600件の滞留は最初の3か月で半減した。**受渡しと滞留を含む全体を変えた例**であり、個々の審査を速めただけではない。

州関係者とEPAの共同報告。環境基準を維持したとの実施側説明だが、測定標本・各平均の集計期間は不明。追加人員配置等を含むため受渡し削減単独の因果効果は分離できない。全工程の役割別図、実作業時間と待ちの内訳、環境成果の独立評価はない。[EPA報告、印刷頁1・33〜36](https://www.epa.gov/sites/production/files/2013-11/documents/leangovtprimer.pdf)

### Michigan州の大気許可

申請者と審査側の接続を、必要情報の共通化、事前協議、条件案の早期共有、双方の中間期限、進捗管理で整えた。報告値は大規模許可422日から98日、小規模143日から50日、申請時の事務的完全性82%から95%。**役割を統合せず、受け手が仕事を始められる条件を改善した例**である。

EPAによる実施報告であり、無作為比較ではない。多数の同時変更、測定件数・期間不明という限界があり、「事前協議だけで短縮」とは言えない。全ての遅延が情報不備によるとの証明でもない。[EPAのMichigan事例](https://19january2017snapshot.epa.gov/lean/michigan-department-environmental-quality-lean-process-improvement-initiative_.html)

### Washington州の聴聞資料準備

資料受領から画像化への受渡しに、職員の対応可能状況による待ちがあった。聴聞担当自身による画像化、相互訓練、資料整理を導入し、43工程から14工程、cycle time 604分から300分と報告。**準備作業の担当境界を変えて、受渡し先の空きを待つ依存を減らした例**である。

州の2014年1〜5月報告、頁57。年間約900件は規模であって標本数ではない。cycle timeに含む待ちの範囲、全工程順、画像化側の正式部署、裁定品質は不明。公式PDFの直接取得は不安定で、公式検索索引と別保管版の索引にある同頁の内容を照合した。全PDFの同一性をバイナリ検証したとはしない。[公式報告URL](https://www.results.wa.gov/sites/default/files/Lean_report_to_legislature_07_01_2014.pdf) / [同報告の別保管先](https://wabusinessalliance.org/wp-content/uploads/attachments/Lean_report_to_legislature_07_01_2014.pdf)

### 手術室から集中治療室への引継ぎ

複数の専門職が装置と情報を渡す際、指揮・配分・順序がばらつき、会話が競合していた。職種を減らさず、調整責任、段階的な移管、まとまった情報伝達と共同確認を整えた。前23件・後27件で技術的エラーは平均5.42件から3.15件へ。**同時に行うべきことと順番を守ることを整理し、境界の成立条件を明確にした例**である。

単施設・非無作為の前後研究。情報欠落は2.09から1.07へ減ったが回帰分析の独立効果は有意でなく、10.8分から9.4分という時間差も有意ではない。死亡等の臨床転帰や、役割数削減の効果は検証していない。本記録は組織の引継ぎの分析であり、治療助言ではない。[Catchpoleほか、2007、Table 1〜4](https://onlinelibrary.wiley.com/doi/10.1111/j.1460-9592.2006.02239.x)

### I-PASSの交代勤務引継ぎ

病棟の担当交代を残し、口頭・書面の情報構造、受け手の理解確認、訓練・観察をまとめて導入。9病院10,740入院で医療エラーは24.5から18.8件／100入院、予防可能な有害事象は4.7から3.3件へ。口頭引継ぎ時間2.4から2.5分／患者に有意差なし。**境界を消す代わりに情報の再構成と確認を助けた例**である。

査読済み多施設前後研究だが無作為化なし。複合介入のため、情報様式だけの効果は分からない。患者数を引継ぎ件数と混同しない。待ち・手戻りの短縮の直接証拠としては使わない。[Starmerほか、2014、著者抄録](https://pubmed.ncbi.nlm.nih.gov/25372088/) / [原著](https://www.nejm.org/doi/full/10.1056/NEJMsa1405556)

## 非同期が有益な対照

GitLabの公開運用方針は、文書やIssueによる非同期連絡を、時差と同時在席への依存を減らす手段とする。一方、文脈を言語化しきれない調整や合意では、長い往復より同期的な会話が適する場合も挙げる。これは組織自身の運用記述であり、改善前後の効果測定ではない。[GitLab Communication、Asynchronous communication節](https://handbook.gitlab.com/handbook/communication/#asynchronous-communication)

したがって、問題は非同期そのものではない。後工程が待つ必要のない仕事なら分離が有益である。順序依存が強いのに、必要情報・完了条件・応答時限・責任が曖昧なまま分離すると、往復と滞留が増え得る。逆に全部を同期化すると、全員の同時在席を待つ新しい依存ができる。これは事例と運用記述からの推論であり、一律の同期化を推奨しない。

## 現場で確かめる問い

1. 一件が始まってから必要な結果が成立するまで、どの仕事が何の完了を待つか。順序は本当に必要か、慣習か。
2. 待っているのは情報、判断権、専門性、資源、それとも担当者の空きか。実作業と待ち・再確認・復旧の時間を分けられるか。
3. 担当が替わった直後、前の担当が知っていた何を再収集・再解釈するか。受け渡すべき意味と実際に渡る記録に差があるか。
4. 完了・受領・責任移管の条件は双方で同じか。未完了や例外は誰が持ち、次の人はそれをどう知るか。
5. その境界・確認・分岐は、どの目的や保証を守るか。減らす、まとめる、順番を変える、情報を保つ方法で同じ保証を維持できるか。
6. 判断や情報を一箇所へ集めた場合、負担の移転、新しいボトルネック、不在時の弱さ、牽制喪失はないか。
7. 需要の量・変動、許容時間、担当者の技能・権限の下で、例外を含めて安定して回るか。成立しない原因は複雑性か、容量や資源の不足か。
8. 区分ごとの計算・手順の違いは、共通の関係を別々に書いているだけか、目的・単位・制約・例外が本質的に違うか。共通化できる部分と残す差を説明できるか。

8は規則表現についての未検証の探索観点である。本研究の業務間受渡し事例・比較試行から、式の意味を保つ汎化能力を実証したとはしない。具体式・単位・境界条件・反例がなければ、式の見た目だけで共通化しない。

## 既存Skillの限定比較

[2事例・6条件の結果](../../work/business-complexity/issue-151/RESULT.md)では、両Discoveryが依存関係を質問した。医療引継ぎは最小入力から実例の中核方向へ到達したが、行政資料準備は背景追加後も画像化担当をまとめる中核へ届かなかった。工程数・総時間の追加と、境界を変えられる権限・能力等のcontextは同じではない。[独立評価](https://github.com/mk3008/alder/issues/151#issuecomment-5990384511)では、行政入力が原資料の「不要な受渡し」という診断を省く一方、医療入力は診断的手掛かりを保持する非対称を確認した。行政出力には、未知を理由に統合を探らず委譲は条件付きで提案する非対称と、現状の受渡しを保つ意味に含める兆候もあり、未到達を情報不足だけで説明できない。単回比較・再構成入力・既知事例の影響があり、一般的な汎化能力やcontextの因果効果は証明していない。定義案とこの限定結果を先にレビューし、guidance変更はまだ決めない。
