# Alder 0.4.8 — 業務設計レビューとCheck Itemの改善

0.4.6からの主な変更点です。

## 追加

- **業務設計書の確認事項・修正指摘（任意）**：Business Designの`# Findings`に、未決の質問（要確認）や根拠のある修正指摘（要修正）、関連するActivity／Object、対応状況を記録できるようにしました。既存の業務設計書に追加する必要はありません。
- **Check Itemの業務名照合**：対応するMarkdown書式では、業務設計書のActivity名とCheck Itemの索引・見出しを照合する読み取り専用の診断を追加しました。

## 変更

- **業務設計書の草案作成**：草案を作った後に既存の品質レビュースキルで点検し、原資料で裏付けられる問題を修正して再レビューする手順にしました。情報不足や解釈が未確定の事項は質問・保留として返し、確認できなかった内容を合格扱いにしません。
- **Check Itemの作成・更新**：共通する条件と期待結果をActivity内に一度だけ示し、各Check IDから参照できるようにしました。入力・条件・期待結果の違いを比べる表や短い具体例を使い分け、同じ説明の繰り返しを減らします。数式や「操作」欄は一律必須にしません。既存のID、人間レビュー状態、未決事項、根拠、Test証拠の対応は保持します。
- **Check Itemの整合性レビュー**：作成・更新後にBusiness Designと照合する読み取り専用レビュー工程を設け、保証の欠落・重複、参照の不一致、具体例から何が違って見えるかを確認します。根拠のある指摘は作成側で修正し、保存後に再確認します。

## 削除

- 削除したSkillや機能はありません。

## 互換性・利用上の注意

既存のBusiness Graph JSON v1と`parse_design`のGraph出力は変更しません。`# Findings`を含む情報はPythonの`parse_document`で取得できますが、通常のGraph JSON出力には含まれません。既存のCheck Itemを新しい表示書式へ一括変換するものではありません。

レビューはAIによる支援であり、業務上の期待結果や未決事項の最終判断・承認は利用者が行います。既存インストールは自動更新されません。
