# Alder 0.4.8

業務設計レビューとCheck Itemの改善をしました。
0.4.6からの主な変更点は以下のとおりです。

## 追加

- **Check Itemにサンプル（テストパターン）を追加**：業務上の入力・条件と期待結果を、具体例で確認できるようにしました。条件の成立・不成立、日付などの境界、説明内容や相手の違いを見比べるときは比較表を使い、表に向かない場面は短いシナリオで示します。サンプルは人間が期待結果を合意するためのもので、自動テストそのものや一般保証の代わりではありません。
- **業務設計書の確認事項・修正指摘（任意）**：Business Designの`# Findings`に、未決の質問（要確認）や根拠のある修正指摘（要修正）、関連するActivity／Object、対応状況を記録できるようにしました。既存の業務設計書への追加は任意です。
- **Check Itemの業務名照合**：対応するMarkdown書式では、業務設計書のActivity名とCheck Itemの索引・見出しを照合する読み取り専用の診断を追加しました。

## 変更

- **Check Itemを業務別に確認しやすく**：Activityごとの一覧から各Checkへ移動でき、業務条件・期待結果・人間レビュー状態を確認しやすくしました。AND／ORや組合せ条件を区別し、未決の業務判断を勝手に確定しません。
- **Check Itemの記述を簡潔に**：共通する条件・業務行為・一般的な期待結果はActivity内に一度だけ示し、個別Checkから参照します。式や「操作」欄は一律必須にしません。既存のID、人間レビュー状態、未決事項、根拠、Test証拠の対応を維持して更新します。
- **Check Itemの整合性レビュー**：作成・更新後にBusiness Designとの整合性を読み取り専用で確認し、保証の欠落・重複、参照の不一致、サンプルから観察できる違いを点検します。根拠のある問題は修正し、修正後に再確認します。
- **業務設計書の草案作成**：草案を既存の品質レビュースキルで点検し、原資料で裏付けられる問題を修正して再レビューする手順にしました。情報不足や未決事項は質問・保留として残します。

## 互換性・利用上の注意

既存Skillの削除はありません。Business Graph JSON v1の形式と従来のGraph出力は変更していません。`# Findings`はPythonの`parse_document`で取得できますが、Graph JSONには含まれません。既存のCheck Itemを新しい表示書式へ一括移行する機能はありません。

AIによるレビューとサンプルの提示は業務上の承認や自動テストの代わりにはなりません。既存のプラグインは自動更新されません。
