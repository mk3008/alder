# Alder Plugin 0.4.8 候補: 業務設計の指摘と関連先

この版番号は未リリースの作業ブランチ上の仮置きです。配布・インストール可能な版を示しません。この変更はPR217の0.4.7候補（草案と品質レビューの改善ループ）を含みません。採用順と最終版番号はマージ・リリース前に調整が必要です。

## 変更

- 業務設計Markdownの任意のFindings欄で、要確認と要修正の内容・状態・関連先を記述できます。既存のProblem / Pain levelによる業務上の困りごとと区別します。
- ViewerはActivity / Objectのバッジと指摘一覧を表示します。複数項目への関連、文書全体、関連先未設定、参照先不一致を扱い、解消済みは既定で隠します。
- Pythonのparse_documentは図と指摘を返します。既存のparse_designとCLIのJSON出力はGraph v1のままです。CLIは指摘を出力から除外する場合、標準エラーに警告します。

## 互換性と限界

指摘がない既存MarkdownとGraph JSON v1のキーは変更しません。指摘があっても業務上の事実や承認の根拠になるわけではありません。構文、対象名、読み方は[指摘の記述ガイド](design-findings.ja.md)を参照してください。

自動テストは構文、変換、表示の対象範囲を確認します。業務判断の正しさ、AIレビューの網羅性、利用者の操作確認を代替しません。プレビューでの人間の確認と採用判断は別途必要です。
