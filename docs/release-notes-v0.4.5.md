# Alder 0.4.5 — システム要件の実装適合レビュー

## 変更

- 実装レビューで、提供されたSystem Requirements（SR）と関連するプロジェクト制約を、実装・DDL・テスト・取得できる実行証拠と照合する。SRの出典、revision、適用範囲と、実装時に用いた版を固定してレビューへ引き継ぐ。
- SRが未提供または読めない場合は、その制約を未確認として残す。Business DesignとSRの曖昧さ・衝突は、両方の根拠と影響を保持して責任者へ返す。入力の版や適用範囲が変わった場合は、影響部分を再レビューする。
- レビューのフォローアップでもSRの根拠と証拠不足を保持する。SRの指摘をCheck Itemへ変換しない。SRの作成、妥当性・完全性の確認はプロダクト側の責任を維持する。
- 配布するAuthoring、Check Item、レビューのフォローアップ用ガイダンスを現行のSR引き継ぎ手順へ同期する。
- READMEに、少ない成果物で成立する理由、成果物の関係、ドリフト検知、テストによるコード検証と逆引きの説明を追加する。

## 互換性

既存の10 Skills、起動文、書込み境界、Check ID、人間の確認状態を維持する。Business Graph JSONはv1、ドリフト診断の入力・出力形式、review knowledge v0.3は変更しない。0.4.4へ固定した既存のインストールは変更されない。

SRの管理台帳やCheck Item化、Business Design外の要求を別成果物へ自動保存・引き渡す方式は追加しない。業務要件と技術的な実現条件を区別する既存のAuthoring境界を維持する。

## 検証範囲

SR引き継ぎの実装には、固定入力による9件のFresh回帰レビューと独立監査の記録がある。パッケージ、出典・ダイジェスト、リリース手順、Business Graph、ドリフト診断の既存検証を実施する。

これらの検証は、0.4.5の実クライアントでの全起動経路や、未観測の運用上の保証を証明しない。静的コード、テスト成功、設定値だけでSRへの運用適合やSR自体の完全性を保証しない。
