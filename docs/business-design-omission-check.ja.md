# 業務設計書の漏れのチェック

[文書構造へ戻る](business-design-structure.ja.md) · [相関チェック](business-design-correlation-check.ja.md)

業務の流れを整理し、前後のつながりを確認した後、実際のシステムで起こり得るのに扱いが決まっていない条件を探します。必要に応じて行う任意の探索です。すべての例外を列挙する工程ではありません。

## 用意するもの

業務設計書の全文と版、対象範囲、合意済みの判断・共通ルールを渡します。検査項目を作る前、または作成と並行して使えます。実装の現在の動作を、未決ルールの答えとして扱いません。

## 確認する観点

| 観点 | 確かめること |
| --- | --- |
| 機能の性質 | 何を受け取り、読み、変更し、いつ結果が確定するか |
| 具体的な場面 | 通常の一回の実行では見えない条件で、利用者にどんな結果の差が出るか |
| 既決事項 | 文書全体、適用範囲、判断記録や共通ルールに、既に答えがないか |
| 未決の意味 | 既存の規則を満たしたまま、異なる業務上の結果が複数成り立つか |
| 適用性 | 実際の対象業務に関係するか。未提示の環境や新しい業務を仮定していないか |

たとえば、予約は保存できたが利用者が結果を受け取れなかった場面です。予約をどう確認できるかが既存の業務や共通ルールで決まっていれば、その根拠で閉じます。決まっていなければ、人間へ返す問いの候補になります。この場面をすべての製品の必須機能とするわけではありません。

## AIへ依頼するプロンプト

プロダクトのルートから使う例です。山括弧の箇所を対象に合わせて置き換えてください。

```text
../alder/docs/business-design-omission-check.ja.md と
../alder/docs/behavior-derivation/functional-considerations.md に従い、
未記載の機能条件を探索してください。

業務設計書: <対象パスと版>
合意済み判断・共通ルール: <参照先、なければなし>
対象範囲: <対象とする業務>
前提: 業務の成立性と前後の相関は確認済み

文書全体を読み、既に決まった条件を再質問しないでください。
既存記述から導ける期待結果と、外部知識を使って発見した未記載の問いを分けてください。
各候補について、対象機能、具体的な発生場面と結果差、関連する文書箇所、
既存判断では決まらない点、発見に使った知識・推論、選択肢と影響、
未確認の前提を示してください。未承認の候補であることを明記してください。

一般論の一覧や遠い仮説で件数を増やさず、少数の有用な問いに絞ってください。
候補ゼロも認め、閉じた論点は理由を短く残してください。
網羅性は主張せず、今回調べた範囲を報告してください。
ファイルを変更せず、候補を要件やテストの期待結果として確定しないでください。
```

## 結果の扱い

AIが外部知識から作るのは問いであり、業務上の答えではありません。人間が意味や保証を決めたら、まず業務設計書を更新・確認し、その確定版から検査項目とテストへつなげます。日常的な可逆の技術選択まで業務上の確認として戻す必要はありません。

詳細な探索・分類・停止の基準は[考慮漏れ検証](behavior-derivation/functional-considerations.md)、確定した設計からの期待結果の導出は[検査項目の作成・保守](check-item-traceability.md)を参照してください。
