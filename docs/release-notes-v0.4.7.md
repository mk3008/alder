# Alder 0.4.7 — 業務ごとのCheck確認と条件の表記

## 変更

- 業務一覧から確認するActivityを選び、そのCheckの条件・期待結果・人間確認状態を一度だけ提示する。表と末尾の詳細で同じ内容を繰り返さず、根拠・導出区分・AI confidence・Test証拠や不足は同じIDから参照する。
- 複数業務に関係するCheckは同じIDと確認状態への参照を共有する。未接続項目を推測で業務へ割り当てず、業務移動や再開位置を承認として扱わない。
- 明示的なANDは「すべて満たす」の箇条書き、ORは「いずれか」のまとまりで示す。混在する条件のグループ、境界、否定、例外、排他性、優先順位を保つ。不明な論理は原文を残し、確認事項として返す。

## 互換性

Business Designの権威、Checkの意味・ID・人間確認状態、BD↔Check↔Testの関係は変更しない。既存の10 Skillsと書込み境界を維持し、必須スキーマ、専用Viewer、追加台帳は導入しない。Business Graph JSON v1、ドリフト診断の形式、review knowledge v0.3、過去の研究資料は変更しない。

配布済みのタグとパッケージは不変。branch上の版番号はパッケージ内容を識別するもので、公開済みの意味ではない。利用する版の公開は[GitHub Releases](https://github.com/mk3008/alder/releases)で確認する。

## 検証範囲と限界

代表的なAND・OR・混在・未確定条件、Shared ID、未接続、再開を使う静的回帰と、既存のパッケージ・出典・配布検証で整合性を確認する。これらは例示と配布物の契約を検査するもので、エージェントが常に期待どおり出力することや、実クライアントの挙動を保証しない。

人間の理解度・レビュー時間・合意精度の改善は未実測。表示変更や検証成功を、人間の業務判断・採否・Checkの承認に置き換えない。
