# Alder 0.4.7 — 草案の品質レビューと再改稿

## 変更

草案作成の自己点検後、独立した工程として既存の読み取り専用レビューを行い、原資料に基づく修正を草案へ戻して再レビューする手順を追加する。原資料にある取りこぼしは修復し、情報不足は具体的な質問、曖昧な解釈は未採用候補として残す。

同じ指摘が改善なく残る場合、レビューを実行できない場合、実行上限に達した場合は反復を止める。実際に確認した版・範囲と未確認の変更を区別し、未実施・失敗を「問題なし」と報告しない。業務上の合意は人間が行う。

## 互換性と限界

既存の10 Skillsと読み取り・書込み境界を維持する。新しい必須成果物、指摘分類のスキーマ、Graph形式、Viewer変更は追加しない。草案作成の指示に基づく調整であり、決定的なワークフローエンジンではない。

配布内容・参照・停止条件の静的検査と合成シナリオの契約は、実クライアントでのループ実行や意味検出能力の実証ではない。別担当または新しいコンテキストを使える場合は活用する。同じ担当がレビューSkill全体を別工程として適用した場合は、独立レビューではないと明示する。レビューそのものを実行できない場合は、レビュー未実施を明示した草案を返す。

このブランチの版は公開済みリリースを意味しない。タグ・release・インストール更新は別途承認後に行う。既存の公開タグとその成果は変更しない。
