# Alder 0.4.11 — 複数の業務案とレビュー指摘の扱い

Alder Pluginで、現行案や改善案など複数の業務案を一つのJSONにまとめ、案を指定して確認・更新できるようにしました。各案は独立して管理し、元の単一JSONも保持します。

## 追加

### 複数の業務案の作成と更新

既存の単一JSONから、名前と安定IDを持つ1件以上の案をまとめたJSONを作成できます。案を指定して取り出し、候補を作ってから更新します。対象以外の案を変更せず、対象案には従来のID・参照・版・人間合意の保存ガードを適用します。対象を一意に特定できない場合は確認を求めます。

### 概念モデルとCheckの具体例

概念モデルを業務設計やCheckと同じJSONに含め、構造と参照を検査できます。概念のデータ例をCheckへ明示的に対応付け、判定用の例と処理結果の例を区別できます。対応先は名前や値の類似から推測せず、業務意味と人間の合意は別途確認します。

### 状態遷移の訂正

不要な状態遷移は、対象ID・理由・根拠の出所を明示して削除できます。申告内容と実際の変更が一致しない場合や、同じ識別元を別のIDに置き換える場合は保存を拒否します。

## 変更

### 草案と単独レビューの指摘分類

草案作成・改稿では、原資料・既決事項・正式書式から修正が一意に定まる誤りだけを修復して再レビューします。正解が未決の不整合は草案の未確認事項と返答へ示し、任意の改善提案は価値のある少数だけチャットへ返します。提案がない場合もあります。未採用案を業務設計やFindingsへ追加しません。

単独の業務設計レビューは、確実な修正も含め常に読み取り専用です。人間の採否回答後、別の明示的な改稿依頼で反映・再レビューします。業務上の合意は人間が行います。

- Checkの条件と具体例について、判断に影響しない条件だけをまとめ、境界・例外・未決を区別する方針を追加しました。対応する業務結果や例外を確認し、未作成と対応未確認を区別します。
- 業務設計のレビューでは、未完了の作業を後から再開すると明記されている場合に、対象の特定から再開・終了までの経路を確認します。
- JSONのレビュー記録更新では、選択したJSONを先に検証し、未対応の形式をAlder正本として更新しないようにしました。
- 状態遷移の同じ出発状態・業務・条件の重複と、未確定ロールに対応する診断の不足を検査します。

## 修正

- 複数案JSONの更新時に、既存ファイルのアクセス権限が変わる問題を修正しました。保存に失敗した場合は元ファイルを保持します。

## 互換性・利用条件

- JSONを直接編集できるのは文書package形式 `0.4` です。旧版は対応する範囲で閲覧でき、直接編集は停止します。別ファイルへの明示的な版変換はソース CLI では実装済み（prepare-version-upgrade）で、配布用同梱 CLI では未反映です。元ファイルを自動変換・上書きしません。
- 従来の単一JSONに複数案用のラッパーは不要です。複数案の各JSONは独立して検査され、案同士の参照はできません。
- 新しい概念文書やCheck参照を知らない旧版の検証器は、それらを含むJSONを受理できません。既存の未接続の例は、意味を変えない別の編集では保持できます。例を追加・変更するときは、Checkへの明示的な対応付けが必要です。
- 複数案の閲覧には対応するViewerが必要です。Pluginを更新しても公開Viewerは自動では切り替わりません。既存の複数案ファイルへ案そのものを追加・改名・削除する専用CLIはありません。
- JSONの操作にはNode.js 24以上が必要です。Markdownからの明示変換にはPython 3.12以上も必要です。構造検証は業務意味や人間の合意を保証しません。
