# 実際のSkill適用候補Cの読者検証

- 記録日: 2026-09-30。C生成中に、読者実行前の条件として保存
- explainer / first-reader scripts: 公開revision `1e393e0b3039a8a38a77d436f387ea58ab48b2fb`
- 内容の一次資料: Alder `90890e1c209af1b7f88f14e64bb27a7a0d2edbee`
- 候補Cと仮personaは読者へ渡す前に公開commitへ固定し、最終実行記録へSHAを追加する
- 予備実験A/Bの出力は著者役・新しい読者役には渡さない
- 親は生成と計測を調整し、読者役にはならない。読者は独立した履歴なしコンテキスト

## 読後の目標

Alderが自分のプロジェクトに必要かを判断し、人間が合意・レビューする内容、AIへ渡す内容、未決の扱い、利用開始の入口を区別できる。

## 配役

両者は架空の読者役であり、実在人物の経歴を推測したpersonaではない。共通の仮personaを保持するため、explainerの実在の一人への個別最適化は未検証。

- K（keen）: AI実装を利用するエンジニア。一般的な要求・設計・テストは知るがAlderは初見。小さな業務へ試すために同僚から紹介されたREADMEを読む。最初の画面で導入目的がつながれば読み進めるが、一般論が続けばskimへ移る。目的は人間が決めることとAIへ渡すものを判断すること
- S（skeptic）: 同じ基礎知識を持つエンジニア。候補ツールのREADMEを比較しており、導入に必要なものと未決仕様の扱いを探す。冒頭の約2段落で目的に結びつかなければ離脱してよい。目的は追加の設計負担に見合うかと、実際の開始手順を判断すること

## 実行

1. skepticalの独立した読者役が `skim.py` の表示だけで、文書の趣旨・全文を読むか・決め手を答える
2. `feed.py serve` の原実装を起動する。K/Sそれぞれに自分専用のREADER_FEED、配役、start/next/quitコマンドのみを渡す。文書パス・実行ディレクトリ・他読者のアドレス・正答は渡さない
3. 原実装の既定dwell `0.08` を維持し、各passageごとに実際のmoment logを記録する。正の反応や完読を強制しない
4. 完読したKと、完読した場合のSについて `recall.py` が出したログとquizだけを新しい読者役へ渡す。文章自体とintended gistは渡さない
5. 完了後に `signals.py` を実行し、親が全文・一次資料との整合を確認する。日本語のsignal数は英語用カウンターの限界付きで扱う
6. 原ログとrecallを保存し、`room.py` で注釈ページを生成する。first-readerが解説文を修正することはない

## 条件と終了

- 全独立読者はAGENTS.mdに従い `gpt-6-sol` / `medium` / `fork_turns:none` を要求。実効runtime設定を独立に証明したとは言わない
- 読者出力・完全プロンプトの安全な抽象化・文書SHA・実行コマンド・逸脱を保存する。公開記録にはローカルfeedの一時tokenを残さない
- 原feed出力から動的なtokenだけを置換したプロンプトを記録する。これは機密を含まない安全な公開再現手順であり、実行時tokenの公開ではない
- recallは読書ログからの再構成であり、実際に翌日まで待った人間の記憶測定ではない
- 予備実験A/Bは通読質問、今回Cはskim/順送り/recallであり、条件差から直接優劣を付けない
- 誤読・離脱・情報不足の有無を根拠付きで整理する。再生成を無制限に繰り返して好ましい結果を作らない
