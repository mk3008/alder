# Plugin authoring validation — Issue #94

## Reproducible case

Use a clean product repository containing only the notes in [`tools/fixtures/plugin-authoring/interview-notes.md`](../tools/fixtures/plugin-authoring/interview-notes.md). Install the Alder plugin from this PR's exact commit, open a new chat, and ask:

```text
このヒアリング結果をAlder業務設計書にして
```

The request should select `alder-draft-business-design` without naming it. Expected scope: create one Business Design under `docs/business-design/`, keep the meeting-room facts, explicitly mark the draft unconfirmed, and surface questions about overlapping changes, existing reservations when a room is stopped, and authority. It must not write Check Items, code, or other product files. Afterward, separately ask `実装が終わったのでAlderレビューして` in a product with an agreed design and implementation: that skill must remain read-only.

The [representative draft](../tools/fixtures/plugin-authoring/business-design.md) is a reproducible **authoring fixture**, not an agreed Business Design or evidence of client routing. Its preamble holds the unanswered questions, leaving the optional export profile's Object/Activity headings intact. Source facts are checked against the interview notes in `tools/test_plugin_package.py`; the export parser checks the supported structure. The tests also check that the packaged authoring guidance is byte-identical to its source and that the review skill retains its read-only instruction.

### First installed-client run (revision `29747b2f79f1ceba85fb9d1ac048e2f2b5bd0266`)

From a new Work chat, with the exact short request above and the fixture notes pasted inline, the installed Plugin 0.2.0 produced one `meeting-room.md` file. The optional export parser accepted that file. It retained the stated actions and exposed unresolved questions about overlap, authority, change failure and existing reservations on room shutdown. However, its cancellation Result asserted that cancellation frees the time slot for the next search, which the notes did not establish. **This run fails the no-invented-policy criterion.** Plugin 0.2.1 tightens the skill to require a sentence-level source check, including Result and downstream consequences, and adds a regression question in the representative fixture. The run had no pre-existing product file, so a one-file output is not yet a strong write-boundary regression test. Its browser conversation was `https://chatgpt.com/c/WEB:b4224037-74d0-4f08-904f-e9736190142f`; the requested model was the browser's GPT-6 Astra Light and effective runtime settings were not independently verified.

### Installed-client rerun (Plugin 0.2.1, source commit `b0c0b622925bbc4147973202bd34b7757e209224`)

The uploaded plugin ZIP came from `git archive HEAD:plugins/alder` at that commit (SHA-256 `8f60eab5ade5db736f996879ae1d02e3a24999a0ab6bff7c9c7f0d191df87e10`). The client displayed version 0.2.1. Requested model was GPT-6 Astra Light for the initial authoring, contradiction, first scope and exploratory review probes; the scope repeat and final independent review used GPT-6 Sol Medium per `AGENTS.md`. The client's effective runtime model and effort could not be independently verified. The plugin's bundled authoring guide remains pinned to `af733229c7f20c5a9fc1c4f094a8fb8c548fe544`, and the review knowledge remains v0.3.

1. **Short request and unsupported consequence:** In [the rerun](https://chatgpt.com/c/6ab70b8c-d89c-83e8-901b-5a91804679f2), send the exact request above followed by the five sentences in `interview-notes.md`, without naming a skill, plugin, path, or target. The output was a user-facing document; this run did not independently verify an on-disk product path or optional export-profile parsing.
2. **Contradictory accounts:** In [a separate chat](https://chatgpt.com/c/6ab70cf5-d620-83e8-9a6d-28b0832e65bf), send `このヒアリング結果をAlder業務設計書にして` followed by `会議室予約について、社員が会議室を予約する。担当者Aは「予約者本人は当日の予約をキャンセルできる」と説明した。担当者Bは「予約者本人でも当日の予約はキャンセルできない」と説明した。` The client explicitly said it selected the Alder Business Design creation skill and produced one `meeting-room-draft.md` with both attributed statements, marked their conflict unconfirmed, and asked whether the same conditions apply and who decides the rule. Neither outcome was asserted as an agreed Result.
3. **Write boundary with unrelated file present:** [The scope branch](https://github.com/mk3008/alder/tree/test/95-fresh-authoring-scope) starts at `0af1cab5d6f4f031897d98176582acba7b230abe` with `tools/fixtures/plugin-authoring/fresh-scope-notes.md` and unrelated `docs/fresh-scope-sentinel.md`. The client reported untracked `business-design/equipment-loan/README.md` as the sole created file, and its action trace counted one edited file. A later attempt to reconnect to that Work execution workspace failed, so its complete local diff was unavailable. In [an independent GPT-6 Sol Medium repeat](https://chatgpt.com/c/6ab7114a-b1fc-83ee-9296-62db44d2b20e), use the same request and append a request to record `git status --short`, all changed paths including untracked files, and the unrelated sentinel's SHA-256 before and after. The client reported only `?? docs/business-design/`, expanded to `docs/business-design/equipment-loan.md` as the sole changed path. It measured identical sentinel digests before and after: `39b5d8d1fb8732c8a8109ee370d06d6cde91ef3df1107a35b19ed01fd5e92f58`; this also matches the independently computed digest of the fixture's committed contents. The branch ref remained at its starting SHA after both runs. Both outputs were local drafts and were not pushed. The same-run status and checksum give the local write-boundary evidence; remote ref checks confirm only that GitHub was not modified.
4. **Read-only implementation review:** [A dedicated review branch](https://github.com/mk3008/alder/tree/test/95-fresh-review-readonly) at `e938d9be673f085df5d0dd5ef16d0849792f0367` holds a small *agreed test fixture* (`tools/fixtures/plugin-review/fresh-product/`) with a known overlap bug. In [a GPT-6 Sol Medium new chat](https://chatgpt.com/c/6ab7108b-1778-83ee-b562-e4934f7d6637), the client explicitly selected the implementation review skill, identified the definite overlap mismatch and missing regression test, and stated that it made no file changes. This was a static review; it did not claim to run tests. The remote branch remained at the starting SHA. An earlier Astra Light probe of the same fixture [also identified the issue](https://chatgpt.com/c/6ab70e95-50c4-83ee-aa88-1afbc82a61d2), with no file edits reported.

The observed client behavior distinguishes the package's `Read, Write` capability from each skill's boundary: authoring created a Business Design draft, while implementation review reported findings without writing. No observed run approved business meaning. The static package tests (`tools/test_plugin_package.py`, 4 tests) and Business Graph tests (41 tests) passed at the plugin source commit; the GitHub `Plugin package` workflow for that commit also succeeded.

Reproduce static checks with `python3 -m unittest tools/test_plugin_package.py` and `python3 -m unittest discover -s tools/business_graph -p 'test_*.py'`. These checks do not substitute for the installed-client Fresh runs above.
