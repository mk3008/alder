# 会議室予約 — 予約受付の記述例

利用者が希望した会議室と時間帯の予約を受け付ける業務の記述例。業務内容は利用先で確認・合意する。この例では予約受付担当者を業務主体とし、人やシステムへの割り当て、画面やDBの設計は定めない。

書き方は[業務設計書の文書構造](../business-design-structure.ja.md)、使い方は[README](../../README.ja.md)を参照。

# Scope

利用者からの予約希望の受付、利用可否と重複の確認、予約の登録、結果の通知を対象とする。空き状況の検索、予約の変更・取消、会議室の利用可否の管理、会議の実施は対象外とする。会議室の利用可否は範囲外の業務が管理する。

# Activity 会議室を予約する

## Scope

true

## Why

会議に必要な時間帯の会議室を確保するため。

## When

利用者から予約希望を受け付けたとき。

## Who

予約受付担当者

## Where

規定なし

## How

### Input

- 利用者 — 対象会議室 / 利用開始・終了日時 / 利用目的 / 予約者
- 会議室台帳 — 会議室の利用可否
- 予約台帳 — 既存予約の時間帯と状態

### Procedure

1. 利用者から対象会議室、利用開始・終了日時、利用目的、予約者を受け取る。
2. 会議室台帳で対象の会議室が利用可能であることを確認し、利用開始が受付時点より後、終了が開始より後であることを確認する。
3. 予約台帳で同じ会議室の有効な予約と時間帯が重ならないことを確認する。ある予約の終了と別の予約の開始が同じ日時なら重複とみなさない。同時の申込みでも、同じ会議室・重なる時間帯の予約を複数成立させない。
4. 対象会議室、利用開始・終了日時、利用目的、予約者を、登録日時とともに有効な予約として予約台帳へ記録する。
5. 利用者へ登録した予約内容を伝える。

### Exception

- 必須の入力が欠ける場合、会議室が利用できない場合、日時の条件を満たさない場合、または既存予約と重なる場合は、予約を登録せず、受付できない理由を利用者へ伝えて終了する。既存の予約は変更しない。

### Output

- 予約台帳 — 登録された予約内容 / 登録日時
- 利用者 — 予約結果 / 受付できない理由

## Result

利用者が指定した会議室と時間帯の予約が成立し、その予定で会議の準備を進められる。
