# 会議室予約 — 予約と取消の記述例

予約を受け付ける業務と、依頼を受けて予約を取り消す業務を、同じ文書に記述する例。業務内容は利用先で確認・合意する。この例では予約受付担当者を業務主体とし、人やシステムへの割り当て、画面やDBの設計は定めない。

書き方は[業務設計書の文書構造](../business-design-structure.ja.md)、使い方は[README](../../README.ja.md)を参照。

# Scope

利用者からの予約希望の受付、利用可否と重複の確認、予約の登録、予約の取消、結果の通知を対象とする。空き状況の検索、予約の変更、会議室の利用可否の管理、会議の実施は対象外とする。会議室の利用可否は範囲外の業務が管理する。

# Activity 会議室を予約する

## Scope

true

## Why

会議に必要な時間帯の会議室を確保するため。

## When

利用者から予約希望を受け付けたとき。

## Who

予約受付担当者

## Where

規定なし

## How

### Input

- 利用者 — 対象会議室 / 利用開始・終了日時 / 利用目的 / 予約者
- 会議室台帳 — 会議室の利用可否
- 予約台帳 — 既存予約の時間帯と状態

### Procedure

1. 利用者から対象会議室、利用開始・終了日時、利用目的、予約者を受け取る。
2. 会議室台帳で対象の会議室が利用可能であることを確認し、利用開始が受付時点より後、終了が開始より後であることを確認する。
3. 予約台帳で同じ会議室の有効な予約と時間帯が重ならないことを確認する。ある予約の終了と別の予約の開始が同じ日時なら重複とみなさない。同時の申込みでも、同じ会議室・重なる時間帯の予約を複数成立させない。
4. 対象会議室、利用開始・終了日時、利用目的、予約者を、登録日時とともに有効な予約として予約台帳へ記録する。予約ごとに識別できるようにする。
5. 利用者へ登録した予約内容と予約の識別情報を伝える。

### Exception

- 必須の入力が欠ける場合、会議室が利用できない場合、日時の条件を満たさない場合、または既存予約と重なる場合は、予約を登録せず、受付できない理由を利用者へ伝えて終了する。既存の予約は変更しない。

### Output

- 予約台帳 — 登録された予約内容 / 登録日時 / 予約の識別情報
- 利用者 — 予約結果 / 受付できない理由

## Result

利用者が指定した会議室と時間帯の予約が成立し、その予定で会議の準備を進められる。

# Activity 予約を取り消す

## Scope

true

## Why

使わない会議室の時間帯を、他の利用者が予約できるようにするため。

## When

利用者から予約取消の依頼を受け付けたとき。

## Who

予約受付担当者

## Where

規定なし

## How

### Input

- 利用者 — 対象予約 / 取消依頼者
- 予約台帳 — 対象予約の内容と状態

### Procedure

1. 利用者から予約の識別情報と取消依頼者を受け取り、予約台帳の対象予約を特定する。
2. 対象予約が有効であり、取消依頼者がその予約の予約者であることを確認する。
3. 対象予約を取消済みにし、取消日時を予約台帳へ記録する。取消済みの予約は会議室の時間帯を占有しない。
4. 利用者へ対象予約の取消結果を伝える。

### Exception

- 対象予約を特定できない場合、有効な予約でない場合、または取消依頼者が予約者と異なる場合は、予約台帳を変更せず、取消できない理由を利用者へ伝えて終了する。

### Output

- 予約台帳 — 取消済みの状態 / 取消日時
- 利用者 — 取消結果 / 取消できない理由

## Result

対象予約が時間帯を占有しなくなり、他の利用者がその会議室・時間帯の予約を申し込める。
