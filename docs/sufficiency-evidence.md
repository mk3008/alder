# 成立事実・直接証拠の明示 — Issue #58

## 結論

**EXISTING_KNOWLEDGE_SUFFICIENT。** 今回検討した狭い仮説について、現行知識が要求する判断と既存レビューの実際の記述に実質的な重なりがあり、追加観点で改善すべき具体的な欠落を特定できなかった。review knowledgeは変更しない。

これは文書・既存観測に基づく採否判断であり、Control/Treatmentの同等性や候補の効果ゼロを証明した結果ではない。runtime優先を明文化していないという文言上の差はあるが、その差だけでは採用根拠にしない。

対象：[Issue #58](https://github.com/mk3008/alder/issues/58)。確認日：2026-09-14。現行資料の基準はmain `f2cfacb1fd28d3190ad4ec6e2192877ddaa6302e`（#57の索引を含む）。再帰treeにAGENTS.mdはなかった。

## 手法・優先順位・停止点

[Research Decision Index](research-decisions.md)からreview knowledge、Output guarantees、research operationを先に読み、[現行Q/P/S](phase2/review-knowledge-v0.3.md)と[技術評価方針](adoption.md#prioritize-and-bound-technical-evaluation)を照合した。

評価範囲は、既存3業務のFresh回帰報告 #32 / #33 / #36、既知の反例候補 #34 / #35、判断を支える会議室実装・テストの固定版の抜取確認までとした。優先した不確実性は「既存記録に、候補が狙う成立事実・根拠・未確認条件の分離が実際にあるか」と「既知の打切り失敗が現行知識にも残る候補固有の問題か」である。

この方法は知識の重複、既存の行動例、追加検証に値する具体的な欠落の有無を判別できる。検出率や文言の因果効果は判別できない。欠落が特定できた場合だけ、その性質を既存ベンチマークで比較する必要性を再判断する方針とした。

下記の照合後、候補固有の欠落を特定できなかったため停止した。追加benchmark、Fresh実行、Control/Treatment比較、runtime再実行は行っていない。以下のテスト成功数・一時実行は**過去報告の観測**であり、今回の実行結果ではない。追加実験を省いた理由は証拠上の重複であり、実行環境の不足ではない。

## 反例候補を除外せず検討した結果

**#34のOutput保証の閉じ方。** [#34論点C](https://github.com/mk3008/alder/issues/34#issuecomment-5632329045)には実装・DDL・競合テストへの参照と、過去照会を許す事実の認識があった。それでも「予約可能」が提示時点で示す意味を十分に分けなかった。[#35](https://github.com/mk3008/alder/issues/35#issuecomment-5633002343)はこれをQ3の適用不足と判断し、現在のBoundaryへ補正した。#36はその意味差を残している。

したがって「コードを見ていなかったから失敗した」という例ではない。直接証拠の追加だけで是正されるとは言えず、現在は対象の読み方が既に明示されている。#35の原因分類も報告からの仮説であり、因果確定には扱わない。

**#34の結果受領中断が#36で主要論点にならなかったこと。** #34は出力失敗を一時実行して、保存済み予約の照合責務を残した。#36でこの論点が主要結果にないことは既知の揺らぎとして維持する。ただし、当該論点を調べて誤った成立事実で閉じたという証拠はない。「閉じるときの直接証拠」を加えると未選択の代表場面が回復する、という因果経路は確立していない。全例再現を採用条件にはしない。

## 採否の4観点

1. **Business-relevant incremental value：** 既存記録が閉じすぎ、現行Q/P/Sでも未対応で、候補だけが妥当に残せる具体的論点を特定できなかった。
2. **Sufficiency quality：** 成立事実・根拠・責任・限界が既に結び付いた記述がある。説明の長文化や引用・実行回数の増加だけを改善とは数えない。
3. **Overreach / cost：** 追加候補による悪化を実測したわけではないためDO_NOT_ADOPTとはしない。ただし、コードが証明できない外部判断まで実行証明を求めれば境界を壊す。利益未確認のままその運用負担を増やす理由はない。
4. **Existing behavior overlap：** 実装・テストの確認、必要時の一時実行、未確認のBusiness条件を残す行動は既存報告にある。この観測を候補の効果に計上しない。

## 適用限界・再検討条件

- 小さな固定3業務とその既存報告の分析であり、一般的な検出率、判断安定性、追加候補の費用対効果は未測定。
- #32 / #33は#31版、#36は#35補正版。最終知識による3業務の一斉再実行ではない。
- 過去報告の実行記述を証拠として利用しており、今回全ソース・全ログを再監査していない。
- 現行知識で重要論点を明示的に閉じたが、その根拠となる事実が誤り／曖昧で、安価な直接確認なら判断を変えられた、という具体例が出れば再検討する。
- または、判断自体が同じでも成立根拠の追跡不能が実際の再確認・誤判断につながる例が出れば、記述品質の差として再検討する。まず既存3業務で該当性を確認し、比較が必要なら文言・条件を実行前に固定する。
- 今回の結論は新しい普遍ルールでも、今後の直接検証を不要とする判断でもない。
