# 第3段階 — c2の転用と過剰要求の検証

本書は第3段階時点の判断を保存する。人間が初稿を修正・追加して完成させるという[目的の再確認](https://github.com/mk3008/alder/pull/63#issuecomment-5738263778)を受け、最新の評価対象・採否は[第4段階](stage4.md)と[結論](conclusion.md)へ更新した。以下の「優先項目中心の確認には不足」という判断を、初稿作成への採否と同一視しない。

## 実行前に固定した問い

[継続指示](https://github.com/mk3008/alder/pull/63#issuecomment-5738020150)に従い、研究目的を機能・検査項目を洗い出す観点とpromptの評価へ戻す。F1–F4/P1–P4の全解決や全ケースのresolved化は完了条件ではない。未決を適切にHuman Reviewへ残すこと自体を評価する。

c2を変更せず、会議室の承認済みsnapshotと設備保全の穴あり固定snapshotへ各1回適用する。過去会話を渡さないFresh Agentはcandidateと対象入力だけを読み、oracle・前回出力・評価基準のケース別詳細は見ない。途中フィードバック・出力修正なし。購入の追加実行や製品実装はしない。

評価者が確認する点:

- 会議室: M1/M2を再質問せず、未来境界・検索後再検査・本人照合・予約維持と変更/取消を保つ。範囲外のBusiness判断、方式や責務を追加しない。
- 設備保全: 一つの実作業と複数依頼、作業不要後の正直な終了、外部対処から再点検への接続の意味を検出できるか。oracleの文言・件数一致を求めず、完了単位・残存資格・引継ぎ責務を勝手に決めないかを照合する。
- 全項目: 根拠、分類、条件・契機・観測・禁止を読む。通常項目と未決条件の重複、高確度の過大断定も確認する。

追加予算はこの2回で打ち切る。既存の購入c2と下流設計probeも合わせて実用上の採否を判断し、失敗が残れば範囲を限定して保留する。ベンチマーク完成のための人間判断は求めない。

## 観測結果

[実行manifest](../../work/behavior-derivation/stage3/records/manifest.json)に入力・c2・指示・生出力のhashとAgent識別を保存した。モデル/effortは継承設定であり、独立した実行証明はない。評価者が以下32項目の根拠・分類・意味を照合した。出力は補正せず保存する。

### 会議室 — resolved入力での過剰要求

[生出力](../../work/behavior-derivation/stage3/outputs/meeting-room-c2.md)は16項目（明示6・強い導出10・要確認0）、優先3。M1/M2を未承認の質問へ戻さず、定期予約・代理操作・履歴・通知等の追加もなかった。

| 観測 | 項目と判断 |
| --- | --- |
| 未来・区間境界、正常候補 | MR-01/02/05が開始=現在・過去、隣接/重複、0/1/複数候補を区別。正常条件を維持 |
| 検索と予約の保証差 | MR-03が検索後の競合・利用不可・時間経過の再検査を保持。仮押さえを要求しない |
| 結果喪失から継続 | MR-07が利用者自身の保存確認、他の予約と取り違えない対象特定を保持。管理担当者や照合方式を追加しない |
| 変更・取消と残る占有 | MR-08〜12が変更条件、失敗時維持、旧枠解放、取消後の非占有を接続。旧枠の無条件な予約成功保証はしない |
| 利用不可・再開と複数予約 | MR-14〜16が既存予約保持と個別の変更/取消後の占有を保持。全予約者の対応完了を再開条件にしない |

c2の部分成立・不要化という観点は、MR-10の新旧枠、MR-16の一部予約だけ変更した場合に具体化され、未決のBusiness確認を増やさなかった。c1と同数でも同じ項目配分ではない。c2の安全性を全業務へ一般化せず、この1入力での観測とする。

### 設備保全 — 穴あり入力への転用

[生出力](../../work/behavior-derivation/stage3/outputs/facilities-maintenance-c2.md)は16項目（明示4・強い導出8・要確認4）、優先4。購入で見られた意味・完了単位・不要化の観点が一部は別業務でも働いたが、要求された接続をすべて拾ったとは言えない。

| 評価する意味 | 項目と判断 |
| --- | --- |
| 一つの実作業と複数依頼 | F10が別依頼の作業で故障が解消する場面を示し、依頼の存在と作業完了の範囲を区別。自動一括完了を仕様化しない。複数依頼への一作業の帰属全体までは具体化していないため部分的な保持 |
| 作業不要後の正直な終了 | F10が不要化・残作業・completedの意味を未確定へ返す。実施した事実と不要になった事実を同一視せず判断を求めた。ただし実施なしで終了する観測結果や、openの依頼が残る資格までは明確でない |
| 外部対処から再点検への引継ぎ | 未抽出。F11は遅れた完了登録・外部完了の受領範囲であり、安全閉鎖を解消する外部対処の結果を誰が再点検へ渡すかという問いではない。F15は後続点検で利用可能と判断された後から始まるため、この欠落を埋めない |
| 通常項目と明示未決の重複 | F12/13は予定済み依頼・反復を除きF14へ分離。c1のFM-10/11の過大な通常条件は今回抑制。F01も閉鎖中の受付をF03へ分離 |
| 不要な範囲拡張 | F11は明示的に未定義の後日登録・外部完了まで優先確認に含む。通常操作の時刻は入力194行で決まっている。通常業務との境界確認には使えるが、その外部機能を実装する・業務方針を今決めるゲートにはしない |

F07の「作業全体の完了に疑義のない」という条件は、購入c2の「意味に争いがない」と同様、具体的なテスト入力を確定するものではない。F16は解除後のopen依頼を通常の日程設定へつなぐが、故障が別途解消・不要化した場合の対象資格まで確定したと読んではいけない。要確認の抽出があっても、通常項目の全条件を自動的に安全にするわけではない。

F05の通常の日程設定、F08の時刻境界、会議室のMR-05/09/16は、条件・操作・観測結果・禁止から具体的な設計ケースへ接続できる記述である。一方、F10/11/14は未確定の期待値を合否にできない。生出力全体を実装投入可能とは判定しない。

## 研究判断と停止

**c2を人間レビュー付きの研究候補として保持し、Alder標準workflowへの工程追加は保留する。今回の研究評価はここで完了する。** 有用な導出と転用を観測したが、引継ぎの欠落、通常条件の曖昧さ、範囲外事項の優先質問化が残る。優先項目だけを人間が確認する運用を標準にする根拠としては不足する。全件精読を続ければ候補の利用は可能だが、目的としたレビュー集中の効果は未証明である。

保留の理由はF/Pの業務判断不足ではなく、導出・レビュー手順の限界である。F1–F4/P1–P4の回答を求めず、追加Fresh・c3・全ケースresolved化・製品テスト実装は行わない。再検討するなら、外部結果から次の判断への引継ぎを落とさず、明示的範囲外を追加確認ゲートにしない短い補正、または実際の利用でのレビュー負荷と見逃しの証拠が採否を変えるときに限る。

[最終成果物](conclusion.md)に最小観点、prompt、分類・Confidence、境界、既存3ケースの証拠と限界を集約し、[Research Decision Index](../research-decisions.md#behavior-derivation)へ反映する。v0.3・adoption・元Business Design・過去生出力は変更しない。

機械検証は3段階のscriptで入力・候補・指示・出力hash、参照行範囲、分類と確度、過去証拠32ファイルの不変性を確認する。これは意味評価と別である。実利用者の読解容易性、工数削減、統計的再現性、未知業務への一般化、製品テストの成功は主張しない。
