# 機能・検査項目の導出研究 — 結論と利用範囲

**判断: c2を人間レビュー付きの研究候補として保持し、Alder標準workflowへの採用は保留する。研究評価は完了し、業務判断待ちにはしない。** 購入・設備保全の未決検出と会議室の承認保持に有用性が見られた一方、設備保全の引継ぎ欠落と通常条件の曖昧さが残った。指定の追加2回で停止し、全ケースresolved化は求めない。詳細は[第3段階](stage3.md)。

## 最小の観点とprompt

再利用する候補は[c2の全文](candidate-c2.md)。固定書式もこのファイルに含む。既存のQ1–Q3/P1/Sを検査可能な記述へ具体化したもので、新しいレビュー原則は追加しない。[既存知識・テスト設計手法との対応](plan.md)を根拠として、次の3手順を残す。

1. **成立と引継ぎを追う。** 担当・開始条件・入力から、観測できる結果と次の仕事をたどる。記録の存在だけで業務の成立を証明したことにしない。
2. **結果が変わる代表場面を選ぶ。** 許可/禁止・日時境界・状態遷移に加え、一部成立、不要化、中断、記録の遅れが現在の仕事へ具体的に影響するかを見る。記録件数と実作業の完了単位を区別する。これらを全業務の必須チェックリストにはしない。
3. **根拠と未決を分ける。** 意味・時点・対象範囲が一意かを確かめ、合理的な解釈で結果が変わる部分をHuman Reviewへ返す。通常項目が未決条件へ広がっていないかも照合する。

c1では条件・状態の展開だけで落ちた購入の日時意味・部分成立・不要化が、c2の試行では現れた。この観測は補正を候補として残す理由になるが、候補文だけの因果効果や未知業務での再現性の証明ではない。

## 書式・分類・人間へ戻す条件

業務ごとに「ID・機能名」と8欄（対象業務、条件/契機/入力、観測結果、禁止、根拠、分類、確度、レビュー優先度）を置く短いカードを使う。先頭に入力版・完成状況・優先ID、末尾に対象外を記す。項目識別には**入力版＋出力版＋ID**を使う。同じMR-07でも出力間で意味が変わったため、IDだけで旧テストを対応付けない。

| 軸 | 値と意味 | 人間レビューでの扱い |
| --- | --- | --- |
| 出所 | 明示 / 強い導出 / 要確認 | 写し・根拠の組合せ・未決の意味を区別する |
| Confidence | 高 / 要精査 | 根拠から期待結果を導ける確かさ。承認・網羅性・校正済み確率ではない |
| 優先度 | 優先 / 通常 | 要確認、要精査、長い推論を優先。通常を承認済みとは扱わない |

期待結果が複数の業務判断に依存するなら「未確定」とし、選択肢、現在の仕事への影響、判断担当を示す。未記述でも業務結果が変わらない技術表現は戻さない。担当の決定権自体が未決なら、既存ロールへ勝手に付与しない。承認済みの意味は入力の根拠として使い、再質問しない。

未決項目を合否テストへ変換せず、関連する通常項目も未決条件を除いた範囲へ限定する。「曖昧でない場合」のような条件だけではテスト入力は定まらない。実装対象となったときに必要な判断を正本のBusiness Designへ反映する。全未決の解決を、この研究や無関係な確定項目の進行条件にはしない。

## 過剰要求と取りこぼしの境界

明示された範囲外、現在の仕事に影響しない例外、UI/API/DB方式、数値上限、全操作の一律無変更保証は追加しない。外部の仕事の実装を要求することと、現在のOutputを成立させる外部結果・判断の引継ぎを確認することを分ける。全組合せやoracle全件の再発見を目的にしない。

一方、出所行・高確度・要確認0件は完全性の根拠にならない。優先項目を先に読み、通常からも明示と導出の代表を原文へ戻し、通常条件と未決条件の重複を確認する。実利用者の読解試験やレビュー時間の計測はないため、人間の全件確認を省ける、負荷が下がったとは結論しない。

## 後続テスト設計への接続

後続AIへBusiness Designとその版に対応する一覧を渡し、確定項目について前提・操作・観測・禁止をテストIDへ対応付ける。意味の選択が必要になったら当該期待値を保留する。テスト成功を業務判断の代わりにしない。

[既存の小規模probe](../../work/behavior-derivation/outputs/downstream-probe.md)はc1の6項目から、限定条件の4項目を計37設計ケースへ展開し、2項目の未決を保留した。正本を併読することで過大な通常条件を絞れた例であり、一覧だけの十分性を示さない。実行可能なテストコード・製品テスト実行・全一覧の品質は未検証。c2の下流Fresh再実行は行わず、今回の新出力では評価者が条件・契機・結果・禁止の具体性を確認する。

**標準workflowへの新工程追加、優先項目中心の確認だけでの承認は保留する。** これは未決業務の完成待ちではなく、引継ぎの取りこぼしと条件限定の弱さが残ったという研究判断である。c2は任意の研究・試行用候補として残す。v0.3や標準adoption文書は変更しない。固定書式は比較しやすさを提供するが、最適な書式や人間の負担軽減を検証したわけではない。
