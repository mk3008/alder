## 主表示

### Activity 1 — 会議室の空き状況を確認する

| ID | 検査項目 | 期待結果 |
| --- | --- | --- |
| A1-01 | 条件に合う会議室が0件 | 候補一覧は0件になる |
| A1-02 | 条件に合う会議室が1件 | その1件だけを候補として取得できる |
| A1-03 | 条件に合う会議室が複数件 | 条件に合う会議室をすべて候補として取得できる |
| A1-04 | 会議室が unavailable | 候補一覧に含まれない |
| A1-05 | 指定時間帯と重なる reserved 予約がある | その会議室は候補一覧に含まれない |
| A1-06 | 既存予約の終了日時と検索開始日時が同一 | その予約は重複とみなさず、他条件を満たせば候補になれる |
| A1-07 | 重なる予約が cancelled | cancelled は占有せず、他条件を満たせば候補になれる |
| A1-08 | 利用開始日時が確認時点と同じ、または過去 | 予約候補に含めない |
| A1-09 | 空き確認だけを行う | 予約や仮押さえは成立しない |
| A1-10 | 候補から会議室を選ぶ | 選んだ会議室を一意に特定して予約入力に使える |
| A1-11 | 候補が0件 | 予約対象を得た扱いにしない |
| A1-12 | 空き確認後に予約へ進む | 予約時点で状態・時間・競合条件を再検査し、検索結果だけで予約成功を保証しない |

## 旧 MR-01 との比較

旧 MR-01 は、0/1/複数件、unavailable、reserved、検索時の副作用禁止、予約への接続、0件後の扱いを1枚のカードにまとめていた。

更新後はそれぞれを独立して採用・修正・削除できる。根拠・分類・Confidence・接続は補足へ退避し、主表示では「何を与えたら何を観測するか」を一読できる。

項目数の増加自体を改善とは扱わない。今回の改善判定は、旧MR-01の複数の独立判断が別Checkへ分かれ、各行を個別にレビューできることに置く。
