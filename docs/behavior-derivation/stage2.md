# 第2段階 — 会議室の承認反映後の導出

この文書は第2段階時点の計画と観測を保存する。末尾の全ケースresolved化・追加業務判断という完了条件は[継続指示](https://github.com/mk3008/alder/pull/63#issuecomment-5738020150)により撤回。現在の研究判断は[第3段階](stage3.md)を参照。

## 実行前の範囲と判断

[PR #63の人間判断](https://github.com/mk3008/alder/pull/63#issuecomment-5737722908)でM1はB（検索時点でも未来条件を満たす候補）、M2は利用者自身による保存確認・対象特定・継続と確定した。追加の承認は求めない。[判断全文](../../work/behavior-derivation/stage2/records/human-decision.json)と[独立snapshot](../../work/behavior-derivation/stage2/inputs/meeting-room.md)を保存し、元入力・第1段階出力を変更しない。

今回の高情報価値の問いは、**同じ候補c1に承認反映済み入力を与えた場合、解消済み論点を再度質問せず、未来境界と結果喪失後の継続を検査可能に導けるか**。c1を変更しない。入力変更とAgentの変動を分離する因果比較ではなく、承認済み契約を導出できるかの1回の観測である。未決の設備保全・購入をresolved扱いしない。

### 実行前の業務相関レビュー（評価者）

| 接続 | 再確認した内容 | 判定 |
| --- | --- | --- |
| 空き確認→予約 | 検索時点の開始>現在という条件を追加。検索後の時間経過・競合・利用不可化は予約時に再検査する | M1の保証範囲が一致。仮押さえ・将来成功保証は不要 |
| 予約保存→結果受領中断→後続操作 | 利用者が保存済みか確認し、保存済みなら同じ対象を特定する。変更・取消は既存の各条件に従う | M2の責務と観測可能な結果が接続。再試行成功だけを証明にしない |
| 利用不可→別室変更/取消→再開 | 既存の#26承認をそのまま保持する | 再承認・管理担当者への照合責任追加なし |
| 設計対象と範囲外 | 定期予約・代理操作・通知等は従来どおり範囲外 | 全例外の仕様化は行わない |

Q1の継続、Q2の占有・利用不可の独立性、Q3のOutput保証、Sの責務境界を文書で再確認した。P2は実装前のため実施していない。M1/M2について評価対象の意味を妨げる未決は確認しなかった。過去入力へのエラー形式と空一覧の選択、照合方式は今回承認された業務結果を変えない限り実装側に残す。実利用者の観察・本番運用承認ではない。

### 事前に固定する観測と予算

Fresh Agentはc1と当該snapshotだけを読む。過去出力・本評価文書・oracleは見せない。1回、途中フィードバックなし。

1. 開始=検索時点・過去を予約候補に含めず、未来で他条件が合う場合と区別できる。
2. 検索後の再検査を維持し、枠保持・予約成功保証を増やさない。
3. 保存確認・成立済み対象特定・後続変更/取消への接続を検査対象とする。
4. M1/M2を未承認として再質問せず、方式・管理担当者の責任を追加しない。
5. 既存の予約維持・重複・変更失敗時保持等を根拠付きで残す。

全項目の根拠と意味を評価者が照合する。出力件数・自己申告確度だけで合格にしない。製品実装や既存20テストの再実行は、研究入力だけの変更を検証しないため行わない。実行可能なテスト実装はこの段階では対象外。判断を変え得る失敗がなければ追加反復せず、他2業務の必要な人間判断へ戻る。

### 既知の失敗に対する局所試験

会議室の実行と独立して、第1段階で購入の日時意味・部分成立・不要化の確認が落ちた失敗を対象に、[c2](candidate-c2.md)を購入の穴あり入力へ1回だけ適用する。Q1/Q3/P1の適用を具体化する短い補正と、通常項目と要確認条件の重なりの照合を加える。c1は保存し、特定の購買方針やoracleはAgentへ渡さない。

これはresolved評価の代用ではない。承認効力に加え、日時の意味・完了単位・不要化後の継続責務が未決として残るか、不要な承認段階などを優先質問に増やさないかを観測する。過去oracleを知った評価者による補正なので未知ケースでの一般化は未証明。2候補×3ケースの総当たりは行わず、第2段階の予算はこの局所試験と会議室の計2 Agent実行で打ち切る。

c1もc2も項目数は13だが、優先対象は2→4へ増えた。今回は未決の可視化が改善した観測であり、レビュー工数が減ったという結果ではない。高確度の通常項目の網羅性も保証しない。1回ずつで実行者が異なるため、補正文だけの因果効果や再現率は未証明。設備保全のFM-10条件重複がc2で直ることも今回未検証である。

## 判断・残作業・検証

**研究候補としてc2を保持し、標準workflowへの採用は引き続き保留する。** 会議室のc1は、承認済み設計の2論点を検査項目へ接続できた。購入c2は、穴あり入力の既知の意味確認を再発見した。異なる入力状態・異なる問いの結果であり、「3ケースがresolvedで成功」「c2が全ケースに有効」とまとめない。

追加実行は会議室1回＋購入1回、合計2回で終了。今回の観測を変えない大量反復や下流テスト設計の再実行はしない。入力・候補・指示・出力hashと参照行範囲、c1研究証拠の不変性は `python3 work/behavior-derivation/stage2/verify.py` で確認する。既存の `python3 work/behavior-derivation/verify.py` と差分検査も継続する。機械検査は意味の妥当性を証明せず、上記の手動照合と区別する。

残る完了条件は設備保全・購入の人間判断、両業務のresolved評価、3ケース全体の採否判断。次は[decision packetのP1〜P4](decision-packet.md)を先に確定するのが情報価値が高い。今回の承認は会議室M1/M2のみであるため、それ以外の業務方針はAIが選ばない。P1はまず購入日時の意味を確定する。購買-05が広げた購入成立事実の詳細は、既存の購買担当者の判断・申告境界では不足する具体的理由が出ない限り、追加の承認ゲートにしない。P3/P4は一部購入や不要化後の残りの仕事を含めて回答する。F1〜F4は引き続き保留。
